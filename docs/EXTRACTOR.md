# Контракт извлекателя

Извлекатель — отдельный процесс под один язык: `semaps-extract-<lang>`. Он читает
исходники и **печатает факты о коде в stdout одним JSON-документом**. Больше он не
делает ничего: не знает о реестре (`entities.json`, `relations.json`), о
контейнерах, видах, текстах и правилах. Всё это — сверка в `core/`, общая для всех
языков.

Нормативная форма реестра, с которым сверяются факты: [`CONTRACT.md`](CONTRACT.md).
Почему так: [`ADR_20260828`](adr/ADR_20260828_diagrams_model-contract-v2.md),
[`ADR_20260831`](adr/ADR_20260831_diagrams_text-provenance-and-view-axes.md).

---

## 1. Запуск

```
semaps-extract-<lang> [--root <dir>] [--include <path>]... [--exclude <glob>]...
```

- `--root` — корень исходников, относительно него пишутся все `file`
  (по умолчанию текущий каталог). Это тот же корень, что `--source-root` у хоста:
  `file` факта и `codeRef` сущности должны совпадать посимвольно.
- `--include` — пути под корнем, которые читать (у проекта — `project.json` →
  `sources.include`). Нет ни одного — читать весь корень.
- `--exclude` — что пропустить поверх умолчаний языка.

Выход:

| Код | Значение |
|---|---|
| `0` | факты напечатаны, stdout — валидный JSON по §2 |
| `1` | извлечь не удалось; stdout пуст или не читается, причина — в stderr |
| `2` | неверные аргументы |

stdout — **только** JSON. Диагностика, прогресс, предупреждения — в stderr.
Частичный результат при ошибке не печатается: сверка по неполным фактам пометит
половину реестра пропавшей.

## 2. Схема фактов

```json
{
  "language": "csharp",
  "root": ".",
  "symbols": [
    {
      "id": "Acme.Agent.Guards.RepetitionGuard",
      "kind": "type",
      "nativeKind": "class",
      "name": "RepetitionGuard",
      "namespace": "Acme.Agent.Guards",
      "file": "src/Acme.Agent/Guards/RepetitionGuard.cs",
      "line": 12,
      "members": []
    }
  ],
  "edges": [
    { "from": "Acme.Agent.Guards.RepetitionGuard", "to": "Acme.Llm.ILlmMiddleware", "kind": "implements" }
  ]
}
```

### 2.1 `symbols[]`

| Поле | Обяз. | Что |
|---|---|---|
| `id` | да | устойчивый ключ символа **внутри этого вывода**: полное имя на языке кода. Уникален в выводе. Это не id реестра — id реестра (`e_…`) выдаёт сверка, один раз и навсегда |
| `kind` | да | общий словарь, ровно одно из `type`, `interface`, `function`, `module`, `value` (§2.3) |
| `nativeKind` | да | как это называет сам язык: `class`, `struct`, `record`, `enum`, `trait`, `protocol`, `package`… Свободная строка |
| `name` | да | короткое имя, как в коде |
| `namespace` | нет | пространство имён / пакет / модуль-владелец; пусто, если у языка его нет |
| `file` | да | путь относительно `root`, прямые слэши |
| `line` | нет | строка объявления, с 1 |
| `visibility` | нет | видимость символа словами языка: `public`, `internal`, `protected`, `private`, `exported`, `file`… Свободная строка; отсутствует — считать публичным |
| `members` | нет | члены в форме `members` из [`CONTRACT.md`](CONTRACT.md) (`entities.json`) |

### 2.2 `edges[]`

| Поле | Что |
|---|---|
| `from`, `to` | `id` символов из этого же вывода. Ребро на символ вне вывода (библиотека, не попавший в `--include` код) **не печатается** |
| `kind` | ровно одно из `extends`, `implements`, `references`, `contains` |

- `extends` — наследование реализации (базовый класс, встраивание по смыслу наследования).
- `implements` — реализация интерфейса / трейта / протокола.
- `references` — символ упоминает другой символ в типе поля или свойства, в
  сигнатуре члена, в собственной сигнатуре, если он сам `function` или `value`,
  в правой части псевдонима типа. Аргументы generic-типов, элементы массивов и
  `Nullable` разворачиваются до символа. Все упоминания `A → B` схлопываются в
  **одно** ребро; `A → A` не печатается. Между модулями — зависимость единиц
  сборки, если язык её объявляет (C#: `ProjectReference` сборка → сборка).
- `contains` — вложенность: модуль содержит тип, тип содержит вложенный тип. Тип
  может лежать в нескольких модулях разом (C#: пространство имён и сборка; файл,
  подключённый в два проекта, — в обеих сборках).

Вызовы (`call`), потоки данных и события — **не** факты извлекателя. Это
авторские типы связей из `relation-types.json`; их заводит человек.

### 2.3 `kind` и `nativeKind`

Единица архитектуры у языков разная, и извлекатель её не выравнивает: в C# это
тип, а `static class` — способ сгруппировать функции; в TypeScript это модуль
(файл), а свободные функции — его содержимое. Оба печатаются как есть: файл —
`module` с `nativeKind: file` и рёбрами `contains`, функции — `function`. Какой
слой класть на вид, решает ось вида; новый язык описывает своё соответствие в
ADR, не в извлекателе.

Символ `module` для файла: `name` — имя файла без расширения, `namespace` —
пусто.

C# печатает два слоя `module`
([`ADR_20260923-10`](adr/ADR_20260923-10_extractors_csharp-assembly-symbol.md)):

| Символ | `id` | `nativeKind` | `name` | `file` | `contains` → | `references` → |
|---|---|---|---|---|---|---|
| проект (`.csproj`) | `[AssemblyName]` | `assembly` | `AssemblyName` | путь `.csproj` | каждый тип верхнего уровня из его исходников | сборки по `ProjectReference` |
| пространство имён | `A.B` (ADR-5) | `namespace` | последний сегмент | первое объявление | каждый тип верхнего уровня в нём | — |

Вложенный тип — под внешним типом, не под сборкой и не под пространством.
`namespace` у обоих — пусто, `visibility` нет.


`kind` — минимальный общий словарь, одинаковый для всех языков; на нём работает
сверка и фильтры. Всё языковое — только в `nativeKind`. Новое значение `kind`
вводится новым ADR, не в извлекателе.

| `kind` | Что сюда | Примеры `nativeKind` |
|---|---|---|
| `type` | тип с данными и/или поведением | `class`, `struct`, `record`, `enum`, `union` |
| `interface` | контракт без реализации | `interface`, `trait`, `protocol` |
| `function` | свободная функция верхнего уровня | `function`, `delegate` |
| `module` | единица группировки кода | `namespace`, `assembly`, `package`, `module`, `file` |
| `value` | именованное значение верхнего уровня | `const`, `static`, `global` |

## 3. Что извлекатель обязан

- **Разрешённые символы, а не текст.** Нужны настоящие имена баз и типов
  членов, а не то, что похоже на них регулярке. Для C# это `MSBuildWorkspace`, а
  не `CSharpSyntaxTree.ParseText` по файлам.
- **`partial` и подобное собирается в один символ.** Один тип — одна запись,
  `file` — файл первого объявления.
- **Детерминизм.** Один и тот же код — байт в байт один и тот же вывод:
  `symbols` отсортированы по `id`, `edges` — по `(from, to, kind)`. Иначе диф
  реестра шумит движением, которого никто не делал.
- **Значения `enum`** — в `members`. Это главный запрос к схемам: «enum есть,
  содержимого нет».
- **Публичные члены интерфейсов** — имя и сигнатура.
- **Свойства и поля** — имя и тип; если тип — символ из этого же вывода, это ещё
  и ребро `references`.

- **Все объявления, включая приватные и не экспортированные**, с `visibility`.
  Что показывать, решает вид, а не извлекатель: обзорной схеме нужны публичные
  типы, тактической — приватный вложенный класс со своими членами.

Пропускать как не-архитектуру: сгенерированный код, выходы сборки. Для C#: `bin/`, `obj/`, `*.g.cs`, `*.Designer.cs`, `AssemblyInfo`,
`GlobalUsings`.

## 4. Чего извлекатель не делает никогда

- **Не пишет файлы.** Ни реестр, ни тексты, ни виды. Он печатает и выходит.
- **Не выдаёт id реестра** и не пытается угадать переименование. «Пропал X,
  появился Y в том же файле» решает сверка — и то только как кандидат для
  человека.
- **Не знает о контейнерах и видах.** Принадлежность вычисляет сверка по
  `containers.json`; на геометрию она не влияет вообще.
- **Не ставит `origin`.** Всё, что он печатает, по определению `code`; решать,
  какие записи реестра `authored` и неприкосновенны, — дело сверки.

## 5. Что делает сверка (`core/`), а не извлекатель

Для полноты границы — правила, которые исполняет
`core/` поверх фактов любого языка:

Почему так: [`ADR_20260923-9`](adr/ADR_20260923-9_core_sync-symbol-mapping-and-containment.md).

```
semaps sync --facts <file.json | -> [--project <id>] [--dry-run] [--no-renames] [dir | file.semaps]
```

Корни — как у `semaps check`. Сверяется один проект: `--project`, а если проект в
workspace один — он. В сверку попадают символы, чей `file` лежит под
`project.json → sources.include` (нет `include` — все).

**Ключ.** Сущность помнит свой символ в поле `symbol` ([`CONTRACT.md`](CONTRACT.md) §3);
на каждом прогоне сопоставление идёт по нему. Сверке подлежит запись с
`origin: code` или с `symbol`; `authored` — никогда.

| Событие | Реакция сверки |
|---|---|
| символ есть в фактах, нет в реестре | новая запись: id `e_` + slug (нижний регистр, всякая серия не-букв и не-цифр → один `_`) короткого имени, а у `module` — `nativeKind` и всего `id` символа (`e_namespace_acme_agent_guards`, `e_assembly_acme_agent`); коллизия — `_2`, `_3`; выдаётся **один раз**. `kind` = `nativeKind`, `origin: code`, `status: present`, `namespace`, `codeRef` = `file`, `symbol` = `id`, `members` |
| есть и там, и там | обновить `namespace`, `codeRef`, `members` (если факты их дают); `missing` → `present`; `id`, `name`, `kind` не трогать |
| запись без `symbol`, не `authored`, первый прогон | усыновление (ниже): запись получает `symbol` и `origin: code`, id остаётся |
| есть в реестре, нет в фактах | `"status": "missing"`, не удалять |
| пропал X и появился Y в том же файле того же `kind` | кандидат на переименование в отчёт, не решение: X не помечается `missing`, Y не заводится, пока человек не поставит X `symbol` = Y или не повторит с `--no-renames` |

**Усыновление** записи, заведённой без сверки: правило 1 — тот же файл (`codeRef` без
`#…`/`:…`) и то же имя, при нескольких символах в файле — тот, чей `nativeKind`
равен `kind`, затем того же семейства; правило 2 — то же `namespace`, имя и семейство
вида. Имя сравнивается без хвостового `<…>` и без арности `` `N ``
(`IRunner<in TIn, out TOut>` ~ `IRunner`); семейство вида — последний сегмент через `-`
без учёта регистра (`abstract-class`, `static-class` ~ `class`; `record-struct` ~ `struct`),
поэтому модификаторы извлекатель пишет в `nativeKind` как `<модификатор>-<вид>`.
Совпадение обязано быть однозначным в обе стороны; иначе запись и символы
не трогаются, в отчёте — `неоднозначно`, `symbol` ставит человек. `kind` и `name`
усыновлённой записи остаются как были: `class` у абстрактного класса сверка не
переписывает ни сейчас, ни потом.

Символ `module` (`assembly`, `namespace`, `file`) — такая же сущность, как тип.

Связь реестра: `r_<from без префикса>_<to без префикса>_<type>`, коллизия — `_2`;
`origin: code`, `status: present`, `evidence: [{ codeRef: <file from>, symbol: <id from> }]`.
Рёбра всех видов — `extends`, `implements`, `contains`, `references` — пишутся связями того же типа; тип
заводится в `relation-types.json` (`origin: code`), если его нет; чужие записи
словаря не трогаются. Связь с тем же `(from, to, type)` уже есть — новая не
заводится: авторская остаётся как есть, прочая получает `origin: code`. Связь
`origin: code`, которой нет в рёбрах, — `status: missing`, если
обе её сущности сверка видит. Паутину `references` убирает видимость на виде
([`CONTRACT.md`](CONTRACT.md) §8.5), а не реестр
([`ADR_20260924-2`](adr/ADR_20260924-2_core_sync-writes-references.md)).

Три вещи принадлежат человеку целиком: `text.<lang>.json`, `views/*.view.json`,
авторские записи `relation-types.json`. Запись в них из сверки — дефект.
Ключи записей, которых сверка не знает, сохраняются вместе с их порядком.

Отчёт: `сломано` (реестр противоречит себе: повтор id, два `symbol` на один символ —
тогда не пишется ничего), `неоднозначно`, `переименование?`, `лишнее` (помечено
`missing`), `не хватает` (новые записи, связи, типы), `изменилось` (обновлённые поля,
усыновление, возврат из `missing`).

| Код | Когда |
|---|---|
| `0` | реестр совпадает с кодом, или изменения записаны и решать человеку нечего |
| `1` | `сломано`, `неоднозначно` или `переименование?`; при `--dry-run` — любой непустой отчёт; факты не читаются или не проходят проверку §2 |
| `2` | неверные аргументы: нет `--facts`, проектов несколько без `--project` |

Проверка фактов перед сверкой: обязательные поля, словари `kind`, уникальные `id`,
рёбра только между символами вывода, без петель и повторов, сортировка §3.
Незнакомые поля фактов пропускаются.

## 6. Незакрытое

1. **Объём `references`.** Не замерен на живом коде. Если счёт пойдёт на тысячи —
   остановиться и обсудить порог.
2. **Гранулярность `members`.** `enum` — точно, члены интерфейсов — вероятно,
   свойства всех классов — под вопросом: если `entities.json` переваливает за
   пару мегабайт, это сигнал остановиться.
