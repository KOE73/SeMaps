# IDE bridge v1

Мост `semaps.ide`, версия `1`, связывает редактор с адаптером IDE. Формат workspace
и HTTP/SSE API host остаются прежними. Адаптер IDE принимает нативное перетаскивание,
разрешает символы, показывает диалоги и работает с файлами проекта. Редактор получает
нормализованные символы, идентификаторы сущностей и координаты.

## Подключение и транспорт

Общая оболочка описана в `plugins/protocol/schemas/message.schema.json`.
Запрос: `protocol`, `version`, `sessionId`, `kind: request`, `id`, `method`, `params`.
Ответ: `kind: response`, `requestId`, ровно один объект `result` или `error`.
Событие: `kind: event`, `id`, `method`, `params`; необязательные `origin`, `causationId`.
Неизвестные поля оболочки, неверные типы и версии отбрасываются.

`bridge.initialize` принимает `{capabilities: string[]}` и возвращает возможности
редактора и текущий `context`. До успешного handshake команды не выполняются.
Новая сессия отменяет ожидающие операции; ответы старой сессии игнорируются.
Возможности объявляются по именам методов; клиент проверяет их перед вызовом.

WebView2 использует JSON messages. В обычном браузере мост автоматически не подключается.
Для iframe экспортирован `frameTransport(peer, origin, receiver)` с проверкой точного
origin и отправителя; `*` запрещён. Приложение с этим транспортом явно вызывает
`attachEditorBridge`. Реального плагина VS Code пока нет.

Получатели запоминают до 200 завершённых запросов в пределах сессии. Повтор того же
id и параметров возвращает ответ; изменение параметров при том же id даёт `duplicateId`.
Это ограниченная защита от повтора, а не долговечный журнал. После таймаута/разрыва
клиент перечитывает состояние перед новой попыткой. Размещение также пропускает уже
существующие блоки. `bridge.cancel {requestId}` отменяет выполняющийся запрос редактора
до изменения модели. VS ждёт ответ обычно 5 секунд и при отмене посылает cancel;
редактор ждёт `source.open` 3 секунды. Уже выполненную операцию cancel не откатывает.

## Контекст и команды

`context = {contextId, projectId, viewId, mode}`. Отсутствующие проект/вид — `null`.
`contextId` меняется при смене документа модели, проекта, вида или режима.
Все команды кроме `context.get` требуют точную копию текущего context и открытый
режим `diagram`. После асинхронного поиска и перед записью контекст проверяется повторно.
Устаревший контекст возвращает `staleContext`; другую карту запрос не изменяет.

| Метод | params | result |
|---|---|---|
| `context.get` | `{}` | `{context, selection: entityId[]}` |
| `symbols.resolve` | `{context, symbols: [{language, symbolId, ...}]}` | `{context, results: [{symbol, graphNodeIds, candidates: [{entityId,onView}], status}]}` |
| `selection.set` | `{context, entityIds, primaryId?}` | `{context, selected}` |
| `entities.reveal` | `{context, entityIds}` | `{context, results: [{entityId,status}]}` |
| `entities.place` | `{context, entityIds, at?}` | `{context, results: [{entityId,status}]}` |

Массивы символов/идентификаторов ограничены 500 элементами. Идентификаторы сравниваются
точно. `symbols.resolve` ищет язык/id в текущем графе host и в привязках объединённого
реестра редактора. `file` и `assembly` — сопровождающие данные; они пока не фильтруют
результат. Несколько сущностей дают `ambiguous`, первый кандидат не выбирается.
Статусы: `resolved`, `alreadyOnView`, `ambiguous`, `notFound`, `notInModel`.
Отсутствие символа не доказывает устаревание графа; извлечение и сверка выполняются отдельно.

Выделение требует существующих размещений (`notOnView` при отсутствии).
`primaryId`, если указан, входит в выбранный массив. Reveal возвращает `revealed`
или `notOnView`. Place принимает только существующие сущности реестра; возвращает
`placed`/`alreadyOnView` и использует штатное размещение, один Undo и рабочую модель host.
Произвольные JSON сущностей, текст исходника и drag payload не принимаются.
Ошибки ответа имеют `{code,message}`: `invalidParams`, `unsupported`, `staleContext`,
`notInModel`, `notOnView`, `cancelled`, `duplicateId`, `failed`.

`at = {space: model|client, x, y}` с конечными числами. Client — CSS-пиксели относительно
всей страницы WebView, не экрана; редактор проверяет границы холста и преобразует точку
через viewport. Без at используется центр вида. VS передаёт WPF DIP при WebView zoom=1;
масштаб холста учитывается редактором. Разные DPI мониторов отдельно не проверены.

## События и исходники

`context.changed {context}` сообщает смену документа/вида/режима.
`selection.changed {context, objects: [{entityId, sources}], primaryId}` сообщает выбор
в диаграмме. Источник: `{language, symbolId, file?, line?}` из code binding.
Вызванное командой выделение получает `origin: ide` и `causationId: requestId`;
пользовательское — `origin: editor`. IDE игнорирует обратные события своего выделения.
Освобождение адаптера посылает `bridge.disconnected {}` и отменяет ожидания.

Редактор вызывает `source.open {context, file, line?, column?, label?}` только при
объявленной возможности IDE. Ответ `{opened: boolean}`. Отказ/ошибка/таймаут сохраняют
штатный браузерный просмотр исходника. Выбор блока сам по себе файл не открывает.
При единственной файловой привязке плагин выделяет её в Solution Explorer; слежение
выключается в меню «⋯». Несколько файлов автоматически не выбираются.

Пути source.open относительны `source_root`, разделитель `/`; строки и колонки
1-based, колонка в UTF-16 code units. Текущий редактор извлекает начальную строку
из `ref` (`#L7`/`#L7-L12`), диапазон не передаёт. Символы используют id экстрактора;
позиция лишь открывает файл. VS проверяет абсолютные пути, выход через `..`, ADS и
похожие префиксы соседних каталогов. Проверка границ лексическая; переходы через
junction/symlink не разрешаются физически.

## Visual Studio

Открытие solution не открывает карту и не запускает сервер. Только ручная команда
`View.SeMaps` или Reconnect ищет ближайший `*.semaps`, проверяет workspace/source_root,
переиспользует подходящий host либо запускает `semaps.exe --here --no-browser`.
Закрытие solution/VS оставляет общий host работающим.

Плагин занимает одну строку высотой 26 DIP: «↻» — Reconnect, «◎» — выбор типа,
«⋯» — слежение и сведения о подключении, индикатор связи. Адрес/диагностика доступны
во всплывающей подсказке и диалоге сведений. Сообщения операций идут в штатную строку
состояния Visual Studio; отдельной нижней полосы/drop-зоны нет.

Плагин принимает FileDrop с C# файлами загруженной Roslyn solution, разрешает объявления
типов с проектными references, объединяет partial и показывает выбор типов даже для
одного кандидата. Несохранённый буфер помечается в диалоге. После подтверждения он
разрешает символы и размещает существующие сущности; неоднозначные/отсутствующие
результаты сообщает без скрытого извлечения или сверки. Точка и context фиксируются
до диалога. Смена карты/сессии отменяет старое назначение.

Кнопка выбора типа из редактора разрешает ближайшее содержащее объявление типа по
курсору последнего активного текстового редактора; выделяет/reveal только существующий
блок. Члены, внешние metadata symbols и постоянное слежение за курсором пока не входят
в адаптер VS. Нативные форматы без FileDrop не разбираются.
