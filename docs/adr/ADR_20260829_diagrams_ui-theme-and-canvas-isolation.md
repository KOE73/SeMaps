# ADR_20260829_diagrams — Изоляция тем интерфейса (Workbench Chrome) от стилей холста диаграммы (Diagram Canvas)

Статус: **принято**

> В контексте **внедрения тем оформления (Cream, Dark, Emerald, Light) и локализации в Workbench редактора**,
> столкнувшись с тем, что **глобальные CSS-переменные темы UI (`var(--panel-alt)`, `var(--line)`, `var(--muted)`)
> начали проникать внутрь SVG-элементов холста диаграммы (в частности, бейджи количества связей стали чёрными на белых фигурах),
> а тёмный фон холста угрожает контрастности тёмных стрелок связей, созданных для светлых схем**,
> мы решили:
> 1. **Строго изолировать домен оформления UI Chrome от домена отображения диаграммы Canvas**.
> 2. **Запретить элементам SVG диаграммы (нодам, коннекторам, бейджам, текстам) использовать переменные темы UI (`--panel`, `--panel-alt`, `--line`)**. Они управляются исключительно `canvas.css` и `StyleLibrary` схемы.
> 3. **Фон холста диаграммы управляется через изолированную переменную `--semaps-canvas-bg`**, а для тёмных схем в дальнейшем предусматривается отдельная настройка подложки/палитры схемы, исключающая растворение тёмных линий связей.
> 4. **Превью тем в Ribbon (Theme Gallery) изолирует `data-theme` строго внутри окна предпросмотра `.ribbon-theme-preview`**, гарантируя читаемость подписей тем на любом фоне ленты.

---

## 1. Проблема и контекст

1. **Размытие границ доменов**:
   `DiagramCanvas` спроектирован как встраиваемая независимая библиотека. При добавлении тем приложения (Workbench) в `editor.css` возник соблазн использовать переменные темы (`var(--panel-alt)`, `var(--line)`) внутри рендереров SVG (`BoxRenderer.ts`).
2. **Следствие**:
   При переключении темы UI в `Dark` бейджи связей `7/5` на белых блоках унаследовали тёмно-серый фон `--panel-alt`, превратившись в нечитаемые тёмные пятна на светлых карточках.
3. **Контрастность связей на тёмном фоне**:
   Архитектурные диаграммы создавались с ориентацией на светлый фон: цвета связей содержат тёмно-зелёные, тёмно-синие и графитовые оттенки. Прямое окрашивание фона холста в глубокий чёрный цвет (`#1e1e1e`) делает такие линии плохо различимыми. Менять цвета связей схемы ради темы приложения недопустимо, так как стили связей принадлежат модели данных схемы.

---

## 2. Принятые решения

### 2.1. Полная автономия элементов SVG холста
* Ни один SVG-элемент внутри `.semaps-canvas` не имеет права читать CSS-переменные хром-интерфейса (`--panel`, `--panel-alt`, `--line`, `--text`, `--muted`, `--hover`).
* Бейджи связей (`semaps-node-badge`) стилизуются автономно в `canvas.css` с нейтральной палитрой (светло-серый чип `#f1f5f9` с рамкой `#cbd5e1` и текстом `#475569`), переходя в акцентный синий `#2563eb` при наведении или активации показа связей.

### 2.2. Управление фоном холста
* Фон холста и координатная сетка управляются через изолированную переменную `--semaps-canvas-bg`.
* В `Workbench` подложка холста может подстраиваться под общую тему рабочей области через `--semaps-canvas-bg: var(--bg)`, однако в перспективе в модель схемы может быть добавлен собственный параметр подложки / палитры схемы, чтобы для тёмного режима выбирать выверенный мягкий серый тон, на котором сохраняется читаемость тёмных стрелок связей.

### 2.3. Инкапсуляция Ribbon Theme Gallery
* При отображении миниатюр в ленте Ribbon атрибут `data-theme="..."` устанавливается только на контейнер `.ribbon-theme-preview`.
* Внешняя карточка `.ribbon-theme-card` и текстовая метка `.ribbon-theme-label` наследуют цвета активной ленты Ribbon, что исключает появление белого текста на светлом фоне или тёмного на тёмном.

---

## 3. Последствия
* **Сохранность моделей**: визуальные стили схем и их рендеринг остаются 100% детерминированными и не ломаются при смене тем оболочки.
* **Портативность**: `DiagramCanvas` может быть встроен в любой внешний хост без риска визуальной деградации SVG-элементов.
