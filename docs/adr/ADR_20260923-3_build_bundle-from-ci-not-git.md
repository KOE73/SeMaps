# ADR_20260923-3_build — Бандл редактора собирает CI, в git он не лежит

Статус: **принято**. Уточняет [`ADR_20260923-2_host_one-binary-and-project-file`](ADR_20260923-2_host_one-binary-and-project-file.md): бандл по-прежнему вшивается в бинарник, меняется только то, откуда он берётся.

> В контексте **одного бинарника с вшитым редактором**, столкнувшись с тем, что
> **собранный `host/app/` (около мегабайта хешированных файлов) лежал в git и менялся
> целиком при каждой сборке** — история host тонет в бандлах, diff и blame бесполезны,
> репозиторий растёт на мегабайт за пересборку,
> мы решили:
> 1. **`host/app/` в `.gitignore`.** В репозитории только исходники редактора.
> 2. **Собирает CI.** На каждый push — проверка, что редактор собирается, хост
>    собирается и пример проходит `semaps check`. На тег `v*` — бинарники для
>    Windows, Linux и macOS в GitHub Release.
> 3. **Путь без Node остаётся: скачать exe из Release.** `install.cmd` собирает
>    бандл сам, если есть npm, иначе говорит, где взять готовый exe.
> 4. **`go.mod` в корне репозитория**, модуль `semaps`: `host/` и `core/` — пакеты
>    одного модуля, бинарник собирается как `go build ./host`.

## Отвергнуто

- **Оставить бандл в git.** Простой клон и `go install`, но плата — растущий
  репозиторий и нечитаемая история. Обещание «Node не нужен» выполняется Release-ом.
- **git LFS.** Снимает рост репозитория, но не шум в истории, и требует LFS у
  каждого, кто клонирует.
- **`go.mod` в `host/` с `replace` на `../core`.** Работает, но `go install`
  с `replace` не умеет, и два модуля ради одного бинарника — лишняя сущность.

## Следствия

- После `git clone` без Node хост не собирается — это ожидаемо, exe берётся из Release.
- `run.cmd` и `install.cmd` проверяют наличие `app/index.html` и объясняют, что делать.
- Обновление: `git pull` больше не обновляет редактор сам по себе; либо
  `install.cmd` с npm, либо новый exe из Release.
