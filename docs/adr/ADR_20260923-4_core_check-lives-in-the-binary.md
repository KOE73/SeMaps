# ADR_20260923-4_core — Проверка модели живёт в бинарнике, не в скрипте редактора

Статус: **принято**.

> В контексте **проекта-потребителя, у которого есть только workspace и `semaps.exe`**,
> столкнувшись с тем, что **единственная проверка модели (`check-model.mjs`) жила в
> `editor/scripts/`, требовала Node и репозиторий SeMaps под рукой, а список текстовых
> полей дублировала руками, потому что не могла импортировать TypeScript без сборки**,
> мы решили:
> 1. **Проверка — пакет `core/` на Go**, вызывается как `semaps check [dir | file.semaps]`
>    с теми же корнями и тем же порядком их поиска, что у сервера.
> 2. **Набор проверок и текст вывода — те же, что были в скрипте** (протухшие переводы,
>    расхождения, недостача текстов, вид без оси, противоречие контейнеров, битый
>    `codeRef`, имя-заглушка, необъявленный тип связи). Скрипт удалён.
> 3. **Хеш текста считается по UTF-16-единицам**, как в JavaScript редактора, чтобы
>    `fromHash` сходился между тем, кто пишет, и тем, кто проверяет.
> 4. **Список текстовых полей** по-прежнему держится в двух местах руками
>    (`core/check.go` и `editor/src/model/text-provenance.ts`); общего источника у Go и
>    TypeScript нет, и заводить его ради шести строк — дороже.

## Отвергнуто

- **Оставить скрипт и звать его из хоста через Node.** Возвращает зависимость от Node
  в проект-потребитель, которую [`ADR_20260923`](ADR_20260923_host_workspace-tool-source-roots.md) убрал.
- **Проверка внутри редактора, в браузере.** Не запускается из CI и агентом.

## Следствия

- `core/` перестал быть заглушкой; сверка с фактами извлекателя (`docs/EXTRACTOR.md` §5)
  ложится в тот же пакет — [`PLAN_20260923_core_sync-with-code`](../plans/PLAN_20260923_core_sync-with-code.md).
- Код выхода `1` при любом замечании: CI проекта-потребителя может звать `semaps check`.
