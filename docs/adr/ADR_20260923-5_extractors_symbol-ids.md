# ADR_20260923-5_extractors — Идентификаторы символов в фактах извлекателя

Статус: **принято**.

## Контекст

[`EXTRACTOR.md`](../EXTRACTOR.md) §2.1 требует от извлекателя `id` символа — устойчивый ключ
внутри одного вывода, «полное имя на языке кода». Для C# план
([`PLAN_20260923_extractors_csharp`](../plans/PLAN_20260923_extractors_csharp.md)) оставил
открытым вопрос generic-типов; для TypeScript понятия «полное имя» нет вовсе: имя живёт в
файле, а не в пространстве имён. Без правила два извлекателя выберут разное, и сверка не
сможет опираться на `id` как на ключ.

Извлекатели — **один из многих**, TypeScript пишется раньше C# как методологический образец.
Правило поэтому формулируется общее и уточняется по языкам.

## Решение

**Общее.** `id` — строка, однозначно называющая объявление в исходниках проекта и не зависящая
от имён параметров типа, порядка объявлений и содержимого тела. Регистр как в коде.
Уникален в выводе; два `partial`/повторных объявления — один символ.

**C#.** Метаданное имя с пространством имён: сегменты пространства имён через `.`, вложенный
тип через `+`, арность через обратную кавычку. Примеры:

| Код | `id` |
|---|---|
| `namespace A.B { class C {} }` | `A.B.C` |
| `class C<T>` в `A.B` | ``A.B.C`1`` |
| `class C { class D<T,U> {} }` в `A` | ``A.C+D`2`` |
| глобальное пространство имён | `C` |
| пространство имён как символ `module` | `A.B` |

Это `INamespaceSymbol`/`INamedTypeSymbol.MetadataName`, собранное по цепочке `ContainingType`
и `ContainingNamespace`. Имя параметра типа (`T` → `TItem`) `id` не меняет.

**TypeScript.** Путь модуля относительно корня, прямые слэши, **без расширения**, затем `#` и
имя экспортируемого объявления; вложенное объявление внутри `namespace` — через `.`. Примеры:

| Код | `id` |
|---|---|
| `export class DiagramCanvas` в `editor/src/canvas/DiagramCanvas.ts` | `editor/src/canvas/DiagramCanvas#DiagramCanvas` |
| `export default function` без имени | `editor/src/x#default` |
| `export namespace N { export interface I {} }` | `editor/src/x#N.I` |
| сам файл как символ `module` | `editor/src/canvas/DiagramCanvas` |

Только экспортированные объявления: не экспортированное — деталь файла, как приватный
вложенный тип в C#. Generic-параметры в `id` не входят: в одном модуле два экспорта с одним
именем невозможны.

**Другие языки** добавляют свой раздел сюда новым ADR, не правкой этого.

## Отвергнуто

- `ToDisplayString()` с параметрами (`A.B.C<T>`): переименование `T` меняло бы `id`, а с ним
  и ключ сверки.
- Только короткое имя (`C`): коллизии между пространствами имён и файлами неизбежны.
- Для TS — id по `package.json`-имени пакета: у монорепозитория один пакет на много файлов,
  ключ терял бы локальность.

## Следствия

- `schemas/extractor-facts.schema.json` ограничивает `id` регуляркой «непустая строка без
  пробелов»; форма по языкам проверяется тестами извлекателя, не схемой.
- Сверка (`core/`) выдаёт `e_`-id из `name` (§5 `EXTRACTOR.md`), а `id` фактов использует
  только как ключ сопоставления между прогонами. Ей форма `id` безразлична, важна устойчивость.
