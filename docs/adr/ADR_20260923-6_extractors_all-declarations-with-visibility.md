# ADR_20260923-6_extractors — Извлекатель печатает все объявления, видимость — поле

Статус: **принято**. Заменяет правило «только экспортированные» из
[`ADR_20260923-5`](ADR_20260923-5_extractors_symbol-ids.md) (формы `id` не касается).

## Контекст

`EXTRACTOR.md` §3 велел пропускать приватные вложенные типы «как не-архитектуру», а ADR-5 для
TypeScript — печатать только экспортированные объявления. Первые прогоны показали, что это
суждение не место извлекателю: карта нужна не только для верха айсберга. Тактическая схема
одного подсистемного узла хочет видеть приватный вложенный класс с его членами — то, чего не
хватало в диаграммах классов Visual Studio. Извлекатель, который заранее решил, что важно,
отнимает у вида выбор.

## Решение

1. Извлекатель печатает **все** объявления: вложенные любой видимости, не экспортированные
   объявления файла в TypeScript. Исключаются только сгенерированный код и выходы сборки.
2. У символа появляется необязательное поле `visibility` — словами языка (`public`, `internal`,
   `protected`, `private`, `exported`, `file`…). Отсутствие поля значит «публичный». Схема:
   `schemas/extractor-facts.schema.json`.
3. Что показывать, решает **вид** (фильтр по `visibility`), а по умолчанию — обзорные виды
   прячут непубличное. Правила фильтра в редакторе — отдельная работа, не этот ADR.
4. **TypeScript, `id` не экспортированного объявления** — та же форма, что у экспортированного
   (`путь#Имя`), `visibility: "file"`. Коллизия имён внутри файла между экспортированным и
   локальным объявлением в TS невозможна, `id` остаётся уникальным. Экспортированное —
   `visibility: "exported"`.
5. **C#**: `visibility` — `DeclaredAccessibility` самого символа, словами языка
   (`private`, `protected`, `internal`, `protected internal`, `private protected`, `public`).
   Публичный тип внутри приватного печатается с собственной видимостью `public`; цепочка
   контейнеров восстанавливается по рёбрам `contains`, дублировать её в поле не нужно.

## Отвергнуто

- Флаг `--include-private` у извлекателя: два режима — два разных вывода для одного кода,
  сверка теряет ключи при переключении.
- Вычислять «эффективную» видимость по цепочке контейнеров: скрыло бы факт, что тип объявлен
  публичным; вид может посчитать сам.

## Следствия

- Правка `EXTRACTOR.md` §2.1, §2.2, §3 в том же коммите.
- Оба извлекателя: печатать всё, ставить `visibility`; `expected.json` и числа `self`
  переснимаются.
- Сверка (`core/`) переносит `visibility` в `entities.json` как есть; это правка `CONTRACT.md`
  §3 при реализации `sync`, не сейчас.
