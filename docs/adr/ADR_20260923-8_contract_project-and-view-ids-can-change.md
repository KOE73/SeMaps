# ADR_20260923-8_contract — id проекта и вида можно менять; id сущности — нет

Статус: **принято**. Развивает [`ADR_20260923-7`](ADR_20260923-7_contract_projects-and-views-found-not-listed.md).

> В контексте **создания проектов и видов из редактора**, столкнувшись с тем, что
> - человек передумывает с именем, а id проекта — это имя папки, id вида — имя файла;
> - хост умел только писать файлы, и `/api/save` молча перезаписывал существующий — новый
>   проект с занятым id затёр бы чужой `project.json`,
>
> мы решили:
> 1. **id проекта и вида переименуемы.** На них ссылаются только изнутри проекта: `project` в
>    каждом виде, ключ текста вида в `text.<lang>.json`, `defaultView`. Переименование
>    переписывает ровно это. Тексты переезжают с происхождением: переименование не делает
>    перевод авторским.
> 2. **id сущности, связи, контейнера по-прежнему неизменны** (контракт §9.1): на них
>    ссылаются виды, связи и тексты, и сверка с кодом держится за них.
> 3. **Хост получает `POST /api/move`** — переименование папки проекта или файла вида, только
>    внутри `projects/`, никогда поверх существующего (`409`).
> 4. **`/api/save?create=1`** создаёт файл, только если его нет (`409` иначе). Редактор
>    создаёт проект и вид только так.
> 5. **Проверка совпадений — в диалоге, при вводе:** занятый id, название проекта, имя вида
>    в проекте подсвечиваются сразу, кнопка неактивна. `409` от хоста — последняя линия на
>    случай, если файл появился на диске в обход редактора.
> 6. **Переименование при несохранённой открытой схеме того же проекта запрещено**: её
>    сохранение писало бы по старому пути и вернуло бы старые имена. Сначала сохранить.

## Отвергнуто

- **Неизменяемые id, переименовывается только название.** Тогда папка `shop` навсегда живёт
  под проектом «Биллинг» — ровно та рассинхронизация, от которой уходили в ADR-7.
- **Удалить и создать заново вместо переноса.** Теряется история файла в git и происхождение
  текстов.
- **Общий `/api/move` по всему workspace.** Переносить `styles.json` или `content/` никому
  не нужно; чем уже дверь, тем меньше за ней можно сломать.

## Следствия

- Переименование — несколько запросов подряд, не транзакция. Сбой посередине оставляет
  частично переписанный проект; `semaps check` покажет, что не сошлось.
- Агент, записавший `id` вида где-то вне проекта, после переименования ссылается в пустоту.
  Вне проекта на виды ссылаться нечем и незачем.
