# ADR_20260924-3_host — Инструменты рядом с бинарником; `.semaps` описывает экстракторы; `/setup`

Статус: **принято**. Заменяет шаги 4 и 6
[`PLAN_20260923_core_sync-with-code`](../plans/PLAN_20260923_core_sync-with-code.md)
(`sources.language` в `project.json`, поиск экстрактора только в PATH) и способ установки
экстрактора C# из
[`README.md`](../../README.md) (отдельный `.nupkg` и `dotnet tool install`).

## Контекст

Сейчас это три независимых инструмента: `semaps.exe`, `semaps-extract-csharp` (dotnet tool
из `.nupkg`), экстрактор TS (npm-пакет). Каждый ставится по-своему, `semaps sync` требует
готовый файл фактов, а агенту в чужом проекте неоткуда узнать, где взять экстрактор и с
какими путями его звать. Цикл «извлечь → посмотреть → сверить» знает только человек.

Пользователи — разработчики: SDK и runtime их языка у них есть. Если нет — достаточно
внятно сказать, чего не хватает.

## Решение

### 1. Поставка: всё в одной папке

```
<папка установки>/
  semaps.exe
  extractors/csharp/    semaps-extract-csharp.exe (+ dll; dotnet publish, framework-dependent)
  extractors/typescript/  extract.mjs (один бандл; запускается node)
```

`install.cmd` и релиз CI собирают все три части одной версией; `semaps install` кладёт
папку целиком. Runtime (dotnet SDK — Roslyn/MSBuildLocator его требует в любом случае,
node) не поставляется: его отсутствие — диагноз, а не сбой.

Каждый экстрактор остаётся **самостоятельной программой** с контрактом
[`EXTRACTOR.md`](../EXTRACTOR.md): факты в stdout. `semaps.exe` — лишь удобный способ его
позвать.

Поиск экстрактора языка `L`: `command` из `.semaps` → `extractors/L/` рядом с
`semaps.exe` → `semaps-extract-L` в PATH.

### 2. `.semaps` описывает экстракторы проекта

```yaml
extractors:
  - id: backend
    language: csharp
    project: core            # модельный проект, в который сверять
    root: .                  # от корня проекта (папки .semaps)
    include: [src]
    exclude: ["**/*.Tests/**"]
  - id: editor
    language: typescript
    project: editor
    root: editor
    include: [src]
    # command: node ../SeMaps/extractors/typescript/dist/cli.js   — только в файле, см. §5
```

Экстракторов в проекте сколько угодно: в одном репозитории бывают и C#, и TS. Что
извлекать и откуда — забота инструмента и живёт в `.semaps`; `project.json` остаётся
контрактом модели и о языках не знает.

Формат `.semaps` — настоящий YAML (`gopkg.in/yaml.v3`) вместо плоских `key: value`:
список без него не выразить. Существующие файлы остаются валидными.

### 3. Один движок, три способа управлять

Цикл: **extract → посмотреть → sync --dry-run → посмотреть → apply.**

| | CLI (агент, CI) | HTTP (редактор) |
|---|---|---|
| что найдено, чего не хватает | `semaps doctor` | `GET /api/tools` |
| настройки | правка `.semaps` | `GET` / `PUT /api/setup` |
| извлечь | `semaps extract [id]` | `POST /api/runs` → лог потоком |
| сверить | `semaps sync [id] [--dry-run]` | `POST /api/runs/{run}/sync` (dry-run, затем apply) |

**Apply пишет те же факты, по которым показан dry-run**, без повторного извлечения:
прогон — это папка во временном каталоге с фактами, логом и статистикой (символы и
рёбра по видам, время, предупреждения), у неё есть id. Факты никогда не лежат в
workspace и в git. `semaps sync --facts` остаётся для отладки и CI.

### 4. `/setup` в редакторе

Страница в том же приложении: проект и инструменты (что найдено, есть ли runtime);
экстракторы (правка параметров, «Извлечь», живой лог, статистика); сверка (отчёт по
разделам, «Записать»; после записи редактор перечитывает проект). Кнопка «Сверить» в
редакторе ведёт сюда.

`.semaps` из UI правится **через дерево YAML с комментариями** (`yaml.v3` `Node`):
меняются только тронутые узлы, комментарии и порядок ключей остаются. Если на каком-то
случае это потребует сложности сверх этого — комментарии не святые, но цель —
сохранять.

### 5. Безопасность — просто

Страница, которая запускает процессы, не должна превращаться в «выполни что угодно»:

1. Хост слушает только `localhost` (как сейчас).
2. Всё, что меняет или запускает, проходит `sameOrigin` (как сейчас для записи) —
   чужая вкладка в том же браузере не достучится.
3. **Командную строку из UI задать нельзя.** Через HTTP правятся только данные:
   `language`, `project`, `root`, `include`, `exclude`. Поле `command` — только в файле;
   UI его показывает, но не пишет. Запускается лишь найденный по §1 экстрактор с
   аргументами, собранными хостом, без оболочки (`exec`, не `cmd /c`).
4. Все пути из запросов — относительные и проходят `inside()` к корню проекта.

Токенов, логинов и ролей нет: на localhost они ничего не добавят к п. 1–3.

### 6. Путь отступления к серверу (не делается сейчас)

Запуск хоста на сервере для команды — вероятно, через год. Сейчас не строим, но и не
замуровываем:

- API говорит **только относительными путями** проекта; абсолютные пути машины наружу
  не отдаются и не принимаются.
- Запуск процессов — за одним интерфейсом (`runner`); прогоны адресуются id, лог идёт
  потоком по HTTP, а не в консоль хоста.
- Проверки «можно ли» собраны в одну точку (middleware), а не разбросаны по
  обработчикам: там же потом встанет аутентификация.
- Ничего в UI не предполагает, что браузер и хост на одной машине, кроме уже
  существующего «открыть в редакторе кода».

## Отвергнуто

- **Экстрактор только как dotnet tool / npm-пакет в PATH.** Отдельная установка на каждый
  язык, версии расходятся с `semaps.exe`, агент не знает, откуда взять.
- **Автономный exe экстрактора C#.** Roslyn с MSBuildLocator всё равно требует SDK.
- **Язык и корни в `project.json`.** Смешивает контракт модели с настройкой инструментов
  конкретной машины; один модельный проект не обязан соответствовать одному экстрактору.
- **Правка `command` из UI.** Превращает страницу в запуск произвольных команд.
- **Токен сессии.** На localhost при `sameOrigin` и запрете `command` из UI не добавляет
  защиты; вернуться вместе с серверным режимом.
