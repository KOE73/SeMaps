# ADR_20260924-5_host — MCP-сервер внутри `semaps`: агент работает через инструменты, не по файлам

Статус: **принято**. Дополняет [`ADR_20260924-3`](ADR_20260924-3_host_tools-beside-the-binary-and-setup.md)
(один движок, несколько входов) и
[`ADR_20260924_contract`](ADR_20260924_contract_agent-lays-out-views-on-request.md) (геометрия —
только по явной просьбе).

## Контекст

Реестр правит в основном агент. Сегодня он читает `entities.json` и `relations.json` целиком —
это сотни килобайт в контекст — и пишет их руками: выдумывает `id`, забывает `origin`/`at` у
текстов, может нарушить контракт так, что заметит только `semaps check`. При членских связях
([`ADR_20260924-4`](ADR_20260924-4_contract_member-relations-from-code.md)) файлы растут, и
читать их подряд становится нельзя.

`core/` уже умеет читать, проверять и сверять; HTTP API уже есть; проект знает себя из `.semaps`.

## Решение

1. **`semaps mcp`** — MCP-сервер по stdio (JSON-RPC) в том же бинарнике, на тех же `core/` и
   правилах, что редактор и CLI. В проекте потребителя — одна запись в `.mcp.json`
   (`command: semaps, args: [mcp]`; корни — как у `semaps` без аргументов, от текущей папки).
2. **Файлы остаются источником истины и контрактом.** MCP — удобный вход к ним, не замена:
   всё, что делает сервер, можно сделать руками по `CONTRACT.md`, и `check` проверяет
   результат одинаково.
3. **Сервер гарантирует структуру**: выдаёт `id` (те же правила, что сверка), проверяет запись
   по контракту до сохранения, ставит `origin`/`at` у текстов сам, не даёт удалить то, что
   удалять нельзя, пишет в `views/` только по явному параметру «человек попросил».
4. **Инструменты первой очереди** (чтение — свободно, запись — с проверкой):
   - проекты и виды; сущность по id/имени/символу; сущности модуля;
   - связи сущности с фильтром по типу, видимости, направлению; связь по id;
   - тексты: прочитать / записать имя, описание, подписи (`origin: authored`);
   - включить / выключить связь на виде; поставить/снять `except`;
   - `doctor`, `extract`, `sync --dry-run`, `sync`; подтвердить переименование сущности
     (`symbol`) и члена (`via.member`);
   - завести авторскую связь и тип связи.
5. **Серверный режим** — тот же путь отступления, что в ADR-3 §6: транспорт stdio сейчас,
   HTTP-транспорт MCP — когда понадобится, поверх той же точки проверок.

## Отвергнуто

- **Отдельный MCP-сервер на Node/Python.** Второй набор правил рядом с `core/` — разойдутся.
- **MCP вместо файлового контракта.** Файлы читают git, редактор, `check`, человек;
  контракт остаётся на файлах.
- **Делать до модели связей.** MCP ляжет на `core/`; если сделать раньше, придётся переписывать
  под новую модель.

## Последствия

- `ADOPTING.md` получает второй путь для агента: «через MCP» как основной, «по файлам» как
  запасной.
- Каждое правило контракта, которое сервер обещает соблюдать, должно жить в `core/`, а не в
  обработчике MCP — иначе редактор и CLI его не увидят.
