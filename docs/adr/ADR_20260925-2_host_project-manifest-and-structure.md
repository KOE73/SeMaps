# ADR_20260925-2_host — Манифест в модели, создание и переименование как структурные операции

Статус: **принято**. Уточняет [`ADR_20260925_host`](ADR_20260925_host_model-owned-by-host.md):
манифест проекта входит в рабочее состояние; перенос файлов и папок остаётся отдельной операцией
хоста. Формат файлов контракта не меняется.

## Контекст

Редактор меняет `project.json` (название, значок, ось по умолчанию, языки и другие поля). После
перехода на модель хоста прежняя запись этого файла через `/api/save` противоречила бы одному
рабочему состоянию и общей кнопке «Сохранить». Создание и переименование, напротив, меняют
структуру файлов проекта и идентификаторы, поэтому их нельзя выразить заменой обычного объекта
в уже загруженном реестре или виде.

## Решение

1. `project.json` — объект рабочей модели с `id`. Операция `Op{Kind: "project", ID, Value,
   Author}` заменяет манифест целиком. Она отмечается как несохранённое реестра, пишется в журнал
   и попадает в общее «Сохранить». Редактор меняет поля манифеста через эту операцию. Порядок
   существующих ключей при записи сохраняется.
2. Создание проекта или вида, переименование проекта или вида — структурные операции хоста:
   создание файла либо перенос файла/папки с необходимой сменой `id` и текстового ключа. Они
   выполняются только при отсутствии несохранённых изменений в затронутом проекте. Иначе хост
   отвечает `409` с требованием сначала сохранить.
3. После успешной структурной операции хост перечитывает модель затронутого проекта из файлов
   и рассылает подписчикам событие «проект перезагружен». Окна заново получают снимок и открытый
   вид. При переименовании проекта событие содержит старый и новый `id`, чтобы окна могли открыть
   новый адрес.

## Не выбрано

- Писать `project.json` напрямую из редактора при обычной правке метаданных: это обошло бы журнал
  и общую кнопку «Сохранить».
- Проводить перенос файла/папки через объектные операции: замена объекта не переносит путь и не
  сохраняет целостность ссылок на переименованные `id`.
