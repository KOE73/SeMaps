# ADR_20260925_host — Модель проекта держит хост: рабочее состояние, «Сохранить», события, MCP по HTTP

Статус: **принято**. Уточняет [`ADR_20260924-5`](ADR_20260924-5_host_mcp-server.md) §1 и §5: MCP
отдаёт запущенный `semaps` по HTTP на своём порту, `semaps mcp` по stdio становится прокси к нему.
Не отменяет [`ADR_20260924`](ADR_20260924_contract_agent-lays-out-views-on-request.md): геометрию
агент пишет только по просьбе человека.

## Контекст

Сейчас у проекта два писателя, которые друг о друге не знают:

- **редактор** грузит файлы проекта статикой, держит модель у себя в памяти и по «Сохранить»
  отправляет файлы целиком в `/api/save`;
- **`semaps mcp`** — отдельный процесс; читает и пишет те же файлы напрямую.

Отсюда три тихие беды. Человек не сохранил → агент работает по старому состоянию диска → «Сохранить»
в редакторе молча затирает работу агента. Агент записал → редактор этого не видит до F5. Человек и
агент правят одновременно → прав тот, кто сохранил последним.

Одновременно растёт роль агента в раскладке видов: «разложи эти семь контейнеров как тот» — десять
минут ручного таскания против одной команды. Давать агенту геометрию при двух слепых писателях
опасно.

Охрана файлов (версии, отказ при чужой записи, события «файл изменён») эти беды закрывает, но
остаётся надстройкой над неверным разделением: модель по-прежнему живёт в браузере. Раз к модели в
хосте всё равно идти, промежуточная ступень — лишняя работа.

## Решение

### 1. Хост — единственный хозяин модели

Запущенный `semaps` держит в памяти **рабочее состояние** проекта: реестр (сущности, связи, типы,
тексты) и виды. Браузер и агент читают и меняют модель только через хост. Файлы контракта
([`CONTRACT.md`](../CONTRACT.md)) не меняются: это по-прежнему формат хранения и то, что идёт в git.

### 2. Гранулярность — объект

Единица изменения, события и конфликта — **объект с `id`**: сущность, связь, тип связи, запись
текстов под ключом, вид (его свойства), зона на виде, размещение сущности на виде. Поле внутри
объекта — не единица: двое одновременно правят один объект редко, а если правят — второй получает
событие и видит новое. Слияния полей нет: последняя запись объекта выигрывает, и все её видят.

### 3. Рабочее состояние и «Сохранить»

- Каждое изменение сразу попадает в рабочее состояние и в **журнал** `<корень проекта>/.semaps/work/`.
  Закрытый браузер, F5, упавший хост ничего не теряют: при старте хост поднимает журнал.
- **«Сохранить»** — одно на проект: записывает в файлы контракта всё несохранённое, и виды, и
  реестр. Описание сущности, поправленное «на виде», — правка реестра, и сохраняется вместе со
  всем. Сохранения по одному виду нет: две оси (вид и реестр) на одном экране, одна кнопка.
- Перед записью «Сохранить» показывает **сводку**: что изменено и кем — вы, агент — по видам и
  реестру. Этого достаточно, чтобы не сохранить вслепую чужую работу.
- После «Сохранить» журнал очищается. Сохранил — решил.
- **«Отменить несохранённое»** — у вида (его геометрия к файлу) и у реестра (к файлам). Это нынешний
  F5, только точечно и осознанно; ничего другого для отката нет.
- Агент сам не сохраняет. Закончив, он отвечает «сделал, не сохранено — проверьте» и даёт
  **ссылку**, которая открывает вид и подсвечивает тронутые объекты. Инструмент `save` у агента
  есть, но вызывается только по прямой просьбе человека.

### 4. События

Хост рассылает изменения всем подключённым: окнам браузера и MCP-сессиям. Пришло событие —
окно применяет объект и перерисовывает: агент подвинул блок — на экране блок поехал. Несколько окон
одного проекта синхронны сами собой. В каталоге у вида с несохранённой геометрией — значок с
автором; у реестра — строка «Реестр: изменено N».

### 5. Загрузка в браузер

- сразу: каталог проекта и видов (с отметками несохранённого) и **снимок реестра** одним ответом —
  он нужен любому виду, по объёму это то, что грузится сейчас (NeuroModFlowNet: 0,85 МБ, сжатым —
  около 100 КБ);
- по открытию вида: его геометрия;
- дальше — только события.

Браузер получает рабочее состояние, а не файлы: с несохранёнными правками — своими и агента.

### 6. Undo — только у вида и только в браузере

Промах мышью — геометрия: зацепил, не то выравнивание, подвинул и не понравилось. Undo остаётся
там, где он сейчас, — в окне браузера, по виду, для своих действий; хост его не хранит. У реестра
Undo нет: тексты и связи правят осознанно, страховка — «отменить несохранённое». Отмены команд
агента нет: перед заданием агенту сохраняются, после — проверяют и сохраняют или откатывают вид.

### 7. MCP по HTTP в том же процессе

- Запущенный `semaps` отдаёт MCP (Streamable HTTP) на своём порту: `/mcp`. Модель одна, у агента
  и у браузера.
- `semaps mcp` по stdio остаётся тем, что пишут в `.mcp.json`: он находит хост проекта; не нашёл —
  поднимает его в фоне; дальше пересылает сообщения в `/mcp`. У клиента агента ничего не меняется.
  Работа с файлами в обход хоста уходит.
- Порт закрыт **ключом**: хост при старте кладёт его в `.semaps/` (вне git), stdio-прокси и браузер
  его предъявляют. Без ключа `/mcp` и запись API отвечают 401.

## Отвергнуто

- **Охрана файлов как отдельная ступень** (версии, 409 на чужую запись, события «файл изменён»).
  Закрывает беды, но оставляет модель в браузере; при переезде модели в хост выбрасывается.
- **Поле как единица изменения и слияние полей.** Одновременная правка одного объекта редка; цена
  — сложная машинерия ради редкого случая.
- **Сохранение по виду.** Правка на виде — часто правка реестра; раздельные кнопки путают, что
  куда ушло.
- **Хранить журнал после «Сохранить»**, откат сохранённого. Для этого есть git.
- **Undo в хосте, общий для окон и агента; отмена отдельной команды агента.** Сложно, а рабочий
  приём проще: сохраниться перед заданием, проверить после.
- **«Все видят всё» — трансляция каждого промежуточного движения мыши.** В события уходит результат
  действия, а не его ход.
- **Переписать хост на .NET.** Математика геометрии живёт в редакторе (TS); хост тонкий, Go даёт
  один маленький exe без рантайма и быстрый старт stdio-прокси. .NET остаётся там, где нужен
  Roslyn, — в C#-извлекателе.

## Последствия

- Редактор перестаёт писать файлы: `/api/save` для файлов проекта уходит, загрузка статикой — тоже
  (статикой остаются `styles.json`, `templates.json`, `content/`, пока их не перевели).
- Хост становится stateful: память, журнал, рассылка, ключ.
- `core/edit.go` — единая точка правил записи — теперь работает над рабочим состоянием, а не над
  файлами; `core.Sync` тоже.
- Инструменты раскладки для агента (`get_view`, ссылка на объект, «разложи по образцу», move/resize)
  ложатся на эту модель; без неё давать их агенту опасно.
- `docs/API.md` (§ модель, события, `/mcp`), `docs/ADOPTING.md` (ключ, «сделал, не сохранено»),
  `docs/LAYOUT.md` меняются вместе с кодом.
