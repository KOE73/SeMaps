# ADR_20260927-4_contract — Внешний символ: `nativeKind: external`, без файла

Статус: **принято**. Дополняет [`ADR_20260927`](ADR_20260927_contract_closed-relation-vocabulary.md) §5.

## Контекст

Go-извлекатель вычисляет `implements` только между типами прочитанного кода; внешние
интерфейсы (`io.Reader`, `error`, `http.Handler`) перечисляются в записи извлекателя
(`implements: [...]`). Но [`EXTRACTOR.md`](../EXTRACTOR.md) §2.2 разрешает ребро только между
символами вывода, а символ обязан иметь `file` под `root`. Ребро «`Log` реализует `io.Writer`»
печатать некуда.

## Решение

1. Символ вне прочитанного кода, нужный ребру как конец, печатается как **внешний**:
   `nativeKind: "external"`, без `file`, `line`, `visibility`. `kind` — какой есть
   (`interface`), `id` — полное имя (`io.Writer`; предопределённый `error` — `error`).
2. Извлекатель печатает внешний символ **только по явному списку** своей записи в `.semaps`
   и только если на него указывает хотя бы одно ребро.
3. Сверка не фильтрует внешний символ по `sources.include`. Он становится обычной сущностью
   (`kind: external` по правилу «`kind` = `nativeKind`», если не привязан к уже существующей)
   с записью `code[]` `{lang, symbol}` **без `ref`**: файла нет, кнопки кода нет.
4. Запись `code[]` / `evidence[]` обязана иметь `ref` **или** быть привязанной к символу.

## Отвергнуто

- **Особое поле ребра** (`toExternal: "io.Writer"`). Второй вид конца ребра в каждом читателе
  фактов; сверке всё равно нужна сущность, к которой вести связь.
- **Все интерфейсы библиотек без списка.** Полный перебор пар — шум и время (ADR_20260927 §5).
- **Фиктивный `file`** (`<external>`). Ломает `check` и просмотр кода; ложь в данных.

## Следствия

- `EXTRACTOR.md` §2.1, `schemas/extractor-facts.schema.json`: `file` необязателен у `external`.
- `CONTRACT.md` §3: `ref` у записи `code[]` необязателен, если есть `symbol`.
- `docs/extractors/go.md`: правило внешних символов.
