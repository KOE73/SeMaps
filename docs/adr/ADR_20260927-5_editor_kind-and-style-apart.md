# ADR_20260927-5_editor — Вид и стиль блока — два разных поля

Статус: **принято**.

## Контекст

Контракт уже разводит два понятия: `kind` сущности (`entities.json`) говорит, **что это**, а
`styleId` размещения (`views/`) — **как это выглядит** на конкретной схеме. Редактор их склеивал.
Поле «Тип элемента» в «Свойствах» предлагало все блочные стили подряд и писало выбор в `type`
элемента, а `type` одновременно работал как `kind` сущности и как запасной `styleId`. Получалось:

- в одном списке лежали виды из кода (Класс, Struct, Enum), архитектурные оформления (Хранилище,
  Внешняя система, Actor) и стили зон, хотя блок не может стать зоной;
- у сущности из кода выбор «Хранилище» тихо переписывал её `kind`, хотя сверка вернула бы его
  обратно;
- рядом уже был отдельный выбор стиля, который пишет `styleId`, — два поля с одним списком.

Виды бывают двух сортов: **языковые** (`class`, `record`, `struct`, `interface`, `enum` — их
приносит код) и **архитектурные** (`external`, `database`, `app`, …: их ставит человек). На
общей архитектурной схеме стили «Класс» и «Struct» не нужны.

## Решение

1. **«Вид»** в «Свойствах» показывает `kind` сущности. У сущности с `origin: code` — только для
   чтения: вид меняется в коде. У нарисованной — редактируется (свободная строка с подсказками),
   и сохранение записывает его в `kind` сущности. Ни один путь сохранения не переписывает `kind`
   сущности из кода.
2. **«Стиль»** — единственное место, где выбирают внешний вид. Выбор пишет `styleId`
   размещения; «Сбросить к виду» убирает его.
3. **Стиль по умолчанию для вида** — как было: стиль, чей `id` равен `kind`; нет такого —
   `default.node` / `default.zone`. Отдельной таблицы соответствий нет.
4. **У стиля новое необязательное поле `kinds`** — виды, которым его предлагать. Нет поля —
   стиль общий, предлагается любому блоку, но не зоне: зоне — только стили с `zone`. Поле наследуется через `basedOn`. Выбор стиля в «Свойствах»
   показывает только подходящие виду блока стили; переключатель «все стили» снимает фильтр.
   Встроенные стили: языковые (`class`, `record`, `struct`, `interface`, `enum`,
   `class.detail`) и устаревшие (`component`, `service`, `concept`) помечены своими видами,
   `default.zone` — видом `zone` (от него его наследуют все стили зон). Архитектурные стили
   остаются общими.

## Отвергнуто

- **Группы видов** («код» / «архитектура») вместо списка видов у стиля. Ещё одно понятие, которое
  надо объявлять и поддерживать; список видов у стиля выражает то же без него.
- **Явная таблица «вид → стиль по умолчанию»** в `styles.json`. Второе место для правки при
  том, что соглашение «`id` стиля = вид» уже работает и понятно по имени стиля.
- **Оставить одно поле, но отфильтровать список.** Не убирает главного: выбор внешнего вида
  не должен менять, чем сущность является.

## Следствия

- `CONTRACT.md` §11.5: поле `kinds`, каскад выбора стиля блока.
- `host/defaults/styles.json`, `editor/src/model/style-defaults.ts`: `kinds` у языковых, устаревших
  стилей и у `default.zone`.
- Редактор стилей правит `kinds` блочного стиля.
