# ADR_20260927-6_contract — Контракт v5: словарь типов, контейнер — это сущность

Статус: **принято**. Заменяет [`ADR_20260927-5`](ADR_20260927-5_editor_kind-and-style-apart.md)
в части поля стиля `kinds` и его правила для зон; разведение «тип ≠ стиль» остаётся в силе.

## Контекст

1. **Тип сущности (`kind`) — открытая строка без словаря.** Редактор подсказывал случайный
   набор, агент через MCP видел голые слова: `stage`, `concept`, `app` ни о чём не говорят без
   описания. Жёсткий enum тоже не годится: извлекатели приносят `nativeKind` языка, проект
   заводит свои архитектурные типы.
2. **Одна вещь называлась тремя словами**: контейнер (реестр), зона (вид и UI), рамка.
3. **Контейнер не был сущностью.** `containers.json` был описан в контракте, но ни одна строка
   кода его не читала и ни одного такого файла не было. Зона вида жила без типа, происхождения
   и описания; её имя держалось на соглашении `z_` → `c_`. При этом извлекатели уже приносят
   контейнеры кода (`namespace`, `assembly`, `package`) **сущностями** со связями `contains` —
   две модели одного понятия.
4. **Частный вид одного блока требовал нового стиля.** Отсюда «Зона · red», «Зона · red ·
   пунктир» и так далее.

## Решение

1. **Словарь типов `kinds.json`** — общий для рабочего пространства, рядом со `styles.json`.
   Группы → типы; у типа имя и описание на языках, признак `container` и базовый стиль.
   Инструмент поставляет базовый словарь (`host/defaults/kinds.json`); файл рабочего
   пространства **дополняет** его: новые группы и типы добавляются, совпавший `id` заменяет
   запись целиком. Словарь **не enum**: тип вне словаря допустим, редактор и `semaps check`
   помечают его «не из словаря». MCP отдаёт словарь инструментом `get_kinds`.
2. **Термин — «контейнер».** Контейнер — не отдельный род объектов, а **роль типа**: тип с
   `container: true` рисуется рамкой и может держать другие размещения. `namespace`, `package`,
   `subsystem`, `layer` — разные типы с этой ролью. Слово «зона» уходит из контракта, UI и MCP.
3. **Контейнер — это сущность** в `entities.json`, с типом-контейнером, происхождением,
   статусом, кодом и текстами, как любая другая. `containers.json` упраздняется вместе с
   правилами `match`/`overrides` и соглашением `z_`/`c_`. Принадлежность в реестре — связь
   `contains` (её уже пишет сверка для контейнеров кода); вложенность на виде — поле `parent`
   размещения, своё у каждого вида и его оси. Декоративной рамки без сущности больше нет:
   «группа для глаз» — сущность типа `group`, и она переносится на другой вид целиком.
4. **Вид — один массив `placements`.** Блоки и контейнеры размещаются одинаково:
   `{entity, parent, x, y, width, height, styleId?, override?, template?, collapsed?}`.
   Рамка это или блок — решает тип сущности, а не массив в файле.
5. **`override` на размещении** — частичный стиль этого одного размещения. Разрешённые поля
   перечислены одной таблицей в коде и одной в контракте (сейчас: заливка, цвет и штрих
   рамки, значок); новое перекрываемое поле добавляется строкой в обе таблицы.
6. **Стили:** у стиля `appliesTo` = `block` \| `container` \| `edge`; поле «для каких типов» —
   `forKinds` (было `kinds`, путалось с `kind` сущности). Каскад стиля размещения: `styleId` →
   базовый стиль типа из словаря → стиль с `id` = тип → `default.node` / `default.container`;
   затем поверх — `override`.
7. **Версия 5.** Загрузчик отвечает на проект версии ниже 5 и на вид с `zones`/`nodes` ошибкой,
   называющей файл и поле ([`ADR_20260927-3`](ADR_20260927-3_core_migrations-outside-the-loader.md)).
   Свои данные (`examples/`, карта SeMaps) переводятся в том же коммите.

## Отвергнуто

- **Жёсткий enum типов в коде.** Каждый новый язык и каждый проект правил бы бинарник.
- **Группы типов вместо признака `container`.** `namespace` — это «код» и одновременно
  контейнер; группа отвечает на «откуда тип», признак — на «рисуется ли рамкой».
- **Сохранить `containers.json` и научить его читать.** Вторая модель сущности со своим
  жизненным циклом ради того, что связь `contains` уже выражает.
- **Оставить декоративную рамку без сущности.** Второй путь в каждом читателе вида; группа
  без смысла — всё равно сущность, просто типа `group`.
- **Правила `match` в новой форме.** Не реализованы ни разу; если понадобятся, это правило
  сверки, порождающее связи `contains`, отдельным решением.
- **Переопределять любые поля стиля на размещении.** Форма и шаблон — «что это», а не
  «выделить один блок»; открытый список полей вернул бы разрастание, только в видах.
