# ADR_20260927-7_contract — Стиль принадлежит типу

Статус: **принято**. Заменяет [`ADR_20260927-6`](ADR_20260927-6_contract_v5-kinds-and-containers.md)
в части `forKinds` (там — необязательное и наследуемое) и выбора стиля в редакторе.

## Контекст

После v5 блок получал стиль из длинного списка «подходящих» стилей. Стили без `forKinds`
подходили всем, поэтому действующему лицу предлагалось хранилище, а `forKinds`, унаследованный
через `basedOn`, клал «Компонент» под «Класс». Явный стиль побеждал тип: смена типа блока не
меняла его вида. Цветные стили контейнеров (`container.green` и ещё двенадцать) не принадлежали
никакому типу и умножали список.

## Решение

1. **Стиль блока или контейнера принадлежит типу:** `forKinds` обязателен и не наследуется через
   `basedOn`. Стиль может числиться за несколькими типами (`class.detail` — за `class`, `record`,
   `struct`). Исключения — запасные `default.node` / `default.container` для типа, у которого
   своего стиля нет; в выборе стиля их нет. Стили связей устроены по-прежнему.
2. **Один механизм установки** — «тип и стиль» одним действием над выделением. Точки входа:
   - «Свойства»: выбор типа ставит его базовый стиль; строка вариантов — только если у типа
     больше одного стиля;
   - контекстное меню блока: варианты стиля его типа с предпросмотром;
   - панель «Стили»: открыть тип до стиля и «Применить» — ставит и тип, и стиль.
   Базовый стиль типа явным `styleId` не записывается: выбор базового снимает `styleId`.
3. **Смена типа снимает явный `styleId`** — блок сразу выглядит как новый тип.
4. **Цвет — локальная правка, не стиль.** Цветные стили контейнеров упразднены; в `override`
   добавлено поле `header.fill`, а «Выделить» получает палитру готовых цветов.
5. Стиль без `forKinds` в `styles.json` рабочего пространства не теряется: редактор показывает
   его в разделе «Без типа», пока ему не назначат тип.

## Отвергнуто

- **Общие стили для всех типов.** Именно они делали список бессмысленным.
- **Цветные стили под каждым типом-контейнером.** 13 цветов × 11 типов в дереве стилей.
- **Наследовать `forKinds` через `basedOn`.** Вариант внешнего вида — не вариант смысла:
  «Компонент», нарисованный как класс, не становится классом.

## Следствия
