# ADR_20260927_contract — Словарь связей закрыт и описывает архитектуру, а не язык

Статус: **принято**.

## Контекст

Третий извлекатель (Go) с первого шага задал вопросы, на которые у контракта нет правила:
встраивание (`struct{ Base }`) — это `extends`, `holds` или новый вид? Неявная реализация
интерфейса — `implements`? [`EXTRACTOR.md`](../EXTRACTOR.md) §2.2 отвечал на встраивание
мимоходом («встраивание по смыслу наследования» — `extends`), и этот ответ для Go неверен:
`User` со встроенным `Base` нельзя подставить вместо `Base`.

Если каждый язык приносит свои виды связей, к пятому извлекателю карта становится словарём
диалектов. Хуже того, схему, нарисованную **до** кода («нарисовал → агент реализовал»),
нельзя нарисовать, не выбрав заранее язык, и нельзя реализовать двумя языками
([`ADR_20260927-2`](ADR_20260927-2_contract_entity-is-intent-code-is-realizations.md)).

Для символов разделение уже есть: общий `kind` и свободный `nativeKind`
([`EXTRACTOR.md`](../EXTRACTOR.md) §2.3). Для рёбер его не было.

## Решение

1. **Словарь `kind` рёбер закрыт** и описывает архитектурный смысл:
   `extends` (подтип / расширение контракта), `implements` (соответствует контракту),
   `contains` (структурная вложенность), `depends` (единица сборки зависит от единицы сборки),
   `holds` (держит / состоит из), `uses` (пользуется, не держа).
   Сверка, фильтры, видимость, сопоставление с нарисованным работают только по нему.

2. **Новый `kind` вводится новым ADR** и только при всех четырёх условиях:
   1. понятие есть (или имеет близкий аналог) в нескольких языках;
   2. оно выражает архитектурный смысл, а не механизм языка;
   3. сведение к существующим видам теряет существенную информацию;
   4. человек нарисовал бы эту связь на пустой карте, **ещё не выбрав язык**.

   Четвёртое — решающее. Встраивание Go, явная реализация интерфейса C#, lifetime Rust,
   virtual-наследование C++, declaration merging TS — все проваливают его: это детали
   реализации.

3. **Как язык выразил связь — `native` на ребре факта**, свободная строка словами языка
   (`embed`, `methodset`, `field`, `property`, `impl`). Сверка **не** сравнивает `native`;
   он переносится в запись основания связи (`evidence[]`, ADR_20260927-2) и служит показу и
   фильтрам. Нет `native` — язык выразил связь единственным очевидным способом.

4. **Сопоставление «конструкция языка → `kind`/`native`» — нормативная таблица в
   `docs/extractors/<lang>.md`.** Каждая строка: конструкция, `kind`, `native`, почему именно
   так, какие варианты отвергнуты и почему. Каждая строка покрыта примером в `testdata`
   извлекателя, и тест проверяет результат: расхождение таблицы и кода роняет сборку.
   Язык без такой таблицы извлекателя не получает.

5. **Первое применение — Go:**

   | Конструкция | `kind` | `native` | Почему не иначе |
   |---|---|---|---|
   | `struct{ Base }` | `holds` | `embed` | не `extends`: подстановки нет, это композиция |
   | `interface{ io.Reader }` | `extends` | `embed` | это расширение контракта, как `IA : IB` в C#; не `holds`: состояния нет |
   | набор методов `T` ⊇ интерфейс | `implements` | `methodset` | реализация неявная, смысл тот же |
   | набор методов только `*T` ⊇ интерфейс | `implements` | `methodset.ptr` | не отдельная связь: смысл тот же |

   `implements` вычисляется только для пар, где **и тип, и интерфейс** из читаемого кода.
   Внешние интерфейсы (`io.Reader`, `error`, `http.Handler`) перечисляются явно в записи
   извлекателя в `.semaps` (`implements: [...]`), по полному имени, без масок: полный перебор
   пар с библиотекой — шум и время.

## Отвергнуто

- **Отдельный вид `embeds`.** Честнее `extends` для Go, но проваливает условие 4: на пустой
  карте никто не рисует «встраивание», рисуют «состоит из». Он же не дал бы реализовать одну
  схему на C# и Go: в C# встраивания нет.
- **`native` вместо `kind`** (сверка по языковым видам). Одна схема на двух языках перестаёт
  сходиться сама с собой.
- **Сопоставление в коде извлекателя без документа.** Решение, которое нельзя прочитать и
  оспорить, не решение; четвёртый язык переоткрыл бы те же споры.
- **`native` на связи реестра.** У одной связи может быть несколько реализаций на разных
  языках с разным `native`; его место — запись основания (ADR_20260927-2).

## Следствия

- `EXTRACTOR.md` §2.2: `kind` — закрытый список, поле `native`, ссылка на таблицы в
  `docs/extractors/`; фраза про «встраивание по смыслу наследования» уходит.
- `schemas/extractor-facts.schema.json`: необязательное `native` у ребра.
- `docs/extractors/csharp.md`, `typescript.md` получают таблицу сопоставления рёбер в той же
  форме (C#: `extends`/`class`, `implements`/`interface`, `holds`/`field`|`property`|`event`…).
- `docs/extractors/go.md` из черновика становится нормативным вместе с извлекателем.
