# ADR_20260928-3_host — Вызовы и методы живут в живом графе, в git и реестр не попадают

Статус: **принято**. Заменяет §6 [`ADR_20260928`](ADR_20260928_host_live-code-graph.md)
(«Вызовы не хранятся… только ответом на запрос»): там решение человека было записано неверно.
Остальное в ADR_20260928 остаётся в силе.

## Контекст

Решение человека было: вызовы **не хранить** — их на порядки больше, чем структурных связей, и
они меняются с каждой правкой. Имелось в виду хранение в git и в реестре. В ADR_20260928 §6 это
записано как «в фактах вызовов не будет, только ответ на запрос» — шире, чем было сказано.

Опыт с агентами ([`PLAN_20260928-5`](../plans/PLAN_20260928-5_host_graph-answers-for-agents.md))
показал цену: у статической фабрики, главной точки сборки конвейера, в графе ноль связей; как
данные идут через систему, агент выяснял поиском по тексту.

## Решение

1. **Два слоя данных, граница — git.**

   | | Реестр (хранимый) | Живой граф |
   |---|---|---|
   | типы, интерфейсы, модули | да | да |
   | наследование, реализация, вложенность, хранение, использование | да | да |
   | место в коде (строки) | нет | да |
   | **методы** | **нет** | да |
   | **вызовы, создание объектов** | **нет** | да |

2. **Методы — узлы графа.** Граф вызовов — настоящий: метод вызывает метод. Рекурсия, цепочки,
   достижимость — обычный обход.
3. **Извлекатель печатает методы и вызовы в фактах.** Факты лежат во временной папке и в памяти
   хоста (ADR_20260928 §1) — в рабочую папку и в git не попадают.
4. **Сверка методы и вызовы не видит.** Из символа-метода сущность не создаётся, из ребра
   вызова связь не создаётся, и `missing` по ним не ставится. Реестр после сверки фактов с
   методами и вызовами совпадает байт в байт с реестром после сверки тех же фактов без них.
5. **Вызов через интерфейс** записывается как есть — на метод интерфейса. Связь «метод
   реализует / переопределяет метод» печатается отдельно, по ней граф доходит до настоящих целей.
6. **Подъём на уровень типов.** Граф умеет по запросу свернуть вызовы методов в связи типов:
   вопрос «кто вызывает класс X» задаётся про тип.
7. **Страница графа по умолчанию показывает типы.** Методы — по запросу.

## Отвергнуто

- **Ребро вызова между типами, метод — в подписи.** Помещается в нынешнюю схему, но граф
  вызовов только изображает: обхода по методам нет.
- **Вызовы только ответом на запрос к извлекателю.** Прежняя запись §6. Требует живого процесса
  извлекателя и не даёт обхода.
- **Методы в реестре со скрытой видимостью.** Тот же шум в git, которого решение избегает.
