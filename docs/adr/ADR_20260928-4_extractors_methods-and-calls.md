# ADR_20260928-4_extractors — Методы и вызовы в фактах

Статус: **принято**. Стоит на
[`ADR_20260928-3`](ADR_20260928-3_host_calls-live-in-the-graph.md). Дополняет словари
[`EXTRACTOR.md`](../EXTRACTOR.md) §2.2–2.3 и форму идентификаторов
[`ADR_20260923-5`](ADR_20260923-5_extractors_symbol-ids.md).

## Решение

### 1. Вид символа `method`

Новое значение `kind`. Сюда: методы, конструкторы, свойства и индексаторы (как пара доступа —
один символ), операторы. `nativeKind` — слово языка: `method`, `constructor`, `property`,
`indexer`, `operator`, `accessor`.

Лямбды и локальные функции символами не становятся: их вызовы приписываются методу, в теле
которого они написаны.

Свободная функция верхнего уровня остаётся `function`, как была.

### 2. Идентификатор метода

`<id типа>.<имя>(<типы параметров через запятую>)` — без пробелов, типы параметров как в коде,
обобщённые параметры метода — арностью после имени: `` Map`1(T,int) ``. Конструктор — имя
`.ctor`, статический — `.cctor`. Свойство — без скобок. Перегрузки различаются списком
параметров. Идентификатор устойчив к перестановке методов в файле.

### 3. Виды рёбер

| Вид | От → к | Что |
|---|---|---|
| `calls` | метод → метод | вызов метода, чтение или запись свойства |
| `constructs` | метод → тип | `new T(...)`; если конструктор — символ вывода, ещё и `calls` на него |
| `overrides` | метод → метод | переопределение виртуального метода базового класса |
| `implements` | метод → метод | реализация метода интерфейса (тот же вид, что у типов) |
| `contains` | тип → метод | принадлежность метода типу (тот же вид, что у типов) |

Несколько вызовов одной цели из одного метода — **одно ребро**; места — списком строк
`lines` у ребра, по возрастанию. `line` — первая из них.

Ребро на символ вне вывода не печатается, как и прежде.

### 4. Что видит сверка

Ничего из этого. Символы вида `method`, рёбра `calls`, `constructs`, `overrides`, и рёбра
`contains` и `implements`, у которых хотя бы один конец — метод, сверка пропускает до всякой
обработки. Правило — по виду, а не по списку извлекателей.

### 5. Включение

Аргумент извлекателя `--edges` получает значение `calls`: с ним печатаются методы и все рёбра
этого ADR. Без него вывод прежний, байт в байт. В `.semaps` — то же слово в `edges`.

`edgeKinds` в заголовке фактов называет `calls`, когда они напечатаны.

### 6. Порядок

Сортировка §3 `EXTRACTOR.md` не меняется: символы по `id`, рёбра по
`(from, to, kind, via.member, via.path)`. `lines` в ключ не входит.

## Отвергнуто

- **Отдельный документ фактов для вызовов.** Два вывода, два прогона, два места, где может
  разойтись список символов.
- **Одно ребро на каждое место вызова.** Объём без пользы: агенту нужен факт вызова и строки.
- **Лямбды как символы.** Имени нет, идентификатор неустойчив.

## Последствия

- `schemas/extractor-facts.schema.json`, `core/facts.go`, `docs/EXTRACTOR.md`,
  `docs/extractors/<язык>.md` меняются вместе с кодом.
- `members` типа остаётся как есть: это форма для шаблона содержимого блока
  ([`CONTRACT.md`](../CONTRACT.md) §3), а не граф.
