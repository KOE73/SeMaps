# ADR_20260928_host — Живой граф кода: производный слой рядом с моделью

Статус: **принято**. Дополняет [`ADR_20260925`](ADR_20260925_host_model-owned-by-host.md): модель
остаётся как есть, рядом с ней в хосте появляется второй слой. Не меняет
[`ADR_20260828`](ADR_20260828_diagrams_model-contract-v2.md): реестр и виды — авторский документ.

## Контекст

SeMaps хранит архитектуру **как задумано**: сущности, связи, контейнеры, виды с осью. Это
документ: его пишут человек и агент, он лежит в git, его читают и правят в обе стороны.

Рядом есть инструменты другого рода (пример —
[CodeGraph](https://github.com/codegraph-ai/CodeGraph)): полный граф кода, построенный
автоматически, живой, с запросами для агентов. Он отвечает на вопрос «как есть» и экономит агенту
чтение файлов: вместо поиска по тексту и чтения файлов целиком — один запрос и короткий ответ.

Данные для такого графа у нас уже есть. Извлекатель печатает символы и рёбра
([`EXTRACTOR.md`](../EXTRACTOR.md) §2), хост складывает каждый прогон в
`%TEMP%/semaps-runs/<проект>/<прогон>/facts.json` (`host/runs.go`). Сверка берёт из фактов часть и
пишет в реестр; остальное (строка объявления, видимость символа, общий `kind`, символы вне
`sources.include`) в реестр не попадает.

## Решение

### 1. Два слоя, разной природы

| | Модель | Живой граф |
|---|---|---|
| Источник | человек и агент | только код, через извлекатели |
| Хранение | файлы контракта, git | память хоста и временная папка, вне git |
| Правка | операции, журнал, «Сохранить» | не правится, пересобирается |
| Вопрос | как задумано | как есть |

Граф — **производные данные**. Потерять его не страшно: он собирается заново из кода.

### 2. Три части

```
Модель (core.Model)      Поставщик графа        Факты кода
авторская, в git     →   соединяет и отдаёт  ←  последние факты извлекателей
```

- Поставщик живёт в хосте, рядом с `modelService`, но **не внутри** `core.Model`: у графа нет
  журнала, авторов и сохранения.
- Модель поставщик только читает.
- Соединение фактов с моделью — по полю `symbol` сущности
  ([`CONTRACT.md`](../CONTRACT.md) §3).

### 3. Один граф со всеми данными, объём — параметрами запроса

Поставщик отдаёт **один смысловой формат**: узлы, рёбра, признаки (вид символа, видимость,
место в коде, сущность модели, контейнер, статус). Потребителей несколько — страница графа в
редакторе и агенты через MCP, — и им нужен один и тот же граф.

Что именно отдать, задаёт запрос: уровень (типы / с функциями), область (проект, контейнер,
окрестность узла), виды рёбер, набор полей. Отрисовщик просит весь проект без членов, агент —
окрестность одного узла с местами в коде.

Представление под отрисовщик (координаты, цвета, массивы для WebGL) — дело браузера. Хост о нём
не знает.

### 4. Три рода узлов

Соединение даёт их само:

- **в коде и в модели** — символ, у которого есть сущность;
- **только в коде** — символ без сущности (вне `sources.include`, придержанный сверкой, не
  сверенный);
- **только в модели** — сущность без символа в фактах (`authored`, `planned`, `missing`).

### 5. Место в коде — в графе, не в реестре

Агенту мало знать, что с чем связано: ему надо прочитать ровно нужный кусок. Граф несёт файл и
строки символа. В реестр строки не пишутся: они меняются с каждой правкой кода и дали бы шум в
git.

### 6. Вызовы не хранятся

Рёбер «кто кого вызывает» в фактах нет ([`EXTRACTOR.md`](../EXTRACTOR.md) §2.2a) и в хранимых
фактах не будет: их на порядки больше, они меняются с каждой правкой, это поток управления, а не
структура. Если понадобятся — только ответом на запрос, без хранения
([`IDEA_20260928-2`](../ideas/IDEA_20260928-2_extractors_calls-on-demand.md)).

### 7. Источник — свои извлекатели

Граф строится на фактах своих извлекателей. Серверы языков (LSP) как источник не используются.

### 8. Другие графы — новые источники за тем же поставщиком

Граф типов из фактов — первый. Граф файлов, вызовы по запросу, «что меняется вместе» из истории
git добавляются как источники; потребители при этом не меняются.

### 9. Оптимизация — по замеру

Индексы и кэши в модели и в графе заводятся, когда замер показал, что и где тормозит, и это уже
не устраивает. Не раньше.

## Отвергнуто

- **Хранить граф в git или в реестре.** Производные данные; диф шумел бы движением, которого
  никто не делал.
- **Класть строки и видимость в реестр**, чтобы граф читал только его. Та же причина; и символы
  вне `sources.include` в реестр не попадают вовсе.
- **Соединять факты с моделью в браузере.** Быстрее начать, но агенты через MCP не получают
  ничего, а логику соединения пришлось бы повторить в Go.
- **Свой формат под каждый отрисовщик.** Отрисовщик — не единственный потребитель; лишнее
  отсекается параметрами запроса.
- **Чужой LSP как источник.** Серверы языков C# и TypeScript стоят на тех же Roslyn и компиляторе
  TypeScript, что и наши извлекатели; протокол говорит позициями, а не символами; сервер надо
  ставить под каждый язык.
- **Свой LSP-сервер.** Это канал доставки карты в IDE, а не источник данных; агентов обслуживает
  MCP. Не отвергнуто навсегда.
- **Встроенная база (RocksDB и подобное), эмбеддинги, векторный поиск.** На нынешних объёмах
  (405 символов, 1361 ребро на NeuroModFlowNet.ONNX) хватает памяти процесса; смысл у нас задаётся
  явно, а не выводится.
- **Переписать хост на C# из-за объёма данных.** Объём мал для любого языка. Довод
  [`ADR_20260925`](ADR_20260925_host_model-owned-by-host.md) остаётся: один маленький exe без
  рантайма, Roslyn — в извлекателе.
