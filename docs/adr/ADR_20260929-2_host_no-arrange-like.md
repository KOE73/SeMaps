# ADR_20260929-2_host — Инструмента `arrange_like` нет: у агента глаза и точные руки

Статус: **принято**. Убирает `arrange_like` из плана
[`PLAN_20260925-2_host_view-tools`](../plans/PLAN_20260925-2_host_view-tools.md) §4 (план остаётся как
история; ADR не менялся — инструмент решал план, не ADR). Инструменты правки вида — в
[`API.md`](../API.md) §6, порядок работы — в [`LAYOUT.md`](../LAYOUT.md).

## Контекст

`arrange_like` раскладывал целевые зоны «как эталонную»: пары узлов находил по роли в
наследовании (база семейства, остальные от неё) и по «различающим словам» имён (`fp16`, `u8`,
`nhwc`, слова, общие для всей зоны, отбрасывались). Он появился под один живой проект — зона с
семью подзонами-семействами — и подходит ровно к такой форме: одно семейство типов с вариантами
в именах. Для любой другой раскладки пары выходят угаданными, а угадывание намерения по словам
имён — как раз то, чего в остальной системе нет
([`ADR_20260928-5`](ADR_20260928-5_extractors_only-unambiguous-facts.md): только однозначное).

## Решение

1. **`arrange_like` удалён целиком**: `core/arrange.go`, инструмент MCP (`host/mcp.go`, список
   `projectTool` в `host/mcp_proxy.go`), тесты, упоминания в живых документах.
2. **«Сделай так же» — суждение агента.** Что чему соответствует, решает он сам; инструменты дают
   ему глаза (`get_view`: зоны, узлы, абсолютные прямоугольники, видимые линии) и точные руки
   (`move_elements`, `resize_elements`, `set_zone`, `add_zone`, `fit_zone`, `align_elements`,
   каждый шаг — одна партия). Порядок: посмотреть, решить, показать план человеку, применить
   шагами, снова посмотреть.
3. Новых «умных» инструментов раскладки по образцу нет, пока нет формы, которая верна не для
   одного проекта.

## Что отвергнуто

- Оставить `arrange_like` «для семейств»: он молча делает вид, что умеет остальное; агент, поверив,
  получит неверные пары и не заметит.
- Заменить сопоставление по словам сопоставлением по чему-то ещё (позиции, размеры): та же
  эвристика под другой вкус.
