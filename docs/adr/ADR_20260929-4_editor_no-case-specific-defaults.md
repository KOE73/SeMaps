# ADR_20260929-4_editor — Никаких выборов под один проект: данные вместо констант

Статус: **принято**. Продолжает [`ADR_20260928-5`](ADR_20260928-5_extractors_only-unambiguous-facts.md)
и [`ADR_20260929-2_host_no-arrange-like`](ADR_20260929-2_host_no-arrange-like.md): то, что верно
для одного проекта или одного скриншота, не зашивается в код.

## Контекст

Аудит кода (`core/`, `host/`, `editor/src`, `extractors/`) нашёл выборы, подогнанные под один
проект: набор видов связей и типов, включённых в графе по умолчанию; «самый вложенный контейнер —
тот, где меньше всего членов»; словарь осей в диалоге; стили `component`/`service`/`concept` для
нового узла; примеры имён из одного проекта в текстах для агентов; правило `kindFamily`, склеивавшее
`record-struct` со `struct`.

## Решение

1. **Фильтры графа по умолчанию — данные**: `graph-filters.json` рядом с `styles.json`, файл
   рабочего пространства побеждает; вид или тип, которого нет в данных графа, пропускается.
2. **Вложенность контейнеров — та, что отдаёт хост из `containers.json`**; догадка «меньше членов =
   глубже» удалена, при неоднозначности узел не относится ни к одному контейнеру.
3. **Стиль нового узла — один идентификатор из данных** (`default.node` в `styles.json`); стили
   `LEGACY_TYPE_STYLES` удалены.
4. **Оси диалога — из рабочего пространства**, свободный ввод как запасной путь.
5. **`record-struct` — самостоятельный вид**: `adopt` в `core/sync` сравнивает виды как есть, без
   схлопывания по последнему `-`.
6. **Числа раскладки графа — в одном именованном блоке** (`GRAPH_TUNING`); пропорция раскладки
   берётся из размера холста.
7. **Примеры в текстах для агентов — нейтральные** (`Billing.InvoiceService`), без имён проекта.

## Что отвергнуто

- Оставить значения по умолчанию «пока всем подходит»: они подходят одному проекту, остальные
  получают чужой вкус молча.
- Расширять эвристики списками слов: тот же вкус, шире.
