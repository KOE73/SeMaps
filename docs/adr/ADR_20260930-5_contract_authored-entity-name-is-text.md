# ADR_20260930-5_contract — Имя нарисованной сущности — текст

Статус: **принято**. Заменяет в [`ADR_20260831_diagrams_text-provenance-and-view-axes`](ADR_20260831_diagrams_text-provenance-and-view-axes.md)
и [`ADR_20260927-6`](ADR_20260927-6_contract_v5-kinds-and-containers.md) правило «имя сущности одно, живёт в `entities.json`
и не переводится» — для сущностей `origin: authored`. Для сущностей из кода правило остаётся. `contractVersion` остаётся `5`.

## Контекст

Слова владельца: **«id фиксирован; на экране — id и осмысленное имя, и имя может меняться»**.

Сегодня у сущности одно поле `name` в `entities.json`, оно «не переводится». Для класса из кода это верно: имя —
то, что написано в коде, и переводить нечего. Для нарисованной сущности — группы, контейнера, компонента, актора —
имя это подпись на схеме, слова человека: «Хранение», «Разбор», «Владелец схемы». У проекта два языка — у подписи
две формы, и она меняется, как меняется схема.

Следствия сегодняшнего правила видны в данных. Контейнер стал сущностью (`ADR_20260927-6`), и его подпись — `name` в
`entities.json`; английское имя зоны, у которой был текст `z_x`/`c_x` на двух языках, при миграции контракта 3
оставалось одно, второе попадало в отчёт «имена на других языках потеряны». Переименовать «Хранение» можно только
правкой `entities.json`, мимо панели «Изменения» и мимо провенанса текстов.

## Решение

1. **У сущности `origin: authored` имя — текст.** Переводимое поле `name` в `text.<lang>.json` под ключом `e_…`
   этой сущности, значение — объект с провенансом, как у остальных текстов (`v`, `at`, `origin`, `from`, `fromHash`).
   Он же — единственное место имени: в `entities.json` у такой сущности `name` **отсутствует**. Не «пусто» и не
   «кэш» — ключа нет; загрузчик и `semaps check` называют его как старую форму, а правило записи отказывает
   пакету, который его несёт.
2. **Запасной показ:** имя в основном языке проекта (первый в `languages` `project.json`), иначе в любом другом
   языке проекта (в порядке `languages`), иначе `id` сущности. Отсутствие имени в одном языке — не дыра, пока оно есть
   в другом: фолбэк здесь отдельное решение, и правило §7.4 «фолбэка нет» для имён нарисованных сущностей не действует.
3. **У сущности из кода** (`origin: code` и сущность без `origin`) имя остаётся именем из кода в `entities.json`,
   не переводится, текстом `name` не заводится: правило записи отказывает `name` под ключом `e_` такой сущности.
   Поле `title` под ключом `e_` не бывает ни у кого.
4. **Правила записи (`core/rules.go`, одни на всех писателей):**
   - новая нарисованная сущность (или сущность, ставшая `authored`) получает `name` хотя бы в одном языке **в том же
     пакете** операций, что и она сама — порядок операций в пакете значения не имеет;
   - текст `name` под `e_`-ключом требует существующей нарисованной сущности; пустое имя, как и любой пустой текст,
     не пишется;
   - id сущности по-прежнему не меняется никогда.
5. **Переименование — правка текста.** Она видна в панели «Изменения» как правка текста под `id` сущности, сохраняется в
   `text.<lang>.json` и ничего не меняет в `entities.json`. MCP: `set_text` c `field: name`; `add_entity` и
   `add_container` пишут имя как текст основного языка проекта (или `lang`).
6. **`semaps check`:** недостача имени нарисованной сущности — когда его нет **ни в одном** языке проекта.
7. **Редактор:** инспектор показывает ID (только чтение, копируется) рядом с именем у любой сущности; поле имени
   правится у нарисованной и только читается у кодовой.
8. **Миграция.** `name` нарисованной сущности переходит в текст основного языка (`origin: authored`, `at` — момент
   миграции); имена зон и контейнеров контракта 3 — в тексты **обоих** языков с их провенансом; пункт отчёта «имена на
   других языках потеряны» исчез.

## Отвергнуто

- **Имя остаётся в `entities.json`, а переводы — в текстах.** Два источника одного имени, и вопрос «какое главное» сразу,
  а это то, что §7.4 запрещает как «фолбэк на базу».
- **`name` в `entities.json` как запасное значение для нарисованной сущности.** Расходится с текстом при первой же
  правке; а по слову владельца имя может меняться — значит, писать его в двух местах и держать их равными.
- **Переводимое имя и у сущности из кода.** Переименование типа — дело кода и сверки (`ADR_20260923-9`); имя в
  коде языко-независимо.
- **Имя, из которого выводится `id`.** `id` фиксирован: на него ссылаются связи, виды, тексты.
- **Требовать имя в каждом языке проекта.** Вид и тип связи в каждом языке имя обязаны иметь; имя блока на схеме с
  двумя языками, где второй ещё не написан, не должно делать модель нечитаемой — показывается имя другого языка.
