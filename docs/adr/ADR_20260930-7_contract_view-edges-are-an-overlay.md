# ADR_20260930-7_contract — `edges` вида — перекрытие реестра, а не его копия

Статус: **принято**. Заменяет в [`ADR_20260903`](ADR_20260903_diagrams_content-templates-and-edge-routing.md) и в
`CONTRACT.md` §8.5 правило «массив `edges` вида переопределяет реестр целиком». Остальное в §8.5 (правило обоих
концов, умолчание, `relations.except`) остаётся. `contractVersion` остаётся `5`.

## Контекст

Слова владельца: **«делай линии как блоки»**.

Размещение блока — ссылка на сущность плюс только своё (координаты, `override`, `styleId`, `template`,
`collapsed`); имя, вид и члены каждый раз берутся из реестра. Линия была устроена иначе: собственный `edges` вида
хранил `id`, `from`, `to`, `type` каждой связи и заменял реестр целиком. Форму или цвет одной линии записать было
негде, кроме этого списка, поэтому редактор при первой же правке одной линии записывал в вид все связи, которые
показывал.

Что из этого вышло в живом проекте: у вида с 20 блоками в `edges` оказались 1704 связи всего проекта (рисуется около
30). Такой вид оторван от реестра: новая связь из кода на нём не появляется, исчезнувшая продолжает рисоваться,
смена типа не видна, `relations.except` и умолчание видимости типа не действуют. Ответ `get_view` на него — четверть
миллиона символов.

## Решение

1. **Запись `edges` — ссылка на связь реестра и только своё:** `{ "id", "styleId"?, "override"?, "routing"? }`.
   Полей `from`, `to`, `type` в записи нет: концы и тип — из `relations.json`. Запись без единого своего поля не
   пишется; вид без таких записей ключа `edges` не имеет. `id` в списке не повторяется и обязан быть id связи реестра.
2. **Что видно, решает одно правило** §8.5 — оба конца на виде, умолчание (тип в словаре, иначе
   `relations.default` вида), `relations.except`. Наличие записи в `edges` на видимость не влияет. Значения
   «`edges: []` — рёбер нет» больше нет: вид без линий — это `relations.default: "hidden"`.
3. **Линии только одного вида не бывает.** Линия, нарисованная человеком, — связь реестра `origin: authored`,
   заведённая тем же пакетом операций, что и её оформление, как нарисованный блок приносит свою сущность.
4. **Скрыть или показать линию на виде** — правка `relations.except`, у всех писателей. «Удалить линию» в редакторе
   для связи из кода — то же скрытие: связь принадлежит коду.
5. **Правила записи (`core/rules.go`, одни на всех):** запись `edges` с `from`, `to` или `type` отклоняется; запись
   с `id`, которого нет среди связей, отклоняется; запись без своего поля отклоняется; `override` проверяется по
   таблице линии (§11.6), как раньше.
6. **`semaps check` и загрузчик** называют запись с `from`/`to`/`type` старой формой и отсылают к миграции.
7. **Миграция сохраняет картинку.** Для вида с собственным `edges` старой формы:
   - запись, чьего `id` нет в реестре, становится связью `origin: authored` (её `from`, `to`, `type`), если оба
     конца — сущности реестра; иначе отбрасывается и называется в отчёте;
   - `relations.except` пересчитывается так, чтобы среди связей с обоими концами на виде видимыми остались ровно
     те, что были в списке;
   - в `edges` остаются только записи со своим `styleId`, `override` или `routing`, без `from`/`to`/`type`;
     опустевший `edges` убирается.

## Отвергнуто

- **Оставить полный список и чинить только редактор** (не писать лишнего). Оторванность остаётся свойством формы:
  любой вид со своим `edges` перестаёт следовать коду, а форму одной линии иначе хранить негде.
- **Отдельный ключ для оформления линий рядом со старым `edges`.** Два способа сказать «что видно» в одном файле.
- **Оставить `from`/`to`/`type` в записи «для читаемости».** Копия, которая расходится с реестром при первой же
  сверке; у размещения блока имени и вида тоже нет.
- **Линии, существующие только на виде.** Связь, которой нет в реестре, не видна ни графу, ни другим видам, ни
  агенту; нарисованный блок такой свободы тоже не имеет.
