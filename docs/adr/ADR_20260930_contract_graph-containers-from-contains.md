# ADR_20260930_contract — Контейнер в графе — из связей `contains`, других источников нет

Статус: **принято**. Заменяет п. 2 решения
[`ADR_20260929-4`](ADR_20260929-4_editor_no-case-specific-defaults.md) («вложенность контейнеров —
та, что отдаёт хост из `containers.json`»): `containers.json` больше нет
([`ADR_20260927-6`](ADR_20260927-6_contract_v5-kinds-and-containers.md)), а остальные пункты того
ADR остаются в силе.

## Контекст

1. **Граф кода группировал и фильтровал по `containers.json`.** Принадлежность узла контейнеру
   вычислялась там же: `overrides` → `match.name` → `match.nameRegex` → `match.path` (длиннейший
   префикс) → «сосед по файлу», а один узел мог попасть в несколько контейнеров. Всё это — догадки
   по именам и путям; граф кода ([`ADR_20260928_host_live-code-graph`](ADR_20260928_host_live-code-graph.md))
   при этом обещает только то, что следует из языка
   ([`ADR_20260928-5`](ADR_20260928-5_extractors_only-unambiguous-facts.md)).
2. **v5 убрала файл**: контейнер — сущность типа с `container: true` в словаре, принадлежность в
   реестре — связь `contains`, вложенность на виде — `parent` размещения. Читателям графа, фильтра и
   раскладки нужно новое основание — и оно уже есть: извлекатели приносят контейнеры кода
   (`namespace`, `assembly`, `package`, `module`, `file`) узлами со связями `contains`, а
   человек записывает свои так же, авторской связью.
3. **Неоднозначность была решена догадкой.** «Самый вложенный — тот, где меньше членов» уже
   удалена ([`ADR_20260929-4`](ADR_20260929-4_editor_no-case-specific-defaults.md)); правило «при
   неоднозначности узел не относится ни к одному» нужно держать и дальше, теперь на данных
   `contains`.

## Решение

1. **Контейнер графа — узел, чей тип контейнер по словарю** (`container: true` в `kinds.json`).
   Тип узла — `kind` его сущности; у узла, которого в реестре ещё нет, — `nativeKind` символа,
   то есть то, что сверка запишет как `kind`. Узел неизвестного словарю типа контейнером не
   считается.
2. **Члены контейнера — узлы, которые он содержит:** ребро `contains` **из** контейнера. Откуда ребро —
   от извлекателя или из реестра, где его записал человек, — всё равно. Других источников нет: ни
   правил по имени и пути, ни соседа по файлу, ни геометрии видов.
3. **Контейнер узла — самый внутренний из содержащих его**: из кандидатов исключается тот, в
   котором лежит другой кандидат. Остался ровно один — он и есть контейнер узла
   (`GraphNode.Containers`, не больше одного элемента; список — чтобы читатель держал одну форму
   «какие контейнеры»). Остались два несвязанных — **узел не относится ни к одному**: граф не
   выбирает. Цикл `contains` обрывает обход и не зацикливает его.
4. **Вложенность контейнеров в графе** (`GET /api/graph/{project}/groups`, `containers[].parent`) —
   контейнер, который содержит контейнер. Группировка «по контейнерам» и уровни вложенности берутся
   оттуда; редактор ничего не достраивает и не выбирает сам.
5. **Фильтр `container`** (HTTP и `get_graph`) принимает узел-контейнер, по id или по имени, как `around`, и
   оставляет его и всё внутри на любой глубине. Узел, который не контейнер, — ошибка, а не
   пустой ответ; неоднозначное имя — `409` со списком кандидатов.
6. **Оси видов** (`groups.axes`) — размещения: контейнер сущности на виде оси — `parent` её размещения;
   это принадлежность **на виде**, и она не подменяет `contains`.
7. Ни одно правило не переносится из старых `match`/`overrides`: `semaps migrate` печатает их в отчёте,
   решает человек — превратить ли их в связи `contains`.

## Отвергнуто

- **Перенести `match` в новую форму.** Правило по имени или пути — та же догадка, только в файле
  другого вида. Если понадобится, это правило
  сверки, порождающее `contains` и оставляющее след в реестре, отдельным решением.
- **«Сосед по файлу» и подобные запасные ходы.** Они и делали принадлежность подсказкой, в которую
  нельзя верить.
- **При неоднозначности брать первый, самый маленький или самый большой контейнер.** Любой выбор — вкус
  одного проекта; узел без контейнера честно показывает, что данные не решают.
- **Выводить принадлежность из вложенности на виде.** Вид — выборка человека на своей оси; один и тот же
  блок вправе лежать в разных рамках разных видов.

## Следствия

- `core/graph_containers.go`: `assignContainers`, `FilterContainer`, `GraphContainers`;
  `core/containers.go` (`match`, `overrides`, `ResolveContainers`) удалён.
- `GraphNode.container` (узел сам контейнер) и `containers` (его контейнер); `groups` — `containers` с
  `parent` и `axes[].containers` с размещениями.
- Редактор графа: `containerOf`, `containerPath` (цепочка контейнеров для фильтра), группировка и
  раскладка без собственных догадок.
- `CONTRACT.md` §4, §6; `API.md` §5.
