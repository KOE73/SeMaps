# Общие стили в рабочей модели хоста

Статус: принято.

## Решение

`WorkspaceModel` владеет стилями и координирует модели проектов. UI и MCP изменяют определения
через общий контракт операций; файл `styles.json` записывается только при Save стилей.
Принятая операция публикуется всем редакторам рабочего пространства через SSE.

Для атомарного переименования между проектами хост сохраняет один заменяемый checkpoint
`.semaps/work/workspace.json`, содержащий определения, ссылки базовых стилей словаря,
авторство и журналы операций проектов. Старые отдельные JSONL-журналы импортируются при
загрузке проекта; checkpoint становится авторитетным. Формат опубликованных файлов
рабочего пространства остаётся контрактом 5.

Save/Discard стилей включают переименованные ссылки на всех видах, но не сохраняют/не отменяют
посторонние изменения проектов. Для этого переименование хранится как операция изменения
ссылки, а не замена размещения целиком. Save проекта требует предварительного Save новых
определений и переименований. UI подписывает области действий в панели изменений.

## Почему

Локальная библиотека каждого клиента и отдельная запись `styles.json` не доставляли новый
стиль другим редакторам. Ссылка через MCP могла обновиться раньше доступного определения.
Один checkpoint связывает определения и ссылки; согласованный ответ вида включает его
stylesheet. Два независимых журнала не обеспечивали бы атомарность переименования между
проектами при перезапуске.

Сохранять весь проект при Save стилей отвергнуто: это незаметно фиксировало бы чужую
незавершённую геометрию. Удалять используемый стиль без замены отвергнуто: запасные цвета
скрывают потерю оформления. Используемые стили требуют явной совместимой замены.

Цена решения: checkpoint переписывается при принятом изменении; это больше записи, чем
append-only журнал. Проверки покрывают восстановление, закрытые проекты, сохранение и
откат ссылок с сохранением независимой геометрии, два SSE-клиента и реальные MCP-вызовы.
