# ADR_20261007_contract — Файл библиотеки и независимая принадлежность символа

Статус: **принято**.

Дополняет ADR_20260927-4: старый nativeKind external поддерживается, но для полного
извлечения C# библиотеки внешний символ сохраняет настоящий nativeKind и отдельный library.

## Решение

1. В одном проекте остаются общие ID и единые логические реестры. Собственные объекты —
   entities.json, собственные связи — relations.json, свои→внешние — relations.external.json.
2. external/<library-file>.json содержит метаданные library, entities и relations.
   Внешняя связь принадлежит библиотеке from, включая связи в другую библиотеку.
3. library — стабильное имя сборки с public key token (без версии). Версия — метаданные
   снимка. ExternalTypeId = [library]::TypeId. Собственные TypeId не меняются.
4. Извлечение границы, окружения типа и целой сборки использует один формат. Факты
   объявляют, какие внешние символы раскрыты и какие сборки покрыты целиком.
   Неизвлечённая часть не считается исчезнувшей. Заглушка конца связи не затирает
   ранее раскрытые члены.
5. Типы и связи из DLL извлекаются по метаданным. Вызовы из тел методов требуют
   отдельного чтения IL либо исходников и не объявляются покрытыми этим режимом.

## Следствия

Загрузчик и Save объединяют и разделяют реестры; API и редактор работают с общим реестром.
Разделение файлов ограничивает диффы, но не устраняет стоимость полного графа в памяти.
Старые рабочие пространства без external файлов продолжают читаться.
