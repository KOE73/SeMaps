# Независимые модификаторы оформления и правила их применения

Статус: принято.

## Причина

Тип и принадлежность библиотеке — независимые признаки. Варианты полного стиля для каждой
пары размножают определения: при K типах и L библиотеках приходится поддерживать до K × L
стилей. Изменение общего шрифта или палитры требует согласовать множество копий. Новая
сущность может получить стиль типа, но её палитру приходится назначать отдельно.

## Решение

Дополнить типовые стили переиспользуемыми разреженными модификаторами и независимыми правилами
выбора. Тогда K базовых стилей и L палитр выражают те же сочетания без копирования полных
определений. Один модификатор может иметь заплаты для нескольких семейств.

Последовательность слоёв фиксирована: базовый/явный стиль, автоматические модификаторы,
ручные модификаторы, локальное перекрытие. Порядок правил явный и воспроизводимый; объяснение
показывает, какой слой задал каждое свойство. Результат вычисляется общей рабочей моделью
хоста и не превращается в назначения на каждом размещении.

Правило хранит версионированное декларативное дерево условий. Каталог полей и операций
общий для проверки, MCP и конструктора UI. Новое поле добавляется вместе с поставщиком
фактов, без нового языка клиента. Принадлежность берётся из реестра; визуальная группировка
на схеме её не подменяет. Отсутствующий факт остаётся неизвестным при отрицании, чтобы
неизвестное происхождение не становилось доказательством принадлежности другой группе.

Модификаторы входят в существующую панель стилей, правила получают отдельную панель.
Определения используют общие авторство, revision и Save/Discard библиотеки; назначения и
исключения остаются состоянием проекта. UI и MCP используют одинаковые операции хоста.

## Границы и альтернативы

Наследование полного стиля через basedOn сохраняется для вариантов типа, но один родитель
не выражает независимые палитры и признаки без размножения сочетаний. Произвольные скрипты
условий отвергнуты: их сложнее валидировать, расширять и объяснять одинаково всем клиентам.
Условия не получают неявную специфичность как CSS: явный порядок проще воспроизвести.

Модификатор меняет оформление, сохраняя контур, шаблон, тип и форму наконечника базового
стиля. Структурные и геометрические изменения остаются отдельными действиями. Alpha цвета
поддерживается обычной прозрачностью при отрисовке; смешивание с цветом предыдущего слоя
не вводится, поскольку делает результат зависимым от промежуточных цветовых преобразований.

Цена решения — необходимость видеть каскад при конфликте и проверять ссылки во всём
workspace. Предпросмотр, происхождение свойств, строгая проверка и ручные исключения входят
в объём решения. Текущий формат и операции описываются в CONTRACT §11.7 и API §3.4c.
