# Необходимость отдельного skill для SeMaps не выявлена

Статус: принято.

## Решение

**Необходимость и обоснованность отдельного skill для текущей MCP-ориентированной
системы SeMaps не выявлены.** Не вводить `semaps-architecture` как обязательный слой
работы с SeMaps и не обещать повышение качества или экономию ресурсов от его применения.

Роль SeMaps в разработке, двунаправленность «авторская архитектура → код» и
«код → архитектура», возможности и правила применения инструментов должны быть
доступны через сам MCP. Поддерживать второй экземпляр этих знаний в skill без
показанной дополнительной пользы не обосновано.

Подготовленный skill 0.1.1 остаётся экспериментальным артефактом с лицензией MIT.
Это решение не требует удаления файлов или публикации пакета. Будущий skill для
специализированного сценария требует собственного обоснования и проверки.

## Основания

SeMaps используется через MCP в ходе обычной разработки. MCP уже сообщает агенту,
что система представляет собой, какие сведения доступны из кода, как работать
с авторской картой и обновлять сведения. Это включает зависимости, вызовы,
наследование, структуру типов, свежесть экстракции и различие между живым графом,
согласованием реестра и сохранением. Актуальные правила принадлежат
[API.md](../API.md) и [ADOPTING.md](../ADOPTING.md), а не этому ADR.

Два сравнительных эксперимента не выявили необходимости дополнительного skill.
Со skill агенты иногда выбирали дополнительные проверки, но не получили
однозначного преимущества в конечном результате и не сократили число вызовов.

## Измерения: явная архитектурная задача

Эксперимент `20261012-2da23003`: проверить архитектуру Model по
`overview/v_internals` и коду, написать интеграционный тест жизненного цикла,
создать отдельное представление фактического жизненного цикла.

Два независимых агента без истории получили одинаковое задание, исходники, карту
и настоящий MCP; одному дополнительно явно предоставлен skill 0.1.1. У каждого
были отдельные тестовые source/workspace и host, без переопределения модели.

| Наблюдение | MCP без skill | MCP + skill |
|---|---|---|
| Авторская схема прочитана | Да | Да |
| Интеграционный тест и независимый повтор | PASS | PASS |
| Принятие пакета, журнал, перезагрузка, Save/Discard в тестах | Проверены | Проверены |
| Отказ валидации и записи журнала | Проверены | Проверены |
| Тест обнаружил имитацию пропуска Save | Да | Да |
| Тест обнаружил имитацию пропуска checkpoint | Да | Да |
| Новая схема создана и проверена рендером | Да | Да |
| Прежние виды и тексты изменены | Нет | Нет |
| MCP tools/call агента | 76 | 141 |
| Ответы MCP isError | 1 | 6 |
| Запросы метаданных/схем через bridge | 14 | 18 |
| MCP Save/Discard карты | 0 | 0 |

Разница — 65 вызовов, приблизительно 86% относительно варианта без skill.
Основное различие связано с детализацией схемы: `set_text` — 4 против 53,
`move_elements` — 0 против 16. Skill не предписывает такое количество действий,
поэтому всю разницу нельзя причинно приписать его тексту.

Без skill исполняемым тестом проверена частичная запись файлов при ошибке Save;
со skill — общая модель HTTP/MCP и два подписчика сервиса. Это разные полезные
проверки без однозначного выигрыша по полноте. Проверка подписчиков не
подтверждает два браузера или SSE по сети.

## Измерения: обычное изменение кода

Эксперимент `20261012-1f9e425a`: исправить нормализацию запроса `find_entities`,
обрезая крайние Unicode-пробелы и сохраняя поиск без учёта регистра, фильтры,
limit и total; добавить регрессионные тесты. **Задание не упоминало диаграммы.**

Три независимых агента получили одинаковые исходники, сохранённую карту и каталог
инструментов. Отличались прежние/новые инструкции MCP и явно предоставленный
skill 0.1.1. Новые инструкции объясняли двунаправленную роль SeMaps в разработке.

| Наблюдение | Прежний MCP | Новый MCP | Новый MCP + skill |
|---|---|---|---|
| Прочитал авторскую карту перед первой правкой кода | Нет | Да | Да |
| Прочитал пояснения MCP server / Model service | Нет | Да | Да |
| Оценил влияние исправления на карту после правки | Не описал | Да | Да |
| Итог исправления | Корректно | Корректно | Корректно |
| Регрессия до исправления и успех после | Подтверждены | Подтверждены | Подтверждены |
| Новых регрессионных сценариев | 23 | 20 | 19 |
| Полная проверка | host: PASS | все Go-пакеты: PASS | host: PASS |
| MCP tools/call агента | 7 | 11 | 18 |
| Ответы MCP isError | 0 | 2 | 0 |
| Запросы метаданных/схем через bridge | 4 | 7 | 10 |
| Изменения сохранённой карты | 0 | 0 | 0 |

Новый MCP без skill уже обеспечил требуемое поведение. Оба варианта с новыми
инструкциями обоснованно заключили, что исправление внутри существующего
обработчика не меняет компоненты, обязанности или связи и не требует правки карты.

Со skill дополнительно проверены свежесть графа после повторной экстракции,
окрестность mcpServer и состояние карты: семь дополнительных вызовов относительно
нового MCP без skill. Две ошибки варианта без skill — запросы неразрешимого узла
`findEntities`. Один прогон не доказывает, что skill систематически предотвращает
такие ошибки. Число тестовых сценариев не является оценкой качества: у всех
проверены требуемые поля поиска, Unicode, пустой запрос, фильтры и total при limit.

## Связанное наблюдение

Во втором эксперименте обнаружено, что прежний stdio-прокси `semaps mcp`
передавал инструменты, но терял Instructions из initialize HTTP-сервера.
Дефект исправлен в MCP; отдельный skill не нужен как обход потери инструкций.
Настоящие бинарники подтвердили отсутствие Instructions у прежнего прокси и
совпадение HTTP/stdio-инструкций у нового. Полный пакет host, включая передачу
инструкций и переподключение, прошёл тесты.

Поведенческое сравнение использовало HTTP MCP с инструкциями initialize для всех
вариантов: эффект нового текста не смешан с исправлением прокси.

## Ограничения и пересмотр

- Один запуск на вариант в каждом эксперименте, задачи внутри самого SeMaps.
  Это наблюдения, а не статистическая оценка.
- Skill предоставлялся явно. Автоматическая активация, обнаружение продукта и
  работа до подключения MCP не проверялись; их предполагаемая польза не доказана.
- Точные токены и стоимость моделей недоступны. Число вызовов не равно расходу
  токенов, стоимости или времени. Вызовы проверяющего и служебные initialize /
  tools/list исключены из счётчиков; сравнение скорости не служит основанием.
- В первой среде отсутствовал собранный host/app; целевые host-тесты использовали
  минимальный ресурс для компиляции и не проверяли embedded UI. Финальные схемы
  отдельно проверены настоящим редактором. Во второй среде использован реальный
  собранный host/app.
- Контрольное исправление поиска проверялось в MCP-сессиях тестов из изменённых
  исходников, без подмены предоставленных работающих бинарников.

Вывод относится к существующему универсальному skill поверх SeMaps MCP.
Бесполезность любых skills или любого будущего специализированного сценария
из этих данных не следует. Пересмотр оформляется новым ADR при появлении
проверяемой дополнительной пользы.
