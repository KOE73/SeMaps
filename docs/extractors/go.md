# Извлекатель Go: нормативное соответствие

**Статус:** нормативный. Извлекатель — [`extractors/go`](../../extractors/go) (`semaps-extract-go`).
Таблицы этого документа — контракт: каждая строка таблицы рёбер покрыта примером в
`extractors/go/testdata/sample`, и тест `TestMappingTable` читает **этот файл** и сверяет
`kind`/`native` с выводом. Правка таблицы без кода (или кода без таблицы) роняет сборку.

Общий контракт — [`EXTRACTOR.md`](../EXTRACTOR.md); словарь рёбер и поле `native` —
[`ADR_20260927`](../adr/ADR_20260927_contract_closed-relation-vocabulary.md); признаки членских
связей — [`ADR_20260924-4`](../adr/ADR_20260924-4_contract_member-relations-from-code.md).

## Запуск

```
semaps-extract-go [--root <dir>] [--include <path>]... [--exclude <glob>]... [--edges holds,uses,injects] [--implements <pkg.Name>,...]
```

- Заголовок фактов: `"language": "go"`; `root` — значение `--root` как передано (прямые слэши).
- Чтение — `golang.org/x/tools/go/packages` + `go/types`: разрешённые символы, не текст.
  Нужна установленная команда `go` (она находит модули и зависимости).
- Каждый `--include` (нет — весь `--root`) грузится в своём модуле: ближайший `go.mod` на
  этом каталоге или выше. `--include` в разных модулях — разные загрузки; вложенный модуль
  (свой `go.mod`) в `./...` родителя не входит — его перечисляют отдельным `--include`.
- Любая ошибка загрузки или типов — код `1`, вывода нет (EXTRACTOR §1).
- `edgeKinds`: всегда `contains`, `depends`, `extends`, `implements`; плюс `holds`, `uses`,
  `injects` — то, что перечислено в `--edges`.
- `--implements` — внешние интерфейсы по полному имени (`io.Reader`, `error`), см. ниже.

### Что пропускается

| Что | Почему |
|---|---|
| `*_test.go` | тесты — не архитектура; `packages.Load` с `Tests: false` их и не читает |
| каталоги `vendor/`, `testdata/` (любой сегмент пути) | чужой код и примеры |
| файлы с заголовком `// Code generated … DO NOT EDIT.` (`ast.IsGenerated`) | сгенерированный код |
| `--exclude <glob>` | поверх умолчаний; `**` — любые символы, `*` — внутри сегмента |
| функции `init`, имена `_` | `init` бывает несколько на пакет и не адресуется |
| объявления внутри функций | не верхний уровень |

Метод в пропущенном файле не попадает в `members` и не даёт рёбер; сам тип остаётся, если он
объявлен в прочитанном файле.

## Символы: `kind` и `nativeKind`

`id` — `<import path>.<Name>`, у пакета — import path. `namespace` — import path пакета
(у пакета — пусто). `visibility` — `exported` | `unexported` (регистр первой буквы).
Типовые параметры в `id` и `name` не входят: `Box[T any]` — `…/model.Box`.

| Объявление | `kind` | `nativeKind` | Примечание |
|---|---|---|---|
| пакет | `module` | `package` | `name` — имя пакета, `file`/`line` — `package`-строка первого по пути прочитанного файла |
| `type T struct{…}` | `type` | `struct` | |
| `type T interface{…}` | `interface` | `interface` | в т.ч. `type J I` над интерфейсом |
| `type T func(…) …` | `type` | `func` | не `function`: у него бывают методы, и он реализует интерфейсы (`http.HandlerFunc`) |
| `type T map[K]V` / `[]E` / `[n]E` / `chan E` / `*E` | `type` | `map` / `slice` / `array` / `chan` / `pointer` | вид подлежащего типа |
| `type T int`, `type T string`… | `type` | имя базового типа: `int`, `string`… | перечисление Go — такой тип плюс константы |
| `type A = B` | `type` (`interface`, если `B` — интерфейс) | `alias` | |
| `func F(…)` верхнего уровня | `function` | `function` | методы — не символы, а `members` типа |
| `const C` | `value` | `const` | |
| `var V` | `value` | `var` | |

`type T U` над именованным типом получает `nativeKind` по подлежащему типу `U`
(`type Admin User` — `struct`).

### `members`

Печатаются у `type` и `interface` (пустой массив, если членов нет; у псевдонима — нет):

| Член | `kind` | `type` | `note` |
|---|---|---|---|
| поле структуры, в порядке объявления | `field` | тип поля | `embedded` у встроенного |
| метод интерфейса (явный), по имени | `method` | сигнатура `func(…) …` | |
| метод типа (объявленный, оба получателя), по имени | `method` | сигнатура | `pointer receiver` у `*T` |
| константа этого типа из того же пакета, в порядке объявления | `value` | точное значение (`0`, `"a"`) | |

Продвинутые встраиванием методы в `members` не повторяются: они — члены встроенного типа.
Константа-член остаётся и отдельным символом `value`.

## Рёбра: таблица соответствия

Рёбра — только между символами вывода. Нет `native` (`—`) — у Go один очевидный способ
выразить эту связь.

<!-- mapping-table: TestMappingTable читает строки этой таблицы; первая колонка — ключ теста -->

| Конструкция | `kind` | `native` | Почему | Отвергнуто |
|---|---|---|---|---|
| пакет объявляет символ верхнего уровня | `contains` | — | структурная вложенность, как пространство имён C# | — |
| `import` пакета из вывода | `depends` | — | единица сборки Go — пакет | модуль (`go.mod`) как единица: слишком крупно, внутри одного модуля пропала бы вся картина |
| поле структуры `f T` | `holds` | `field` | тип держит объект через член | — |
| встроенное поле `struct{ T }` | `holds` | `embed` | композиция: `User` со встроенным `Base` нельзя подставить вместо `Base` | `extends` — подстановки нет; отдельный вид `embeds` — проваливает условие 4 ADR_20260927 |
| встраивание интерфейса `interface{ I }` | `extends` | `embed` | расширение контракта, как `IA : IB` в C# | `holds` — у интерфейса нет состояния |
| определение интерфейса над интерфейсом `type J I` | `extends` | `underlying` | тот же контракт под новым именем; `J` принимает всё, что `I` | `holds` — состояния нет |
| набор методов `T` ⊇ интерфейс | `implements` | `methodset` | неявная реализация, смысл тот же | не печатать — потерялась бы главная архитектурная связь Go |
| набор методов только `*T` ⊇ интерфейс | `implements` | `methodset.ptr` | тот же смысл; `native` говорит, что подставлять нужно `*T` | отдельная связь — смысл не отличается |
| определение типа над составным или именованным типом `type T []E` | `holds` | `underlying` | `type Batch []Item` состоит из `Item`, как поле | `uses` — тип значением **является** коллекцией, а не пользуется ею |
| определение функционального типа `type F func(A) R` | `uses` | `signature` | сигнатура упоминает типы, не держит их | `holds` — функциональный тип не хранит `A`/`R` |
| псевдоним `type A = B` | `uses` | `alias` | правая часть псевдонима (EXTRACTOR §2.2) | `extends` — это то же самое имя, а не подтип |
| параметр функции или метода | `uses` | — | EXTRACTOR §2.2 | `injects` — конструкторов в Go нет (ниже) |
| результат функции или метода | `uses` | — | EXTRACTOR §2.2 | — |
| тип `var` / `const` | `uses` | — | собственная сигнатура значения (EXTRACTOR §2.2) | — |

**`implements`** считается для пар «именованный не-интерфейсный тип × интерфейс вывода» из одной
загрузки (одного модуля: одна вселенная типов). Пропускаются: обобщённые типы и интерфейсы
(набор методов зависит от инстанцирования), интерфейсы-ограничения (`~int | string`) и пустые
интерфейсы (их реализует всё — шум). Сначала проверяется `T`, затем `*T`: если подходит `T`,
`methodset.ptr` не печатается.

**`injects`.** В Go нет конструкторов: `NewX(…) *X` — обычная функция. Рёбер с
`memberKind: constructor` извлекатель не печатает никогда; `--edges injects` лишь объявляет
покрытие в `edgeKinds` (связей этого вида в Go-коде нет). Угадывать конструктор по префиксу
`New` отвергнуто: соглашение, а не язык, и оно ломается на `NewFromConfig`, `Must…`, фабриках.

**Внешние интерфейсы (`--implements io.Reader,error`).** ADR_20260927 §5 велит считать
`implements` и к явно перечисленным внешним интерфейсам. Контракт фактов этого пока не
допускает: ребро — только между символами вывода, а у символа обязателен `file` под `--root`.
Флаг принимается и проверяется (полные имена, без масок); имя, которое есть в выводе,
считается как обычно; для внешнего печатается предупреждение в stderr, рёбер нет. Решение —
за изменением `EXTRACTOR.md` (например, символ `nativeKind: external` без `file`).

### Членские связи: `via`

| Ребро | `via.member` | `via.memberKind` | `via.modifiers` |
|---|---|---|---|
| поле | имя поля (у встроенного — имя типа) | `field` | `public` у экспортированного, `private` у неэкспортированного |
| определение типа (`underlying`) | имя типа | `self` | как у поля, по имени типа |
| `alias`, `signature` | имя типа | `self` | — |
| параметр функции | имя параметра | `parameter` | — |
| параметр метода | `<Метод>.<параметр>` | `parameter` | — |
| результат | имя функции/метода; при нескольких — `<имя>.<результат>` | `return` | — |
| `var` / `const` | имя значения | `self` | — |

Безымянный параметр или результат (и `_`) — `#<позиция>`: `Split.#0`. Префикс метода нужен,
потому что ключ членской связи — `(from, to, семейство, member, path)`, а `from` у метода —
его тип: два метода с параметром `ctx` иначе дали бы повтор.

`modifiers` — `public`/`private`, а не слова Go: сверка (`core`) решает `holds.*.internal` по
этим словам (`private`, `internal`, `protected` — непубличный член). Выбран `private`:
неэкспортированное видно только своему пакету, а `internal` в C# означает сборку — единицу
крупнее пакета.

`via.text` — тип члена, как написан в коде (`map[string]*Item`, `...model.Item`).
Ребро на свой же тип (`func (m *MemStore) Clone() *MemStore`) не печатается.

### Признаки членских связей

Путь (`via.path`) строится от типа члена к символу вывода. На именованном типе вывода обход
останавливается; у чужого именованного типа смотрятся только аргументы типа. Кратность
задаёт **внешняя** коллекция: `map[Key][]Item` → `keyed` для обоих рёбер.

| Тип | `cardinality` | `path` | `deferred` | Почему |
|---|---|---|---|---|
| `T` | `one` | — | | |
| `*T` | `one` | — | | указатель в Go — способ разделять объект, а не «может не быть». `optional` у каждого сервиса, переданного по указателю, стёр бы различие; nil-допустимость — не замысел |
| `[]T`, `[n]T`, `...T` | `many` | `item` | | |
| `map[K]V` | `keyed` | `key` / `value` | | два ребра, если оба — символы вывода |
| `chan T`, `<-chan T` | `many` | `item` | `true` | поток значений, приходящих позже (как `IObservable`) |
| `func(A) R` (значение-функция) | как снаружи, иначе `one` | `arg:i`, `result` / `result:i` | `true` | объект появится при вызове (как `Func` в C#) |
| `G[A]` | `one` для `G`; для `A` как снаружи | у `A` — `arg:i` | | обобщённый тип вывода и его аргумент — две связи |
| `struct{ F T }` (анонимная) | как снаружи | `field:F` | | |

`mutability` не печатается никогда: в Go изменяемость — свойство переменной (значение или
указатель), а не типа; «неизвестно» честнее угадывания (EXTRACTOR §2.2a).

## Место в коде

Поля места в коде (`endLine`, `spans`, `memberLines` у символа; `line`/`file` у ребра,
`docs/EXTRACTOR.md` §2.1–2.2) необязательны для любого языка; будущий Go-извлекатель ими не обязан.
