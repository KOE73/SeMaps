# Членские связи Go: соответствие типов признакам

**Статус:** извлекателя нет.

Черновой план соответствия типов Go признакам членских связей
(§2 [`ADR_20260924-4`](../adr/ADR_20260924-4_contract_member-relations-from-code.md)).

## Кратность и изменяемость коллекций

| Тип | Кратность | Изменяемость | Примечание |
|---|---|---|---|
| `[]T` (slice) | `many` | `mutable` (?) | срез; мутабельность неизвестна из типа |
| `[n]T` (array) | `many` | `mutable` (?) | массив фиксированного размера; мутабельность неизвестна |
| `map[K]V` | `keyed` | `mutable` (?) | словарь; мутабельность неизвестна |
| `*[]T`, `*map[K]V` | `many` / `keyed` | `mutable` (?) | указатель на срез/словарь; мутабельность неизвестна |

**Замечание:** В Go вся мутабельность контролируется на уровне переменной (копирование значения vs указателя), а не типа.
Извлекатель не может вывести из типа, изменяемо ли содержимое. Возможно, потребуется объявить все `many`/`keyed` типы без признака `mutability`.

## Опциональность

| Тип | Кратность | Примечание |
|---|---|---|
| `*T` | `optional` (?) | указатель может быть nil |
| `T` (по значению) | `one` | обязательное значение |

**Замечание:** В Go нет явного Optional; указатель — это способ обозначить nullable значение.
Вопрос открыт: считать ли `*T` (указатель) как `optional` при одновременной ссылке на T, или как отдельную связь.

## Отложенные типы

| Тип | Сигнатура пути | Примечание |
|---|---|---|
| `chan T` | `result` (?) | канал; результат — значение из канала |

**Замечание:** Каналы в Go — это потоки данных, подобны `IObservable` в C#. Точное обозначение требует определения.

## Из кода не выводится (неизвестно)

| Что | Почему | Решение |
|---|---|---|
| Мутабельность коллекций | контролируется на уровне переменной | ? |
| Опциональность указателей | только по `*T` синтаксису | ? |
| Интерфейсы-потребители | неявная реализация | авторская связь |
