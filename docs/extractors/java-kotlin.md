# Членские связи Java и Kotlin: соответствие типов признакам

**Статус:** извлекателя нет.

Черновой план соответствия типов Java и Kotlin признакам членских связей
(§2 [`ADR_20260924-4`](../adr/ADR_20260924-4_contract_member-relations-from-code.md)).

## Кратность и изменяемость коллекций

### Java

| Тип | Кратность | Изменяемость | Примечание |
|---|---|---|---|
| `List<T>` | `many` | `mutable` (?) | интерфейс списка; мутабельность неизвестна |
| `ArrayList<T>` | `many` | `mutable` (?) | изменяемый список |
| `LinkedList<T>` | `many` | `mutable` (?) | связанный список |
| `Collection<T>` | `many` | `mutable` (?) | интерфейс коллекции |
| `Iterable<T>` | `many` | `readonly` | интерфейс итератора |
| `Set<T>` | `many` | `mutable` (?) | интерфейс множества |
| `HashSet<T>` | `many` | `mutable` (?) | множество (неупорядоченное) |
| `TreeSet<T>` | `many` | `mutable` (?) | множество (упорядоченное) |
| `Map<K, V>` | `keyed` | `mutable` (?) | интерфейс словаря |
| `HashMap<K, V>` | `keyed` | `mutable` (?) | словарь (неупорядоченный) |
| `TreeMap<K, V>` | `keyed` | `mutable` (?) | словарь (упорядоченный) |

**Замечание:** Java имеет иерархию коллекций, но не различает мутабельность на уровне типа.
Извлекатель не может вывести мутабельность из типа.

### Kotlin

| Тип | Кратность | Изменяемость | Примечание |
|---|---|---|---|
| `List<T>` | `many` | `readonly` | неизменяемый список по умолчанию |
| `MutableList<T>` | `many` | `mutable` | изменяемый список |
| `ArrayList<T>` | `many` | `mutable` | реализация изменяемого списка |
| `Set<T>` | `many` | `readonly` | неизменяемое множество |
| `MutableSet<T>` | `many` | `mutable` | изменяемое множество |
| `HashSet<T>` | `many` | `mutable` | реализация множества |
| `Map<K, V>` | `keyed` | `readonly` | неизменяемый словарь |
| `MutableMap<K, V>` | `keyed` | `mutable` | изменяемый словарь |
| `HashMap<K, V>` | `keyed` | `mutable` | реализация словаря |

**Замечание:** Kotlin явно различает изменяемые и неизменяемые коллекции через интерфейсы.

## Опциональность

### Java

| Тип | Кратность | Примечание |
|---|---|---|
| `Optional<T>` | `optional` | контейнер для nullable значения |
| `T` (ссылочный тип) | `one` | может быть null, но не отмечено |

**Замечание:** Java 8+ предусмотрела `Optional`, но также допускает null в ссылочных типах без явного обозначения.

### Kotlin

| Тип | Кратность | Примечание |
|---|---|---|
| `T?` | `optional` | nullable тип |
| `T` | `one` | non-null тип (по умолчанию) |

**Замечание:** Kotlin явно различает nullable и non-null типы.

## Отложенные типы

| Тип | Сигнатура пути | Примечание |
|---|---|---|
| `Future<T>` | `result` | асинхронный результат (Java) |
| `CompletableFuture<T>` | `result` | асинхронный результат (Java 8+) |
| `Callable<T>` | `result` | вызываемое, возвращающее T |
| `Supplier<T>` | `result` | поставщик значения |
| `suspend fun(): T` | `result` | suspend функция (Kotlin) |

## Из кода не выводится (неизвестно)

| Что | Почему | Решение |
|---|---|---|
| Мутабельность (Java List/Map) | не различается типом | ? |
| Аннотации (Java @NonNull) | не извлекаются | авторская связь |
| Анонимные классы | трудноразличимы | авторская связь |
| Обобщения с ограничениями (Java `<T extends Foo>`) | не печатаются как связи | авторская связь, если нужна явность |

## Маппинг kind и nativeKind

### Java

| kind | nativeKind | Примеры |
|---|---|---|
| `type` | `class` | класс |
| `type` | `interface` | интерфейс |
| `type` | `enum` | перечисление |
| `type` | `record` | record (Java 16+) |
| `function` | `method` | метод класса |
| `module` | `package` | пакет |

### Kotlin

| kind | nativeKind | Примеры |
|---|---|---|
| `type` | `class` | класс |
| `type` | `interface` | интерфейс |
| `type` | `enum` | перечисление |
| `type` | `data class` | data class |
| `type` | `sealed class` | sealed класс |
| `interface` | `object` | singleton (по-другому рассматривается как тип) |
| `function` | `fun` | функция на уровне пакета или метод |
| `module` | `package` | пакет |

**Замечание:** Kotlin использует более явные конструкции; `object` может рассматриваться как тип или как функция инициализации.
