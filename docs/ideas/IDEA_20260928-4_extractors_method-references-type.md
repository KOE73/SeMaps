# IDEA_20260928-4_extractors — Факт «метод упоминает тип»

Отложено решением человека 2026-09-28: граф сейчас не усложнять. Стоит на
[`ADR_20260928-5`](../adr/ADR_20260928-5_extractors_only-unambiguous-facts.md).

## Мысль

В теле метода тип может быть назван, не будучи ни вызванным, ни созданным:

| Запись | Способ |
|---|---|
| `typeof(ImageRunner<,,,>)` | `typeof` |
| `GetService<IRunner>()`, `Deserialize<Config>(json)` | аргумент обобщённого вызова |
| `(IRunner)obj`, `obj is IRunner`, `obj as IRunner` | приведение и проверка |
| `catch (OnnxException)` | перехват |
| `nameof(Runner)` | имя |

Это язык, библиотеку знать не нужно. Ребро `references` метод → тип, в подписи — способ и строки.

## Что это дало бы

Слепые места становятся видны без догадок. Метод с отметкой динамического создания в строке 57
и упоминанием `ImageRunner` через `typeof` в строке 55 — два факта рядом; вывод делает читатель.
Регистрация в контейнере `AddSingleton<IRunner, ImageRunner>()` — два упоминания в одной строке,
без слова о контейнерах.

## Что надо решить

- Объём: упоминаний может быть не меньше, чем вызовов (2752 на NeuroModFlowNet.ONNX).
- Не дублировать то, что уже есть: тип параметра, возвращаемого значения, поля — это `uses` и
  `holds`.
- Входит ли в обход по умолчанию.
