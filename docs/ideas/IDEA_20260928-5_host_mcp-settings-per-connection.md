# IDEA_20260928-5_host — Настройки MCP на подключение, а не на проект

Отложено решением человека 2026-09-28: замечание верное, сейчас не делать.

## Мысль

Настройки MCP (набор инструментов, подробность описаний, формат ответа, пороги) лежат в файле
`.semaps` — он в git и общий для всех. Модель у каждого своя: один работает с сильной, другой с
локальной на 27B. К одному хосту могут быть подключены два агента с разными моделями сразу.

## Как это могло бы выглядеть

| Уровень | Где | Для чего |
|---|---|---|
| умолчание проекта | раздел `mcp` в `.semaps` | что получает агент, если не сказано иное |
| своё для клиента | аргументы `semaps mcp` в `.mcp.json` у каждого | `--tools narrow --description brief` |

Для прямого подключения по HTTP — параметры адреса `/mcp`.

Иной путь — два подключения с разными именами (`semaps` и `semaps-simple`), каждое со своим
набором. Проще сделать, но у агента два набора инструментов об одном и том же.

## Что надо решить

- Прокси `semaps mcp` копирует список инструментов хоста при старте: ему надо знать профиль до
  копирования.
- Как страница настроек показывает, кто с каким профилем подключён.
