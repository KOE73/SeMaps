# PLAN_20260923_core — Сверка реестра с фактами извлекателя

Статус: **в работе** — сделан шаг 1, остальное не начато.

Цель: `semaps sync` делает то, что описано в [`EXTRACTOR.md`](../EXTRACTOR.md) §5 —
читает факты извлекателя и приводит `entities.json` / `relations.json` в соответствие
с кодом, не трогая ни текстов, ни видов, ни `authored`-записей. Без этого обещание
README «машина сверяет с кодом» держится только на `codeRef`.

## Шаги

1. ~~`semaps check` в `core/` — перенос `check-model.mjs`.~~
   [`ADR_20260923-4`](../adr/ADR_20260923-4_core_check-lives-in-the-binary.md).
2. Чтение фактов: `core/facts.go` — структуры §2 `EXTRACTOR.md`, валидация
   (`kind` из словаря, `edges` только на символы вывода, сортировка).
3. `semaps sync --facts <file.json> [dir | file.semaps]`:
   - символ есть, записи нет → новая `e_…`, `origin: code`, `status: present`;
     коллизия id → `_2`, `_3`;
   - запись есть, символа нет → `status: missing`, запись не удаляется;
   - переименование (пропал X, появился Y в том же файле) → только кандидат
     в отчёте, решает человек;
   - `authored` не трогается никогда;
   - ребро извлекателя → `relations.json` с типом из общего словаря; авторские
     типы не затрагиваются.
   Правила — таблица в `EXTRACTOR.md` §5, она нормативна; расхождение = баг.
4. Запуск извлекателя из хоста: `semaps sync` без `--facts` ищет
   `semaps-extract-<lang>` в PATH по `project.json → sources.language`
   (ключа пока нет — ввести правкой `CONTRACT.md` в том же коммите).
5. Отчёт о дрейфе: что добавлено, что пропало, кандидаты на переименование;
   код выхода как у `check`.
6. Кнопка «Сверить» в редакторе — вызывает `/api/sync` и перечитывает проект.
   Требует правки `API.md`.
