# PLAN_20260923_extractors_csharp — Извлекатель C#

Статус: **в работе**.

Цель: `semaps-extract-csharp`, печатающий факты по [`EXTRACTOR.md`](../EXTRACTOR.md).
Нужен практически: первые проекты-потребители на C#. Методологический образец —
[`PLAN_20260923_extractors_typescript`](PLAN_20260923_extractors_typescript.md); оба
извлекателя — «один из многих», ни один не главный.

Нормативные документы: [`EXTRACTOR.md`](../EXTRACTOR.md) (контракт вывода),
[`ADR_20260923-5`](../adr/ADR_20260923-5_extractors_symbol-ids.md) (форма `id`),
[`schemas/extractor-facts.schema.json`](../../schemas/extractor-facts.schema.json) (схема).
Расхождение кода с ними — баг кода, а не повод править документ молча.

## Техническое задание

### Расположение и запуск

- Каталог `extractors/csharp/`: решение `SeMaps.Extract.CSharp.slnx`, проекты
  `src/SeMaps.Extract.CSharp/` (консоль, .NET 10, `PackAsTool`, `ToolCommandName` =
  `semaps-extract-csharp`, `PackageId` = `SeMaps.Extract.CSharp`) и
  `tests/SeMaps.Extract.CSharp.Tests/` (xunit).
- Roslyn через `Microsoft.CodeAnalysis.Workspaces.MSBuild` + `Microsoft.Build.Locator`
  (§3: разрешённые символы). Никакого `CSharpSyntaxTree.ParseText` по файлам.
- Аргументы по §1: `--root <dir>` (по умолчанию cwd), `--include <path>`…, `--exclude <glob>`….
  Что открывать: если под `--root` (или под каждым `--include`) есть ровно одно `*.sln`/`*.slnx`
  — открыть его; иначе все `*.csproj` под этими путями по одному. `--include` — фильтр по
  путям **файлов** результата, не по проектам: символы из файлов вне `--include` не печатаются.
- Коды выхода 0/1/2 по §1. stdout — только JSON, всё остальное в stderr. Диагностика
  MSBuild (`WorkspaceFailed`) — в stderr; если ни один проект не загрузился — выход 1.

### Исключения по умолчанию

`bin/`, `obj/`, `*.g.cs`, `*.g.i.cs`, `*.Designer.cs`, `*AssemblyInfo.cs`, `GlobalUsings*.cs`,
`*.generated.cs`, файлы с `<auto-generated` в первых строках, символы с
`[GeneratedCode]`/`[CompilerGenerated]`. `--exclude` добавляет поверх.

### Символы

| Объявление C# | `kind` | `nativeKind` |
|---|---|---|
| пространство имён (каждое, в котором есть хоть один тип из вывода) | `module` | `namespace` |
| `class`, `static class`, `abstract class` | `type` | `class` / `static-class` / `abstract-class` |
| `struct`, `record`, `record struct` | `type` | `struct` / `record` / `record-struct` |
| `enum` | `type` | `enum` |
| `interface` | `interface` | `interface` |
| `delegate` | `function` | `delegate` |

- `id` по ADR-5 (метаданное имя с пространством имён). `name` — короткое имя без арности
  (`List`), `namespace` — полное имя пространства. `file`/`line` — первое объявление по
  сортировке пути; `partial` — один символ.
- Вложенные типы: печатаются, если **публичные или internal**; приватные вложенные
  пропускаются (§3). Ребро `contains` от внешнего типа.
- `members`: `enum` — все члены (`kind: "value"`, `type` — числовое значение); `interface` —
  все члены (`kind`: `property` / `method` / `event`, `type` — тип или сигнатура возврата,
  `visibility: public`); `class`/`struct`/`record` — публичные и `internal` поля и свойства
  (`kind`: `field` / `property`, `type` — тип, `visibility`). Методы классов **не** печатаются
  (§6.2 EXTRACTOR: ограничение объёма). `type` — `ToDisplayString` с минимальной
  квалификацией (`SymbolDisplayFormat.MinimallyQualifiedFormat`).

### Рёбра

- `contains`: пространство имён → тип; внешний тип → вложенный.
- `extends`: базовый класс (кроме `object`, `ValueType`, `Enum`, `Delegate`).
- `implements`: каждый интерфейс из `Interfaces` (прямые, не `AllInterfaces`).
- `references`: тип поля/свойства, параметров и возврата **публичных** методов и
  конструкторов, аргументы generic-типов, тип элемента массива, `Nullable<T>` → `T`. Только на
  символы этого же вывода; `A → B` схлопывается в одно ребро; `A → A` не печатается.
- Ребро на символ вне вывода (BCL, NuGet, исключённый файл) не печатается.

### Детерминизм

`symbols` по `id` (ordinal), `edges` по `(from, to, kind)` (ordinal), `System.Text.Json` с
`WriteIndented`, порядок свойств как в схеме, `\n` в конце. Тест: два прогона — один байт в
байт вывод. Пути — прямые слэши, относительно `--root`.

## Открытое

1. **Объём `references` замерен.** На реальном решении-потребителе (7 проектов, ~390 типов)
   получено 548 рёбер `references` (плюс `contains` 383, `extends` 118, `implements` 107),
   выход `0` за 7 с. До тысяч далеко, порог обсуждать пока незачем — закрывает открытый вопрос
   старого плана.
2. **Что открывать, когда `--include` не один путь.** Поисковые корни — это пути `--include`,
   если они заданы, иначе один `--root`. Если под объединением этих корней находится ровно один
   `*.sln`/`*.slnx` — открывается он; иначе — каждый `*.csproj` под ними. Проект, подтянутый в
   workspace транзитивно через `ProjectReference` (для разрешения символов), но лежащий вне
   `--include`, из символов не выпадает автоматически: его типы участвуют в разрешении
   (`extends`/`implements`/`references` видят правильные символы), но не печатаются — фильтр
   `--include` применяется к `file` каждого символа отдельно, как и требует EXTRACTOR.md §1.
3. **Глобальное пространство имён.** Символ `module` для глобального пространства имён не
   печатается (у него нет непустого `id`, а схема требует `\S+`). Тип, объявленный без
   `namespace`, получает `namespace: ""` и id без точки-префикса (как в примере ADR-5), но ребра
   `contains` в него не будет — самое узкое поведение при отсутствии другого текста в контракте.
4. **Видимость вложенных типов проверяется только у самого типа.** «Печатаются, если публичные
   или internal» (план, «Символы») прочитано буквально: для проверки берётся собственная
   `DeclaredAccessibility` типа, а не видимость его контейнеров по цепочке. Публичный тип,
   вложенный в приватный, формально попадёт в вывод — граница не расширяется толкованием.
5. **Событий класса/структуры/record нет в `references`.** EXTRACTOR.md §2.2 перечисляет
   источники `references` явно: «тип поля/свойства, параметров и возврата публичных методов и
   конструкторов». Событий там нет, поэтому `public event` класса не даёт ребра. Для
   `interface`, где план прямо требует печатать событие как член (`kind: "event"`), его тип
   дополнительно сканируется и на `references` — событие там уже часть контракта членов.
6. **Собственная сигнатура delegate тоже сканируется на `references`.** У delegate нет полей и
   методов в обычном смысле, но есть `Invoke` с параметрами и возвратом — это и есть его
   единственная сигнатура; она проверяется на `references`, аналогично методам класса.
7. **Методы/конструкторы, дающие `references`, — только `public`.** Для класса/структуры/record
   internal-методы не сканируются (в отличие от полей и свойств, где internal тоже даёт ребро) —
   в EXTRACTOR.md написано именно «публичных методов и конструкторов». Для `interface` сканируются
   все обычные методы (там весь член контракта публичный по определению языка).
8. **Форма `type` члена-метода интерфейса.** «Тип или сигнатура возврата» (план, «Символы»)
   реализовано как полная сигнатура — `ВозвращаемыйТип Имя(ТипПараметра имя, …)`, в
   `SymbolDisplayFormat.MinimallyQualifiedFormat`, без имени содержащего типа. Только тип
   возврата было бы недостаточно для различения перегрузок в `members`.
9. **`root` в выводе — буквально значение `--root`**, как оно передано (или `"."`, если флаг не
   указан), без разрешения в абсолютный путь: тот же принцип, что и у `--source-root` хоста
   (EXTRACTOR.md §1) — совпадать посимвольно может только не тронутая строка.
10. **Диагностика `MSBuildWorkspace` не всегда фатальна.** `WorkspaceFailed` (включая, например,
    NuGet audit-предупреждения о пакете с известной уязвимостью — они приходят с
    `DiagnosticKind.Failure`, хотя сам проект после них благополучно загружается) всегда пишется
    в stderr, но выход `1` — только когда **ни один** запрошенный проект не выдал `Compilation`.
    Отдельный проект, который не загрузился, просто выпадает из вывода — как и требует
    «частичный результат не печатается» (EXTRACTOR.md §1) в применении к отдельному проекту, а
    не ко всему прогону.
11. **JSON: `<`, `>`, `+`, `` ` `` не экранируются** (`JavaScriptEncoder.UnsafeRelaxedJsonEscaping`) —
    иначе `id` вида `A.B.C\`1` и `type` вида `Repo<Status>` в выводе не совпадали бы по виду с
    примерами EXTRACTOR.md/ADR-5, хотя и оставались бы валидным JSON в экранированном виде.
    Перевод строк принудительно приведён к `\n` (замена `\r\n` → `\n`), чтобы вывод не зависел от
    `Environment.NewLine` хост-ОС — без этого детерминизм ломался бы между Windows и CI.
