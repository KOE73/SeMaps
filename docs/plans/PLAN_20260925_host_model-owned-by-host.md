# PLAN_20260925_host — Модель у хоста: рабочее состояние, «Сохранить», события, MCP по HTTP

Статус: **в работе** — шаги 1–5 выполнены; следующий шаг 6.

Решение: [`ADR_20260925_host`](../adr/ADR_20260925_host_model-owned-by-host.md). Прочитать его
целиком до начала; ниже — только «где и как».
Уточнение манифеста и структурных операций:
[`ADR_20260925-2_host`](../adr/ADR_20260925-2_host_project-manifest-and-structure.md).

Следом (отдельный план): инструменты раскладки для агента — `get_view`, «копировать ссылку» на
объект, «разложи по образцу», move/resize. Они ложатся на модель из этого плана.

## Как сейчас (чтобы знать, что меняем)

- Редактор: `editor/src/editor/io/ProjectStore.ts` — `HttpProjectStore.load(view)` тянет статикой
  вид и файлы проекта (`project.json`, `entities.json`, `relations.json`, `relation-types.json`,
  `text.<lang>.json`) и склеивает их в один `WireDocument`; `save()` → `saveProjectBundle()`
  раскладывает документ обратно и пишет каждый файл через `POST /api/save?file=`.
  `WorkspaceStore.ts` — каталог (`GET /api/workspace`), создание и переименование проектов и видов
  (`/api/save?create=1`, `/api/move`). `History.ts` — Undo снимками, в памяти окна.
- Хост: `host/server.go` — статика workspace, `/api/save`, `/api/move`, `/api/workspace`;
  `host/api_tools.go`, `host/api_mcp.go` — API режимов; `host/mcp.go` — MCP-инструменты.
- `core/edit.go` — правила записи (id, тексты с `origin`/`at`, запрет удаления, геометрия только по
  просьбе) над **файлами**; `core/sync.go` — сверка над **файлами** (`loadRegistry`/`save`).

## Шаги

Каждый шаг — отдельный коммит (или несколько), тесты зелёные на каждом. Go-тесты:
`GOTMPDIR=%LOCALAPPDATA%\Temp\semaps-gotest go test ./...`.

### 1. `core/model.go` — рабочее состояние в памяти

- `type Model` на один проект: манифест `project.json` и реестр (сущности, связи, типы, тексты по языкам — теми же
  упорядоченными `object`, что в `sync.go`, чтобы файлы писались с прежним порядком ключей) и виды
  (свойства вида, зоны, размещения, `relations`-политика), загружаемые лениво.
- `LoadModel(workspace, project)` — из файлов; `(*Model).Save()` — пишет файлы контракта всем,
  что изменено, тем же форматом (2 пробела, без HTML-экранирования, ключи в прежнем порядке).
- **Операция** `Op{Kind, ID, View, Value, Author}`: `Kind` ∈ `project`, `entity`, `relation`,
  `relationType`, `text` (ключ + язык), `view`, `zone`, `node`; `Value` — объект целиком или `null`
  (снятие зоны или размещения с вида; для реестра `null` запрещён — записи не удаляются, как и
  сейчас). `Author` — `human` или `agent`.
- `(*Model).Apply(ops []Op, author) (changed []Ref, err)` — атомарно: пачка применяется целиком
  или никак; проверки — правила из `core/edit.go` (шаг 2).
- **Несохранённое**: по каждому виду и по реестру — множество тронутых объектов и авторы.
  `(*Model).Dirty()` отдаёт сводку для «Сохранить».
- **Журнал** `<корень проекта>/.semaps/work/<project>.jsonl`: каждая применённая пачка — строка;
  `LoadModel` проигрывает журнал поверх файлов. `Save()` и «отменить всё» очищают журнал;
  `Discard(view)` / `Discard(registry)` — сбрасывают часть к файлам и переписывают журнал без неё.
  `.semaps/.gitignore` уже есть (логи MCP).
- Тесты: загрузка → операции → `Save()` даёт те же байты, что правка руками; порядок ключей
  сохранён; журнал переживает «перезапуск» (новый `LoadModel`); `Discard` вида и реестра; атомарность
  пачки; запрет `null` для реестра.

### 2. `core/edit.go` и `core/sync.go` — над моделью

- Функции `edit.go` (`SetText`, `AddRelation`, `AddRelationType`, `SetRelationVisible`,
  `ConfirmEntityRename`, `ConfirmRelationRename`, `PlaceEntities`) превращаются в построители
  операций над `*Model` + проверки; запись файлов из них уходит.
- Новое для агента в той же точке: `MoveNodes`, `ResizeZone` — **не делать здесь**, это следующий
  план; но `Op` для `node`/`zone` уже есть, редактор ими пользуется.
- `core.Sync(model, facts, opt)` меняет модель операциями с автором `agent`/`sync`, а не файлы;
  `--dry-run` — на копии модели. CLI `semaps sync` без запущенного хоста: `LoadModel` → `Sync` →
  `Save()` (как сейчас по результату).
- Тесты `edit_test.go`, `sync_test.go` переводятся на модель; поведение не меняется.

### 3. Хост: модель, API, события, ключ

Новый файл `host/model.go` (сервис: модели проектов в памяти, мьютекс на проект, рассылка).
`docs/API.md` — новый раздел «Модель» в том же коммите.

| Путь | Метод | Что |
|---|---|---|
| `/api/model/{project}` | `GET` | снимок: реестр целиком + свойства всех видов + несохранённое (`dirty`: по видам и реестру, с авторами) |
| `/api/model/{project}/views/{id}` | `GET` | геометрия вида: зоны, размещения, политика связей |
| `/api/model/{project}/ops` | `POST` | `{client, ops[]}` → `{changed}`; автор `human`; ошибка правила → 422 с текстом |
| `/api/model/{project}/save` | `GET` | сводка перед «Сохранить» |
| `/api/model/{project}/save` | `POST` | записать файлы, очистить журнал |
| `/api/model/{project}/discard` | `POST` | `{scope: "view", id}` \| `{scope: "registry"}` \| `{scope: "all"}` |
| `/api/events?project=` | `GET` | SSE: `{client, author, changed[], dirty}` на каждую пачку; клиент пропускает свои |

- **Ключ**: при старте хост пишет `.semaps/host.json` `{pid, port, key}`; всё, что меняет, и `/mcp`
  требуют `Authorization: Bearer <key>` (браузер получает ключ в странице, которую отдаёт хост).
  `sameOrigin` остаётся.
- `/api/save` для файлов проекта убирается; остаётся для `styles.json`, `templates.json`,
  `content/` и для создания проекта/вида (или переводится на операции — решить по ходу, записать в
  `API.md`). `/api/move` (переименование проекта/вида) — остаётся, но сбрасывает модель проекта из
  файлов после переноса (с несохранённым — отказ 409 «сначала сохраните»).
- По уточнению ADR: обычная правка `project.json` идёт `Op kind: project` и общим Save;
  создание/переименование проекта и вида остаются прямыми структурными операциями хоста только
  при чистой модели, затем модель перечитывается и всем подписчикам идёт `projectReloaded`.
- Тесты (`host/model_test.go`): снимок; ops → событие у второго подписчика; save/discard; 401 без
  ключа; 422 на нарушение правила.

### 4. Редактор на модели хоста

- `editor/src/editor/io/HostModelStore.ts` вместо `HttpProjectStore` для проектов: загрузка вида из
  снимка реестра (держится один на проект) + геометрии вида; тот же `WireDocument`, чтобы не
  трогать рисование и панели.
- **Синхронизация** (`editor/src/editor/io/ModelSync.ts`): после каждого завершённого действия
  (там же, где сейчас пишется снимок в `History`) — сравнить документ с последним подтверждённым
  **по объектам** и отправить изменившиеся объекты как ops. Промежуточные движения мыши не
  отправляются — только результат действия.
- **Входящие события**: применить объекты к документу без записи в `History`, перерисовать. Если
  событие трогает объект, который пользователь сейчас тащит, — применить после отпускания.
- `History` (Undo) остаётся в окне, по виду, для своих действий; после «отменить несохранённое»
  или смены вида из события история вида очищается.
- «Сохранить» (`file.save`, QAT): `GET save` → если есть изменения агента, модальное окно-сводка
  «ваши: …; агент: …» → «Сохранить всё» / «Отмена»; иначе сразу `POST save`.
- «Отменить несохранённое»: команды в рибоне (группа «Файл») — для вида и для реестра; с
  подтверждением.
- Переключение видов без вопроса «сохранить?»; значки в каталоге (`CatalogPanel.ts`): у вида —
  точка с автором (вы / агент), строка «Реестр: изменено N».
- Подсветка по ссылке: `#<view>?highlight=<id,id…>` открывает вид и выделяет объекты.
- Несколько окон: второе окно того же проекта получает события и живёт синхронно.
- `WorkspaceStore.ts` правит поля манифеста операцией `project`; создание и переименование
  вызывают структурные операции хоста, обрабатывают 409 и `projectReloaded`.
- `tsc` чисто, сборка зелёная; проверка в браузере — шаг 7.

### 5. MCP по HTTP и stdio-прокси

- `host`: Streamable HTTP-хендлер SDK на `/mcp` в том же процессе, над тем же сервисом моделей;
  инструменты `host/mcp.go` работают через `*Model` (шаг 2), автор `agent`. Журнал вызовов
  (`host/mcplog.go`) — как есть.
- `semaps mcp` (stdio): читает `.semaps/host.json`; хост не отвечает — запускает `semaps --here
  --no-browser` в фоне (detach, как `install`/`run`), ждёт порт; дальше пересылает JSON-RPC между
  stdio и `/mcp` с ключом. Режима «напрямую по файлам» больше нет.
- Новый инструмент `save` (только с `requestedByHuman: true`) и `discard`. Каждый пишущий
  инструмент в ответе: «не сохранено» + ссылка из шага 4 на тронутые объекты.
- Песочница редактора (`/api/mcp/call`) идёт через тот же `/mcp`-сервер процесса.
- Тесты: прокси поднимает хост и отвечает; вызов агента → событие в SSE; `save` без
  `requestedByHuman` — отказ.

### 6. Документы

- `docs/API.md`: раздел «Модель» (шаг 3), `/mcp`, ключ; §6 — транспорт и `save`/`discard`.
- `docs/ADOPTING.md`: `.mcp.json` не меняется; хост поднимается сам; «сделал, не сохранено —
  проверьте» и ссылка; сохраняться перед заданием агенту.
- `docs/LAYOUT.md`: агент меняет геометрию через модель, результат виден сразу, сохраняет человек.
- `README.md`: коротко про рабочее состояние и «Сохранить».

### 7. Проверка на NeuroModFlowNet.ONNX

Руками и скриптом, результат — в этот план:

1. Открыть вид, подвинуть блок, F5 — блок там же, значок «не сохранено» на месте.
2. Второе окно того же вида — движение в первом видно во втором.
3. Агент (Claude Code, `.mcp.json` проекта) `set_text` на сущности — описание сразу видно на
   открытом виде; «Реестр: изменено 1».
4. Агент ставит блок (`place_entities`, по просьбе) — блок появляется на экране без F5.
5. «Сохранить» — сводка показывает правки агента; после — файлы в git diff, журнал пуст.
6. «Отменить несохранённое» у вида — геометрия вернулась к файлу, реестр не тронут.
7. Закрыть всё, запустить агента без открытого редактора — `semaps mcp` поднимает хост сам.
8. `install.cmd` при запущенном хосте и сессии агента — убивает, после перезапуска сессии всё
   работает, несохранённое поднято из журнала.

## Не входит

- Инструменты раскладки (`get_view`, ссылка, «разложи по образцу», move/resize) — следующий план.
- Undo в хосте, отмена команд агента, слияние полей — отвергнуто в ADR.
- Несколько людей на одном хосте, права — позже, на том же ключе.
- Перевод `styles.json`, `templates.json`, `content/` в модель.
