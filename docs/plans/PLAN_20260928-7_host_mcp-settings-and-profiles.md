# PLAN_20260928-7_host — Настройки MCP, наборы инструментов, описания, отметки слепых мест

Статус: **выполнен** — шаги 1–7 сделаны. Опыт по профилям — отдельный план, не начат.
Решения: [`ADR_20260928-5`](../adr/ADR_20260928-5_extractors_only-unambiguous-facts.md),
[`ADR_20260924-5`](../adr/ADR_20260924-5_host_mcp-server.md). Откуда взялось: повторный опыт,
[`PLAN_20260928-5`](PLAN_20260928-5_host_graph-answers-for-agents.md) шаги 4 и 6.

## Зачем

Повторный опыт показал, что большая часть ошибок агентов — от невнятного описания, а не от
графа. Описание инструмента `get_graph` в коде устарело (называет удалённый параметр `set`,
ссылается на файл ADR, которого у агента нет) и не содержит ни одного примера. Порог обрезки
списков (5 имён, 8 строк) резал обычную фабрику с 14 методами.

## Шаги

### 1. Раздел `mcp` в файле `.semaps`

Сделано: `host/projectfile.go` — `mcpSettings`, умолчания, `validateMcp`, `patchMcp` (правит
дерево YAML, комментарии и порядок ключей сохраняются, как у `extractors:`).

```yaml
mcp:
  tools: one            # one | narrow
  description: standard # brief | standard | full
  format: facts         # формат ответа по умолчанию
  list_cap: 50          # сколько имён и строк одной связи печатать до «+N»
  limit: 200            # сколько узлов в ответе без around и container
```

Все ключи необязательны, значения выше — умолчания. `list_cap` и `limit` остаются и
параметрами запроса: запрос сильнее настройки. Хост правит файл через дерево YAML, комментарии
и порядок ключей сохраняются.

### 2. Настройки действуют сразу

Сделано: `host/mcp_settings.go` — `mcpSettingsBox` (один общий объект, за блокировкой чтения-записи)
держит `mcp:` в памяти; `PUT /api/setup` правит файл и тут же зовёт `Set`, так что и HTTP-обработчик
графа, и MCP-сервер видят новые `format`/`list_cap`/`limit` со следующего вызова — без перезапуска.
Смена набора инструментов/описаний (шаг 4) не сделана — ключи `tools`/`description` пока только
хранятся.

`GET`/`PUT /api/setup` несут раздел `mcp`. Формат, порог и предел — со следующего вызова.
Набор инструментов и описания — хост пересобирает список и шлёт подключённым клиентам
уведомление протокола о смене списка инструментов; перечитает ли клиент список посреди сеанса,
решает клиент. В новом сеансе настройка действует всегда.

### 3. Правки по повторному опыту

Сделано: все шесть правок ниже, в `core/graph_template.go`, `core/graph_format_text.go`,
`core/graph_filter.go` (`LiftNoneHint`) и `core/graph_format.go`.

- Список строк и имён режется по `list_cap`, не по 5 и 8.
- Отметка об обрезке (`limit`, `fanout`, `list_cap`) — первой строкой текстового ответа.
- Сборка в строке узла формата `facts`.
- Тип, спрошенный с `lift=none`, у которого связей нет, а у его методов есть: ответ говорит об
  этом и называет, как спросить.
- Строка счёта называет число типов и число методов отдельно, а не только «узлов».
- Комментарий «временно» у `DefaultToolFormat` убрать.

### 4. Две оси: набор инструментов и подробность описаний — сделано

Тексты трёх уровней для `get_graph`/`find_node`/`graph_formats` и десяти узких инструментов —
в `host/mcp_descriptions.go`, простыми строками. Узкие инструменты — тонкие обёртки над тем же
`getGraph`, которым пользуется и `get_graph` (`narrowWalk`), так что второй копии правила нет.
Набор и уровень меняются PUT `/api/setup` немедленно: `mcpSettingsBox.OnChange` дёргает
`mcpServer.rebuildGraphTools`, которая зовёт `Server.RemoveTools`/`AddTool` официального SDK на
том же `*mcp.Server`, что и обслуживает все сессии `/mcp` — оба метода сами шлют
`notifications/tools/list_changed`. Живая сессия увидит новый список, когда клиент в следующий
раз спросит `tools/list` (SDK не даёт способа подменить список у сессии без этого): новая сессия
видит его всегда. Прокси `semaps mcp` копирует список инструментов один раз при старте и не
следит за его сменой — агенту, работающему через прокси, после смены `tools`/`description`
нужен новый запуск `semaps mcp` (перезапуск сессии агента), это задокументировано в API.md §6.
`/api/mcp` дополнительно отдаёт `mcpTools`/`mcpDescription` (текущие настройки) и `combos` — все
шесть сочетаний с полным текстом описаний и размером в байтах и в оценке токенов (шаг 5 саму
страницу ещё не строит).

**Набор `one`** — `get_graph`, `find_node`, `graph_formats`, как сейчас.

**Набор `narrow`** — узкие инструменты с одним обязательным параметром `name` и необязательным
`depth`; внутри — тот же граф с заданным `follow`:

| Инструмент | `follow` |
|---|---|
| `who_extends` | `extended-by`, `implemented-by` |
| `what_it_extends` | `extends`, `implements` |
| `who_holds` | `held-by`, `injected-into` |
| `what_it_holds` | `holds`, `injects` |
| `who_calls` | `called-by` |
| `what_it_calls` | `calls`, `constructs` |
| `where_created` | `constructed-by` |
| `what_is_inside` | `contains` |
| `where_it_lies` | `inside` |
| `find_node` | — |

**Описания** — три уровня для каждого инструмента обоих наборов, в одном файле
`host/mcp_descriptions.go`, текстом, а не сборкой из кусков:

| Уровень | Что в нём |
|---|---|
| `brief` | что делает, одна-две строки, один пример |
| `standard` | что делает, основные параметры, примеры «вопрос → запрос», как читать строку ответа |
| `full` | всё: словарь связей, `lift`, `fanout`, язык шаблонов, разрешение имён |

Описание не ссылается на файлы репозитория SeMaps и не называет того, чего нет.

Правка: то, что было общим для всех инструментов графа — как читать строку `facts`, ловушки —
сказано один раз в `Instructions` сервера (`serverInstructions`, `host/mcp_descriptions.go`), а не
в каждом инструменте; у узких инструментов описание называет только их собственные параметры
(`name`, `depth`). Размер (байты, `/api/mcp`) теперь считает и `Instructions`. Было → стало:
`one/brief` 3291→3462, `one/standard` 7406→7832, `one/full` 11779→13130, `narrow/brief`
3886→2602, `narrow/standard` 25277→6197, `narrow/full` 30046→8499.

### 5. Страница настроек

На странице MCP редактора: выбор набора и уровня, формата, порогов; рядом — точный текст,
который получит агент, и его размер в байтах и в оценке токенов. Сохранение — через
`PUT /api/setup`, действует по шагу 2.

Сделано: раздел «Настройки для агента» на странице MCP (`editor/src/app/mcpSettings.ts`).
Проверено в браузере на пробном проекте: выбор меняет пример и размеры без запроса к хосту;
сохранение пишет раздел `mcp` в файл `.semaps`, остальные ключи файла целы; после перезагрузки
страница показывает сохранённое. По ходу найдено и исправлено: `/api/setup` отдавал раздел
`mcp` с именами полей `Tools`, `ListCap` вместо `tools`, `listCap`.

Сделано и по шагу 6: отметки печатает извлекатель C#, несёт граф, показывают форматы
(`{dynamic: create @57 in CreateRunner}`); сверка их не видит — тест на совпадение реестра.

### 6. Отметки слепых мест в извлекателе C#

Метод получает список `dynamic: [{kind, line}]` для вызовов базовой библиотеки платформы из
короткого списка (ADR_20260928-5 §3): создание через `Activator`, вызов через
`MethodInfo.Invoke` и `Delegate.DynamicInvoke`, построение типа `MakeGenericType`, получение
типа по строке `Type.GetType`, ключевое слово `dynamic`. Цели у отметки нет. Узнаётся
смысловой моделью, не текстом. В графе — поле узла; при подъёме на уровень типа отметки
методов собираются у типа с именем метода. В строке `facts` — в фигурных скобках после связей.
Сверка отметок не видит.
