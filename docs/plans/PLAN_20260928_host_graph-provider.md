# PLAN_20260928_host — Поставщик графа: факты и модель одним ответом

Статус: **шаги 1–7 сделаны** — замер на NeuroModFlowNet.ONNX ниже.
Решение: [`ADR_20260928`](../adr/ADR_20260928_host_live-code-graph.md).

## Зачем

Странице графа и агентам нужен один граф: символы и рёбра кода, соединённые с сущностями и
контейнерами модели. Сейчас факты лежат файлом во временной папке и читаются только сверкой.

## Шаги

Каждый шаг — отдельный коммит, тесты зелёные. `docs/API.md` правится в том же коммите, что и
адрес или инструмент.

### 1. Граф в `core/` — сделано

- `core/graph.go`: `Graph{Nodes, Edges}` и сборка из `[]*Facts` и `*Model`.
- Узел: `id`, `symbol`, `kind`, `nativeKind`, `name`, `namespace`, `visibility`, `file`, `line`,
  `language`, `extractor`, `entity` (id сущности или пусто), `status`, `containers`, `presence`
  (`both` | `code` | `model`).
- Ребро: `from`, `to`, `kind`, `via`, `relation` (id связи реестра или пусто), `presence`.
- **Ключ узла.** В один проект модели могут писать несколько извлекателей (`.semaps` →
  `extractors[].project`). Проверить, могут ли совпасть `id` символов разных языков; если да —
  ключ узла `<extractor>:<symbol>`.
- Узлы «только в модели»: сущности без символа в фактах. Рёбра «только в модели»: авторские связи.
- Тесты: три рода узлов; два извлекателя в один проект; сущность `missing`.

### 2. Принадлежность контейнеру — сделано

- `core/containers.go`: порядок из `CONTRACT.md` §6 — `overrides` → `match.name` →
  `match.nameRegex` → `match.path` (длиннейший префикс) → сосед по файлу.
- Сущность может состоять в нескольких контейнерах — поле узла `containers` это список.
- Узел «только в коде» получает контейнер по тем же правилам (`name`, `file`): так видно, куда
  он лёг бы.
- Тесты на каждое правило и на порядок.

### 3. Служба графа в хосте — сделано

- `host/graph.go`: `graphService`, по проекту модели — последние факты каждого его извлекателя.
- При первом запросе читает `facts.json` последнего **успешного** прогона каждого извлекателя.
  Прогонов нет — граф из одних узлов модели и признак `facts: none` в ответе.
- После завершения прогона (`runStore.start` → `finish`) служба берёт новые факты.
- Граф собирается при чтении из фактов и текущего рабочего состояния модели. Кэш и индексы — по
  замеру (ADR §9).

### 4. API — сделано

- `GET /api/graph/{project}` → `{nodes, edges, facts: [{extractor, run, finished}], stats}`.
- Параметры: `level` (`types` — без `function` и `value`; `all`), `kinds` (виды рёбер),
  `around` (id узла) и `depth`, `container`, `fields` (`members`, `via`, `position` — по
  умолчанию без `members`).
- Адрес только для чтения; при `--workspace` без файла `.semaps` — как остальные адреса §5.
- Тесты: каждый параметр; объём ответа на копии NeuroModFlowNet.ONNX записать в план.

### 5. События — сделано

- Новые факты → событие подписчикам `/api/events`. Форму выбрать так, чтобы нынешний редактор,
  не знающий о графе, её пропускал: проверить разбор в
  `editor/src/editor/io/HostModelStore.ts`.
- В событии — что изменилось (добавленные, убранные, изменённые узлы и рёбра), а не весь граф.

### 6. MCP — сделано

- `get_graph` (чтение): те же параметры, что у адреса; по умолчанию `around` обязателен или
  стоит `limit`, чтобы агент не получил весь граф случайно.
- Ответ — объект (`structuredContent`), как у остальных инструментов.
- Строка в `docs/API.md` §6 и в `docs/ADOPTING.md`: когда агенту звать `get_graph`, а когда
  `get_relations`.

### 7. Проверка на NeuroModFlowNet.ONNX

Время сборки графа, объём ответа целиком и для окрестности одного узла, число узлов каждого
рода. Результат — в этот план.

### Результат проверки (шаг 7, 2026-09-28)

Хост — сборка ветки `live-graph` (бинарник `semaps.exe` из окружения агента, не пересобирался в
этой сессии). Экстрактор C# — свежий `dotnet publish` из этого коммита (в
`extractors/csharp/…/bin,obj` — игнорируемый мусор сборки). Проект — рабочая копия
`C:\GitKOE\NeuroModFlowNet.ONNX` (с незакоммиченными правками, только на чтение), измерительный
`.semaps` лежит вне неё, в `SeMaps/.claude/nmfn-measure/measure.semaps` (`workspace` и
`source_root` указывают в `NeuroModFlowNet.ONNX`, порт 8795, extractor `command` — путь к
опубликованному бинарнику; `watch` не задан). Хост поднимался фоновым процессом
`semaps.exe --here --no-browser --port 8795 …` и был остановлен после замеров; порт 8795
свободен, модель нигде не редактировалась, `<workspace>/.semaps` не появился.

**G. Токенная арифметика для окрестности depth=1 узла D.** Ответ депth=1 — 150 331 байт.
В нём 187 уникальных файлов; сумма размеров этих файлов на диске — 334 345 байт.
Отношение ответ/исходники — 0,45 (то есть JSON-ответ примерно вдвое компактнее, чем пришлось бы
прочитать агенту исходники всех затронутых файлов целиком, притом что депth=1 даёт куда более
узкий срез — не всё содержимое файла, а только связи символа).

**H. Что проверено на аномалии:**

- Дубликаты id символов/узлов — не найдено (0).
- Рёбра, указывающие на отсутствующий узел, — не найдено ни в фактах (405 символов), ни в графе
  (405 узлов) — `from`/`to` каждого ребра резолвится.
- Символы без `endLine` — 18 из 405, все — `module` (`namespace`/`assembly`): у них по контракту
  нет диапазона строк как у типа/члена, это ожидаемо, не дефект.
- Узлов с присутствием `model` (сущность без символа в фактах) не нашлось вовсе — все 405 узлов
  `both`. То есть в этом проекте реестр модели полностью соответствует извлечённому коду; не
  проверено, есть ли вообще узлы `code`-only или `model`-only на других сочетаниях `fields`/
  `level` — на всех снятых срезах presence не менялось.
- `fields=` (пусто) не отличимо от «параметр не передан» — см. C.

**Что не измерялось:**

- Сеть/latency `GET` через реальный TCP не проверялась отдельно от localhost — все запросы шли на
  `127.0.0.1`, реального сетевого расстояния не было.
- Повторный прогон окрестности глубины 1 после «прогрева» не выделен статистикой отдельно от
  первого захода — см. отступление в D.
