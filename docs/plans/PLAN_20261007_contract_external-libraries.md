# PLAN_20261007_contract — Внешние библиотеки и их связи

Статус: **закрыт**.

Запрос: внешние типы должны быть объектами карты, с возможностью раскрыть их связи и всю
выбранную библиотеку. Большие внешние реестры хранятся отдельно от собственных.

Согласовано с чатом «Оценить плагин SeMaps для IDE»: собственные C# TypeId не меняются;
единый helper ExternalTypeId доступен плагину; working bundle объединяет все сущности.
Этот план не включает изменения VSIX, IDE bridge и их файлов.

- [x] Единый реестр в памяти, отдельные файлы библиотек и граничных связей; Save/Discard/journal.
- [x] Принадлежность библиотеке отдельно от настоящего kind; область сверки внешних данных.
- [x] C# metadata: used, выбранный тип с depth, полная выбранная сборка; внешние структурные связи.
- [x] Настройки запуска в .semaps и API, нормативные документы и проверка.

Проверено: `go test ./...`; C# `dotnet test` — 37 тестов, включая исходный golden;
`npm run build:app` (typecheck включён), 20 model-sync и 12 IDE bridge checks.
Тесты библиотек покрывают межбиблиотечные связи, pointer, циклы, depth, private/internal,
неиспользуемые и вложенные типы, одинаковые имена из разных DLL; Go — отдельные файлы,
повторную загрузку journal, Save/Discard, частичное покрытие, смену версии, общий граф,
повреждённые файлы и отказ атомарной операции. Своя правка не переписывает неизменённую DLL-сущность.
Соседний чат подтвердил совместимость; metadata navigation/pick в первой версии VSIX отсутствует.

Вызовы внутри DLL из IL не входят в этот этап. Методы и calls остаются слоем живого графа.
Коммиты и публикация этим запросом не разрешены.
