# PLAN_20261007_editor — Универсальный мост IDE и плагин Visual Studio

Статус: **в работе** — собран и проверен первый VSIX-прототип, автозапуск host работает.
Проверены окно SeMaps, транспортный handshake и нативный drag в Experimental Instance.
Универсальные команды редактора и сопоставление символов пока не реализованы.

## Цель и границы

Открывать существующий SeMaps в окне IDE, связывать выбор на карте с исходниками и
перетаскивать выбранные символы на карту. Первый плагин — Visual Studio; контракт
сразу проверяется на вариантах Visual Studio, VS Code и обычного браузера.
Реализация плагина VS Code в этот план не входит.

Главное ограничение пользователя: сам SeMaps меняется минимально. В нём только
необязательный универсальный мост вокруг существующих операций редактора.
Разбор перетаскивания, Roslyn, выбор проекта/файла, диалоги и работа с IDE — в плагине.
Не меняются формат workspace, правила извлечения и владение рабочей моделью.
Плагин не пишет файлы workspace: размещение проходит через редактор и текущий host.

## Единый контракт v1

Контракт определяет смысл сообщений отдельно от транспорта. В первой реализации:
WebView2 JSON-сообщения; второй транспорт проверяется iframe/postMessage-стендом.
Логику протокола нельзя связывать с `window.chrome.webview` напрямую: это деталь адаптера.
HTTP/SSE host остаются транспортом модели, новый параллельный сервер не создаётся.

### Общая оболочка

- `protocol`, `version`, `sessionId`, `id`, `kind`, `method`, `params`.
- Ответ с `requestId` и ровно одним `result` или `error`.
- `origin` и `causationId` для связи событий и подавления циклов выбора.
- Handshake объявляет поддерживаемые методы/события и текущий контекст.
- Правила несовместимых версий, необязательных полей, неизвестных методов, таймаута,
  отмены, повторного подключения и закрытия сессии фиксируются сразу.
- Повтор доставленного запроса размещения не должен повторять изменение модели.
  Для завершённых запросов хранится ограниченный кэш ответов в пределах сессии.
  После разрыва с неизвестным результатом клиент сначала перечитывает состояние.

### Контекст и адреса

- Разделять SeMaps project, IDE project и корень исходников; они не равнозначны.
- У каждого запроса явный контекст проекта; команды карты указывают `viewId`.
- Различать идентификатор символа, узла графа, сущности модели и размещения.
- Адрес исходника: язык, идентификатор символа по правилам SeMaps, контекст исходников,
  относительный путь и необязательный диапазон. Абсолютные локальные пути нормализует плагин.
- Зафиксировать слэши, регистр идентификаторов, правила сравнения путей, базу строк/колонок,
  UTF-16 позиции, конец диапазона и отсутствие доступного файла.
- При нескольких объявлениях/реализациях возвращать кандидатов; не брать первый молча.
  Символ устойчив к сдвигу строк, но после переименования может сменить id.

### Команды IDE → SeMaps

| Метод | Смысл |
|---|---|
| `bridge.initialize` | Версия, возможности, установка сессии |
| `context.get` | Текущий project/view/mode и доступные операции |
| `symbols.resolve` | Нормализованные символы/позиции → кандидаты в графе, сущности, размещения |
| `selection.set` | Выбрать/снять выбор; поддержать массив объектов и основной объект |
| `entities.reveal` | Показать существующее размещение или символ в графе; карту не менять |
| `entities.place` | Разместить существующие сущности в указанном view через обычный Undo/host |

Названия — исходный список для согласования шага 1. Управление контекстом и режимом
должно быть явным: смена вкладки/карты не превращает отложенный запрос в запись в другую карту.
Для `entities.place` передаются ids, точка и контекст; редактор перечитывает текущие сущности.
Произвольные JSON сущности, текст исходника и нативный drag payload команда не принимает.

### События/запросы SeMaps → IDE

| Сообщение | Смысл |
|---|---|
| `context.changed` | Смена карты/проекта/режима, инвалидирование старого контекста |
| `selection.changed` | Выбранные объекты и доступные привязки к коду |
| `source.open` | Открыть конкретную привязку; IDE сообщает успех/отказ |
| `bridge.disconnected` | Закрытие связи, отмена ожидающих операций |

Без подключённого адаптера остаётся существующий просмотр кода и обычный браузерный UI.
Выбор не означает открытие файла и не означает размещение. Автослежение включается настройкой
плагина; входящее выделение не возвращается в IDE как новое пользовательское действие.

### Результаты и состояния

Возвращать отдельный результат по каждому входному символу/сущности:
`resolved`, `ambiguous`, `notFound`, `notInModel`, `alreadyOnView`, `unsupported`,
`staleContext`. Общий ответ различает валидацию запроса, закрытую сессию и ошибку выполнения.
Свежесть графа сообщается только в пределах того, что текущий host действительно знает;
не выдавать отсутствующий символ за доказательство устаревшего графа.

`notFound` и `notInModel` требуют разных действий:

- Нет символа в графе — проверить охват extractor и предложить извлечение фактов.
- Символ есть в графе, entity нет — предложить существующую сверку модели.
- Entity есть, размещения нет — можно разместить.
- Уже на карте — выделить существующий блок, вернуть `alreadyOnView`.

Извлечение/сверка не выполняются как скрытый побочный эффект выделения или drop.
После выбранного пользователем обновления повторно разрешить символы и проверить view.

### Координаты и перетаскивание

Плагин принимает drag, через Roslyn разбирает файлы/символы и показывает неоднозначный выбор.
Для файла с несколькими типами — выбор типов; для нескольких файлов — пакет кандидатов.
Partial-декларации одного символа объединяются. Несохранённый буфер может расходиться
с графом host: это явно показывается в результате сопоставления.

В протоколе различать клиентскую точку WebView в CSS-пикселях и точку модели карты.
Преобразование client → model выполняет редактор. При запросе клиента обязательно задавать
систему координат; нативные экранные пиксели и DPI нормализует транспорт плагина.
Drop сохраняет исходный view и точку до диалога; смена view/сессии требует нового подтверждения
назначения, а не размещения в случайной карте. Нативный payload остаётся внутри плагина.

## Порядок реализации и контрольные результаты

1. **Зафиксировать контракт.** Уточнить схемы/поля/ошибки выше, подготовить examples и fixtures
   в `plugins/protocol/`. Прогнать сценарии VS, VS Code-стенда и браузера. Результат:
   одна спецификация и перечень возможностей без команд с префиксом конкретной IDE.
2. **Проверить риск UI и SDK отдельно.** После подготовки workload создать минимальный VSIX
   в `plugins/visual-studio/`: WPF ToolWindow, WebView2, JSON round-trip, приём drag из
   Solution Explorer и измерение точки. Сборка настоящего `.vsix`, запуск в Experimental
   Instance. На этом шаге карта не меняется; реальный drag проверяется до полного моста.
3. **Реализовать минимальный мост редактора.** Dispatcher, проверка схем, context, события
   выбора, открытие кода через адаптер с браузерным fallback, resolve/reveal/place вокруг
   текущих методов. `core/` не меняется; `host/` менять только при доказанном пробеле
   существующего API и после отдельного обоснования. Нормативный `docs/IDE_BRIDGE.md`
   появляется вместе с реализацией; `docs/API.md` меняется только при изменении host API.
4. **Подключить реальный проект.** Только при ручном открытии карты или Reconnect найти `*.semaps`
   рядом с solution или в ближайшем родительском каталоге; при одном файле автоматически
   подключить/поднять сервер, при нескольких предложить выбор. Проверять также solution,
   уже открытый к моменту загрузки плагина. Отсутствие файла не запускает сервер.
   прочитать существующий адрес host и проверить соответствие выбранному проекту.
   Подключиться к существующему процессу или запустить установленный `semaps` с текущими
   флагами без браузера. Обработать устаревший host.json, занятый порт и отсутствие exe.
   Открытие solution ничего не запускает и не показывает, загрузки пакета по solution нет.
   Только по команде пользователя открыть существующий `/app/` в WebView2.
   Не останавливать общий host при закрытии IDE.
5. **Карта → студия.** Выбор сущности выделяет файл в Solution Explorer при включённом
   слежении; `source.open` открывает нужную декларацию/строку. Несколько кандидатов —
   выбор, внешний символ без файла — понятный результат. Сохранить поведение браузера.
6. **Студия → карта.** Roslyn symbol из текущего буфера → id по правилам extractor → resolve
   → reveal/select. Проверить типы, generic/nested/partial, перегрузки и несколько проектов
   с совпадающими именами. Методы/свойства без entity можно показывать в графе; заменять
   их содержащим типом только по явному выбору, не молча. Проверить цикл событий.
7. **Перетаскивание и выбор действия.** Нативный drag разбирается исключительно в плагине.
   Диалог: найденные символы, доступные entity, уже размещённые, требующие сверки.
   После выбора отправляется нормализованная `entities.place`; пакет — один Undo.
   Проверить zoom/DPI/scroll, диалог со сменой карты, несколько файлов и закрытие сессии.
8. **Совместимость и поставка.** Одинаковые fixtures на адаптерах WebView2 и postMessage;
   неподдерживаемая версия/метод, reconnect, повторы, невалидный payload. Собрать Release
   VSIX, описать установку/обновление и требования. Финальный отчёт: какие IDE реально
   запускались, какой artifact собран и что осталось непроверенным.

Сопоставление C# не связывать с исполняемым `net10.0` extractor напрямую: плагин `net472`.
На шаге 6 проверить возможность переиспользовать небольшой SymbolIds source с совместимыми
зависимостями; в любом случае общие тестовые примеры должны обнаруживать расхождение
плагина и extractor. Несовместимость не является основанием менять правила symbol id.

После каждого этапа — конкретный отчёт: изменённые файлы, полученное поведение,
выполненные проверки, ограничения и следующий этап. Коммиты/push — только по отдельному
запросу пользователя в соответствующем сообщении, согласно `AGENTS.md`.

## Проверки

- Протокол: валидация fixtures, версия/capabilities, корреляция, отмена, защита от циклов
  и повторного размещения; два transport adapter используют одни примеры.
- Редактор: typecheck/build; реальные проверки resolve и placement, дублей/Undo,
  отсутствующих entity, устаревшего context; обычное открытие в браузере.
- Плагин: нормализация путей/диапазонов, id совпадают с extractor, кандидаты не теряются;
  Debug/Release сборка и содержимое `.vsix`.
- Live VS: Experimental Instance, открытие карты, оба направления навигации, drag,
  несколько проектов, смена view во время диалога, DPI и перезапуск host.
- Безопасность моста: фиксированные методы, валидация сообщений, доверенный origin
  страницы, пути в пределах выбранного корня; без произвольного eval/запуска команд.
- Go checks — если реально изменён Go-код. Полную сборку SeMaps проверять при интеграции
  редактора в host. Одного успешного build недостаточно для подтверждения live VS UI.
