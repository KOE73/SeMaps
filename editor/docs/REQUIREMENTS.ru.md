# SeMaps Editor — реализованные требования

**Статус:** базовая спецификация, восстановленная из работающей реализации.
**Архив.** Срез однофайлового редактора до переезда на TypeScript (`docs/diagrams/index.html` на коммите `42197c9` исходного репозитория, здесь его нет). Хранится как история; действующий контракт — [`docs/CONTRACT.md`](../../docs/CONTRACT.md).
**Английская версия:** [`REQUIREMENTS.md`](REQUIREMENTS.md) — те же идентификаторы, держится в синхроне.

## 0. Зачем этот документ

Это **не** предложение по дизайну. Здесь записано, что текущая реализация
делает на самом деле, чтобы миграцию на TypeScript/ESM/Vite можно было
сверять с написанным, а не с памятью.

Каждое утверждение ниже — одно из трёх:

- **`R-*` — требование.** Реализовано, сделано намеренно, должно пережить миграцию.
- **`D-*` — дефект.** Реализовано, но неправильно. Воспроизводить **нельзя**;
  рядом указано, как должно быть.
- **`Q-*` — открытый вопрос.** Поведение есть, но замысел неясен; нужно решение,
  прежде чем сохранять его или выбрасывать.

Идентификаторы требований стабильны, на них ссылаются коммиты миграции и тесты.

## 1. Термины

| Термин | Значение |
| --- | --- |
| **Модель** | Одна диаграмма, сериализованная в один JSON-документ. |
| **Узел** (node) | Листовой элемент холста — класс, компонент, сервис, заметка. |
| **Зона** (zone) | Прямоугольный контейнер, несущий архитектурный смысл (подсистема, граница, зона безопасности). |
| **Связь** (edge) | Направленное соединение двух узлов. |
| **Вид** (view) | Именованный пресет подсветки, гасящий всё за пределами своего предмета. |
| **Каталог** | Список моделей, предлагаемых в левой панели. |
| **Холст** (canvas) | SVG-поверхность: рендер, вьюпорт, прямое манипулирование. |
| **Редактор** (editor) | Приложение целиком: холст плюс тулбар, инспектор, каталог, история, сохранение. |

## 2. Контракт данных (`R-MODEL`)

JSON-контракт на время миграции **заморожен**. Он описан здесь как наблюдаемый,
а не как желаемый.

### R-MODEL-01 — Корень модели

Модель — JSON-объект с необязательными членами `metadata`, `views`, `zones`,
`nodes`, `edges`. Любая коллекция необязательна; отсутствующая считается пустой.
Ни один член при загрузке не валидируется.

### R-MODEL-02 — `metadata`

`metadata.title` (строка) — отображаемый заголовок. `metadata.layout` (строка)
объявляет вариант компоновки (`semantic-atlas`, `message-flow`,
`subsystem-overview`). Редактор потребляет только `title`; `layout` потребляют
внешние инструменты.

### R-MODEL-03 — Зона

```
id           string    обязателен, уникален
name         string    подпись в шапке
type         string    семантический тип (boundary, subsystem, security-zone, storage-zone, component)
semanticId   string    устойчивый семантический адрес, напр. "zone.core.runtime"
tags         string[]  свободные метки
x, y         number    левый верхний угол, координаты модели
width        number
height       number
style        object    fill, stroke, strokeWidth, strokeDasharray, headerBg
metadata     object    description, responsibilities[]
```

### R-MODEL-04 — Узел

```
id           string    обязателен, уникален
label        string    отображаемая подпись
type         string    визуально-семантический тип, см. R-REND-07
zone         string?   id явно указанной родительской зоны либо null
x, y         number    левый верхний угол, координаты модели
width        number
height       number
tags         string[]
metadata     object    type (текст подписи), description, codeRef, responsibilities[]
```

`metadata.type` — свободный текст подзаголовка, это **не** то же поле, что `type`.

### R-MODEL-05 — Связь

```
id     string    обязателен, уникален
from   string    id узла-источника
to     string    id узла-приёмника
label  string    необязательная подпись в середине
type   string    семейство маршрутизации/оформления, см. R-REND-11
```

Связи соединяют **только узлы**. Связь, ссылающаяся на отсутствующий узел,
молча пропускается при отрисовке.

### R-MODEL-06 — Вид

```
id              string
name            string    подпись кнопки
icon            string    эмодзи, по умолчанию 🔹
description     string    подсказка кнопки
highlightZones  string[]  необязательно
highlightNodes  string[]  необязательно
```

### R-MODEL-07 — Координаты абсолютны

Все `x`/`y` — абсолютные координаты модели. Вложение узла в зону **не** делает
его координаты относительными. В относительные их переводит только экспорт в
Draw.io (R-IO-07).

### R-MODEL-08 — Никакого авто-лейаута

Редактор никогда не вычисляет и не поправляет позицию, которую задал человек
или генератор. Координаты меняются исключительно как прямой результат жеста
перетаскивания или изменения размера. Это основополагающее ограничение всего
инструмента.

## 3. Каталог (`R-CAT`)

### R-CAT-01 — Источник

Каталог читается из глобального `window.SEMAPS_CATALOG`, который заполняет
отдельный `catalog.js`, загружаемый перед скриптом приложения.

### R-CAT-02 — Форма записи

`{ id, file, title, subtitle, icon, theme }`. `theme` — одно из `blue`,
`emerald`, `indigo`, `amber`, влияет только на подсветку иконки при наведении.

### R-CAT-03 — Автозагрузка

При старте первая запись каталога выбирается и загружается автоматически.

### R-CAT-04 — Загрузка модели

Выбор записи выполняет `fetch(entry.file)` относительно страницы и загружает
разобранный JSON как активную модель.

### R-CAT-05 — Отрисовка панели

Каждая запись рисуется кнопкой с иконкой, заголовком и подзаголовком. Активная
запись визуально выделена. Кнопки имеют DOM-id `schema-nav-<id>`.

## 4. Рендеринг (`R-REND`)

### R-REND-01 — Порядок слоёв

Холст содержит ровно четыре SVG-группы внутри одной трансформируемой группы
вьюпорта, в порядке наложения: **зоны → связи → узлы → ручки размера**. Связи
рисуются под узлами, чтобы линии уходили под блоки, которые они соединяют.

### R-REND-02 — Полная перестройка

Отрисовка очищает все четыре слоя и пересоздаёт каждый элемент из модели.
Частичного или инкрементального обновления не существует.

### R-REND-03 — Тело зоны

Скруглённый прямоугольник (`rx=12`) по геометрии зоны, заливка и обводка из
`zone.style`, по умолчанию заливка `#f8fafc`, обводка `#cbd5e1`, толщина `2`.

### R-REND-04 — Шапка зоны

Скруглённый прямоугольник высотой **34** во всю ширину зоны, заливка из
`style.headerBg` (по умолчанию `#e2e8f0`). Шапка — ручка перетаскивания зоны
(R-EDIT-02).

### R-REND-05 — Подпись зоны

Имя зоны рисуется в `x+36, y+22`, 13px жирным, `#334155`. В свёрнутом виде к
подписи добавляется число вложенных узлов. `semanticId` рисуется по правому
краю в `x+width-14, y+21`, 10px моноширинным, `#64748b`.

### R-REND-06 — Свёрнутая зона

Свёрнутая зона рисуется высотой **34** (только шапка), её пунктир подавляется,
все геометрически вложенные узлы скрываются, ручка размера не показывается.

### R-REND-07 — Оформление узла по типу

Заливка, обводка, толщина и иконка узла берутся из фиксированной таблицы по
ключу `node.type`:

| тип | заливка | обводка | толщина | иконка |
| --- | --- | --- | --- | --- |
| `concept` | `#fefce8` | `#fef08a` | 1.8 | 💡 |
| `note` | `#fef9c3` | `#fde047` | 1.5 | 📝 |
| `component` | `#ffffff` | `#cbd5e1` | 1.5 | 📦 |
| `service` | `#ffffff` | `#93c5fd` | 1.5 | ⚙️ |
| `security-component` | `#fff1f2` | `#fca5a5` | 2.0 | 🛡️ |
| `tool` | `#ffffff` | `#bfdbfe` | 1.5 | 🔧 |
| `database` | `#ffffff` | `#d8b4fe` | 1.5 | 💾 |
| `external-system` | `#fffbeb` | `#fde68a` | 1.5 | 🌐 |
| *(любой другой)* | `#ffffff` | `#cbd5e1` | 1.5 | 📄 |

### R-REND-08 — Тело узла

Скруглённый прямоугольник (`rx=8`) с фильтром тени, подпись `<иконка> <label>`
12.5px полужирным и моноширинный подзаголовок с `metadata.type` (при отсутствии
— `type`). Базовые линии подписей сдвигаются вниз, если высота узла больше 60.

### R-REND-09 — Видимость узла

Узел не рисуется, если геометрически содержащая его зона свёрнута.

### R-REND-10 — Маршрутизация связей

Связь — кубическая кривая Безье между центрами узлов. Доминирующая ось
выбирается сравнением `|Δx|` и `|Δy|`; кривая выходит и входит через
соответствующие грани блоков, контрольные точки — в середине пролёта. Обхода
препятствий и ортогональной маршрутизации нет.

### R-REND-11 — Оформление связей по типу

Типы связей делятся на два визуально различимых семейства:

**Структура** — как собран код; серые линии, треугольные наконечники,
извлекаются генератором автоматически:

| тип | цвет | пунктир | наконечник |
| --- | --- | --- | --- |
| `extends` | `#475569` | сплошная | полый треугольник |
| `implements` | `#64748b` | `8,4` | сплошной треугольник |
| `realizes` | `#64748b` | `8,4` | сплошной треугольник |
| `composes` | `#0f766e` | сплошная | сплошной ромб |

**Поток** — что происходит в рантайме; цветные линии, стрелки, описываются
вручную:

| тип | цвет | пунктир | наконечник |
| --- | --- | --- | --- |
| `call` | `#94a3b8` | `4,4` | стрелка |
| `data-flow` | `#3b82f6` | сплошная | стрелка |
| `event` | `#ea580c` | `2,3` | открытый шеврон |
| `security` | `#f43f5e` | `3,3` | стрелка |
| `storage` | `#a855f7` | сплошная | стрелка |
| *(любой другой)* | `#cbd5e1` | сплошная | стрелка |

### R-REND-12 — Связи и свёрнутые зоны

Если зона конца связи свёрнута, этот конец переносится в центр свёрнутой шапки
вместо скрытого узла. Если **оба** конца лежат в одной свёрнутой зоне, связь не
рисуется вовсе.

### R-REND-13 — Подпись связи

`edge.label`, если задан, рисуется в середине кривой, 11px, `#475569`,
некликабельно.

### R-REND-14 — Индикация выделения

Выделенный узел или зона обводятся `#2563eb` толщиной 2.5px. Выделенная связь
обводится `#3b82f6` толщиной 3px со свечением, её подпись синеет и жирнеет.

### R-REND-15 — Индикация наведения

Наведение на узел поднимает тень. Наведение на связь красит её в `#2563eb` и
утолщает до 2.5px.

## 5. Виды и подсветка (`R-VIEW`)

### R-VIEW-01 — Панель видов

В шапке рисуется по кнопке на каждый вид модели, в порядке модели. Если видов
не объявлено, показывается один неявный вид `all` / «Все элементы».

### R-VIEW-02 — Начальный вид

При загрузке активным становится первый объявленный вид; если видов нет —
активен `all`.

### R-VIEW-03 — Подсветка зон

Если активный вид объявляет непустой `highlightZones`, зоны вне списка рисуются
с прозрачностью **0.25**; иначе все зоны полностью непрозрачны.

### R-VIEW-04 — Подсветка узлов

`highlightNodes` имеет приоритет: узлы вне списка рисуются с прозрачностью
**0.2**. Если вид не объявляет `highlightNodes`, но объявляет `highlightZones`,
узел подсвечен тогда, когда подсвечена содержащая его зона.

### R-VIEW-05 — Подсветка связей

Связь подсвечена, только если **оба** её конца входят в `highlightNodes`; иначе
она рисуется с прозрачностью **0.15**.

### R-VIEW-06 — Подсветка — только представление

Переключение вида никогда не изменяет модель.

## 6. Вложенность (`R-CONT`)

### R-CONT-01 — Узел в зоне

Узел принадлежит зоне, когда `node.zone === zone.id`, **либо**, если это не так,
когда центр узла лежит внутри прямоугольника зоны. Геометрия — запасной вариант
для моделей, где родительство не объявлено.

### R-CONT-02 — Зона в зоне

Зона вложена в другую, когда её прямоугольник **полностью** содержится во
внешнем. Зона никогда не вложена сама в себя, соприкосновение краями
вложенностью не считается.

### R-CONT-03 — Попадание в точку

Зона под точкой ищется обратным проходом по порядку модели, поэтому побеждает
объявленная последней. Свёрнутые зоны проверяются по свёрнутой высоте.

## 7. Вьюпорт (`R-NAV`)

### R-NAV-01 — Трансформация

Вьюпорт применяет `translate(panX, panY) scale(zoom)` к одной группе,
охватывающей все четыре слоя. Начальное состояние — `zoom=0.9`, `pan=(40, 20)`.

### R-NAV-02 — Панорамирование

Перетаскивание пустого холста двигает вьюпорт один к одному за указателем.
Перетаскивание, начатое на узле, шапке зоны, ручке размера или связи, не
панорамирует.

### R-NAV-03 — Зум колесом

Колесо масштабирует на ×1.1 / ×0.9 за щелчок. Прокрутка страницы подавляется.

### R-NAV-04 — Зум кнопками

Кнопки тулбара масштабируют на ×1.2 и ×0.8.

### R-NAV-05 — Ограничение зума

Масштаб ограничен диапазоном **0.2 … 3.0**.

### R-NAV-06 — Сброс

Сброс возвращает `zoom=1`, `pan=(40, 20)`.

### R-NAV-07 — Вписать

«Вписать» считает габаритный прямоугольник всех зон и узлов, добавляет по 60
единиц отступа с каждой стороны и центрирует. Итоговый масштаб ограничен сверху
значением **1.2**, чтобы маленькие схемы не раздувались. Выполняется
автоматически после каждой загрузки модели.

### R-NAV-08 — Индикатор масштаба

Текущий масштаб отображается округлённым процентом.

## 8. Прямое манипулирование (`R-EDIT`)

### R-EDIT-01 — Перетаскивание узла

Нажатие на узел выделяет его и начинает перетаскивание. Смещение делится на
текущий масштаб, поэтому узел следует за указателем при любом зуме.

### R-EDIT-02 — Перетаскивание зоны

Зона тащится только за шапку; её тело инертно, поэтому пространство внутри зоны
остаётся доступным для панорамирования и для захвата лежащих в ней узлов.

### R-EDIT-03 — Перетаскивание контейнером

Пока включена «Зона-Контейнер» (по умолчанию **включено**), перетаскивание зоны
двигает и содержащиеся узлы, **и вложенные в неё зоны**. Без второго списка
дочерние контейнеры остаются на месте и схема визуально разваливается.

### R-EDIT-04 — Привязка к сетке

Пока включена «Привязка» (по умолчанию **включено**), результаты перетаскивания
и изменения размера привязываются к сетке в **10 единиц**. Привязывается
итоговая координата, а не смещение указателя, поэтому элемент остаётся на сетке
при последовательных перетаскиваниях.

### R-EDIT-05 — Индикация приёмника

Пока узел перетаскивается, зона под его центром обводится синим.

### R-EDIT-06 — Смена родителя

Отпускание узла над зоной записывает её id в `node.zone`. Отпускание над пустым
холстом оставляет прежнее родительство нетронутым.

### R-EDIT-07 — Изменение размера зоны

У выделенной развёрнутой зоны в правом нижнем углу появляется ручка. Её
перетаскивание меняет размер зоны с минимумами **160 × 100**. Содержимое зоны не
двигается и не масштабируется.

### R-EDIT-08 — Изменение размера узла

У каждого узла в правом нижнем углу есть невидимая ручка размера с минимумами
**100 × 40**.

### R-EDIT-09 — Подгонка ширины узла

Двойной щелчок по ручке размера узла ставит ширину в
`max(120, длина_подписи × 8 + 40)` — грубая подгонка под подпись. Высота не
меняется.

### R-EDIT-10 — Сворачивание

Кнопка `−` / `+` в шапке зоны переключает свёрнутость. Жест привязан к отпусканию
кнопки мыши и останавливает всплытие, поэтому нажатие на кнопку никогда не
начинает перетаскивание зоны.

### R-EDIT-11 — Свёрнутость не сохраняется

Свёрнутость — состояние представления. Она живёт вне модели, никогда не
сериализуется и сбрасывается при каждой загрузке модели.

## 9. Создание и удаление (`R-CRUD`)

### R-CRUD-01 — Новый узел

Создаёт узел в центре текущего вьюпорта, с привязкой к сетке в 10 единиц,
190 × 60, тип `concept`, с автоматическим назначением зоны под этой точкой, и
выделяет его.

### R-CRUD-02 — Новая зона

Создаёт зону в центре текущего вьюпорта, 420 × 300, тип `boundary`,
`semanticId` производится от сгенерированного id, со стилем по умолчанию, и
выделяет её.

### R-CRUD-03 — Генерация id

Новые id — `node_`, `zone_` или `edge_` плюс временная метка в base-36.

### R-CRUD-04 — Удаление узла

Удаляет узел **и все ссылающиеся на него связи**, затем снимает выделение.

### R-CRUD-05 — Удаление зоны

Удаляет зону и сбрасывает `node.zone` у всех узлов, которые её называли.
Вложенные узлы **не** удаляются — они остаются на месте осиротевшими.

### R-CRUD-06 — Добавление связи

Инспектор добавляет исходящую связь от выделенного узла к выбранной цели, с
выбранным типом и необязательной подписью.

### R-CRUD-07 — Удаление связи

Исходящая связь удаляется из списка связей выделенного узла.

## 10. Инспектор (`R-INSP`)

### R-INSP-01 — Что выделяется

Выделяются узлы, зоны и связи. Щелчок по телу узла или зоны выделяет их; щелчок
по связи выделяет связь.

### R-INSP-02 — Бейдж заголовка

Показывает род и тип выделения — `NODE: service`, `CONTAINER: boundary`,
`EDGE: call` — с цветовой кодировкой по роду.

### R-INSP-03 — Живые координаты

Показывает `X, Y (Ш×В)` для узлов и зон, обновляясь непрерывно **во время**
перетаскивания или изменения размера. Для связей вместо этого — `FROM … TO …`.

### R-INSP-04 — Редактируемые поля

Подпись (`label` у узлов, `name` у зон), семантический тип, описание
(`metadata.description`) и ссылка на код (`metadata.codeRef`). Правка подписи и
типа немедленно перерисовывает холст.

### R-INSP-05 — Словарь типов

Селектор типа предлагает фиксированный список: `concept`, `component`,
`service`, `security-component`, `tool`, `database`, `external-system`, `note`,
`boundary`, `subsystem`.

### R-INSP-06 — Показ родительской зоны

Показывает имя содержащей зоны, «Вне зон» при её отсутствии или «Является зоной»
при выделенной зоне. Только для чтения.

### R-INSP-07 — Панель зоны

Для зоны показывает число вложенных узлов и кнопку свернуть/развернуть.

### R-INSP-08 — Панель связей узла

Для узла перечисляет исходящие связи с именем цели и типом, у каждой — кнопка
удаления, плюс форма добавления новой связи (цель, тип, подпись).

### R-INSP-09 — Кнопка удаления

Кнопка удаления текущего выделения, формулировка меняется для узла и зоны.

### R-INSP-10 — Пустое состояние

Когда ничего не выделено, инспектор показывает подсказку, кнопка удаления
неактивна.

## 11. История (`R-HIST`)

### R-HIST-01 — Модель снимков

История отмены хранит снимки модели целиком в виде JSON. Модели команд или
разниц нет.

### R-HIST-02 — Глубина

Хранится не более **50** снимков; лишние старые отбрасываются.

### R-HIST-03 — Обрезание повтора

Новое действие после отмены отбрасывает хвост повтора.

### R-HIST-04 — Начальный снимок

Загрузка модели засевает историю ровно одним снимком и сбрасывает индекс.

### R-HIST-05 — Точки фиксации

Снимок фиксируется при: создании узла, создании зоны, удалении элемента,
добавлении связи, удалении связи, подгонке ширины и при отпускании после
перетаскивания или изменения размера.

### R-HIST-06 — Подавление пустых действий

Перетаскивание или изменение размера, закончившееся там же, где началось, не
фиксирует ничего. Определяется сравнением сериализованной модели со снимком,
снятым в начале жеста.

### R-HIST-07 — Выделение переживает отмену

После отмены или повтора выделение заново разрешается по id в восстановленной
модели, поэтому инспектор указывает на живой объект, а не на отсоединённую
копию.

### R-HIST-08 — Клавиатура

`Ctrl+Z` — отмена, `Ctrl+Shift+Z` и `Ctrl+Y` — повтор, `Delete` / `Backspace` —
удаление выделения. Сочетания подавляются, пока фокус в текстовом поле.

### R-HIST-09 — Состояние кнопок

Кнопки отмены и повтора неактивны на концах стека.

## 12. Признак изменений (`R-STATE`)

### R-STATE-01 — Установка

Любое изменение модели поднимает признак и показывает индикатор «изменено».

### R-STATE-02 — Снятие

Загрузка модели или успешное сохранение снимают признак.

### R-STATE-03 — Автосохранения нет

Ничего не пишется автоматически. Нет ни `localStorage`, ни восстановления
сессии, ни периодического сброса. Несохранённые правки теряются при закрытии
страницы.

## 13. Загрузка, сохранение, экспорт (`R-IO`)

### R-IO-01 — Загрузка из каталога

См. R-CAT-04.

### R-IO-02 — Выбор файла

Локальный `.json` можно открыть через файловый диалог.

### R-IO-03 — Перетаскивание файла

Бросок `.json` в любое место окна загружает его; во время перетаскивания
появляется оверлей на всё окно. Файл не-JSON отклоняется сообщением.

### R-IO-04 — Пользовательские записи

Загруженный вручную файл добавляется в отдельный раздел «Пользовательские»
левой панели и до конца сессии может быть выбран оттуда повторно.

### R-IO-05 — Сохранение

Сохранение выполняет `POST /api/save?file=<имя файла каталога>` с
сериализованной моделью в теле и подтверждается временной сменой состояния
кнопки.

### R-IO-06 — Сохраняется только каталог

У загруженного вручную файла нет серверного происхождения, и он не может быть
сохранён; попытка отклоняется с объяснением.

### R-IO-07 — Экспорт в Draw.io

Экспортирует документ `.drawio` (mxGraph), в котором:

- зоны становятся ячейками `swimlane` с `container=1`, `collapsible=1` и
  начальным размером 34, сохраняя заливку, обводку, толщину и пунктир;
- узлы становятся дочерними ячейками своей объявленной зоны, координаты
  переводятся из абсолютных в **относительные к зоне**;
- связи становятся ортогональными рёбрами `mxCell`;
- семантика (`type`, `semanticId`, `tags`, `codeRef`) переносится в дочерний
  `<Object as="data">`, чтобы смысл пережил обмен;
- файл скачивается с именем, произведённым от заголовка модели.

### R-IO-08 — Просмотр JSON

Модальное окно показывает сериализованную модель, позволяет скопировать её в
буфер обмена и вставить отредактированный документ обратно — что заменяет
активную модель и перерисовывает холст.

## 15. Нефункциональные характеристики

### R-NFR-01 — Никаких зависимостей рантайма

Холст не зависит ни от чего, кроме браузерных SVG- и DOM-API. Никакой
библиотеки диаграмм, никакого движка укладки графов.

### R-NFR-02 — Масштаб

Крупнейшая используемая модель, проект `full_core`, содержит ~246 узлов в 13
границах и 17 вложенных под-ролях. Это рабочий масштаб, на котором рендерер
обязан оставаться пригодным.

### R-NFR-03 — Способ доставки

Приложение отдаётся по HTTP, потому что загружает модели по относительному URL и
сохраняет через HTTP-эндпоинт. Из `file://` оно не работает.

## 16. Дефекты — воспроизводить нельзя

### D-01 — Высота свёрнутой зоны расходится между модулями

Отрисовка и привязка связей используют **34**; «вписать» и попадание в точку —
**36**. Как надо: одна константа, используемая везде.

### D-02 — Правки текста в инспекторе минуют историю

Правка подписи, описания или ссылки на код меняет модель и поднимает признак
изменений, но не фиксирует снимок — поэтому отмена перепрыгивает через правку и
молча её теряет. Как надо: правки текста фиксируются, с задержкой, чтобы набор
текста давал один снимок, а не по одному на каждое нажатие.

### D-03 — Инъекция HTML в инспекторе

Инспектор собирает разметку конкатенацией строк с неэкранированными значениями
модели. Подпись с кавычкой или угловой скобкой ломает панель, а специально
составленная модель может выполнить скрипт. Как надо: значения ставятся как
текст/свойства, а не подставляются в разметку.

### D-04 — Неоднозначный родитель у вложенных зон

`R-CONT-01` определяет родителя узла первым совпадением при проходе по списку
зон, поэтому для вложенных зон победитель зависит от порядка элементов в
массиве, а не от глубины вложенности. Как надо: побеждает самая внутренняя
содержащая зона.

### D-05 — Устаревшее выделение после удаления связи

Удаление связи заново выделяет прежнее выделение, не проверив, что оно ещё
существует, оставляя инспектор привязанным к удалённому объекту. Как надо:
выделение снимается, когда его объект исчез.

### D-06 — Кнопка сохранения ищется по своему инлайн-обработчику

Анимация успеха находит кнопку селектором
`button[onclick="downloadUpdatedJson()"]`, связывая поведение с разметкой.
Устраняется само собой, как только инлайн-обработчиков не станет.

### D-07 — Каталог продублирован в приложении

`DEFAULT_CATALOG` повторяет всё содержимое `catalog.js` в качестве запасного
варианта, который мёртв, когда `catalog.js` загрузился, и устарел, когда нет.
Как надо: один источник, а отсутствие каталога — явное пустое состояние.

### D-08 — Экранированный перевод строки в сообщении об ошибке

Сообщение об ошибке сохранения содержит буквальный `\n`, потому что escape в
исходной строке экранирован дважды.

### D-09 — Присваивание подсказки в никуда

`resizer.title = "…"` присваивается SVG-элементу, где `title` не является
свойством и подсказка не появляется. Как надо: дочерний элемент `<title>` либо
удалить.

### D-10 — Мёртвое определение маркера

Маркер `#triangle` в `<defs>` использует `stroke="currentColor"` без заливки и
никем не используется. Как надо: удалить.

### D-11 — Встроенная запасная модель

Полная копия старого `model.json` встроена в исходник и загружается при любой
неудаче запроса, поэтому сломанный путь молча показывает устаревшую архитектуру
вместо сообщения об ошибке. Как надо: неудача запроса становится видимой.

## 16a. Отклонения, внесённые переносом на TypeScript (проход 1)

Перенос сверен по `model-features.json` (ныне проект `features` — имена файлов
здесь исторические, см. [`CONTRACT.md`](CONTRACT.md)): все шесть моделей
грузятся, рисуются и ходят туда-обратно байт в байт, а все двенадцать путей
связей на стенде — посимвольно те же, что давал оригинал. Изменились три вещи,
и все они вынуждены целевой структурой, а не выбраны.

### Δ1 — Родителем становится самый внутренний контейнер (чинит D-04)

Модель в памяти — настоящее дерево, поэтому первого-совпадения-по-массиву больше
неоткуда взять. На стенде `n_concept` теперь принадлежит `zone_nested`, а раньше
принадлежал `zone_outer`.

### Δ2 — Одна константа высоты свёрнутой зоны (чинит D-01)

`HEADER_HEIGHT = 34` используется и отрисовкой, и попаданием в точку, и
«вписать». Раньше последние две брали 36, так что теперь обе на два пикселя
плотнее.

### Δ3 — Структурные дефекты исчезли по построению

D-03 (инъекция HTML в инспекторе), D-06 (поиск кнопки по инлайн-обработчику),
D-07 (дублирование каталога в исходнике), D-10 (мёртвый маркер) и D-11
(встроенная запасная модель) не имеют выражения в новой структуре: инспектор
строит DOM-узлы, инлайн-обработчиков нет, каталог читается из `catalog.json` (с ADR_20260923-7 — из `GET /api/workspace` хоста), а
неудача запроса сообщается, а не подменяется молча.

Заодно добавлено экранирование XML-атрибутов в экспорте Draw.io — это был тот же
класс дефекта, что D-03, только в другом выводе.

D-05 (устаревшее выделение после удаления связи) починен, потому что новый путь
удаления всё равно обязан был сделать явный выбор. D-08 и D-09 в новом коде тоже
не выразились — сообщение собирается шаблонной строкой, а подсказка SVG-элементу
не присваивается.

**Все дефекты из раздела 16 закрыты.** Отдельного второго прохода потребовал
только D-02, см. R-HIST-10.

### Структура

`R-REND-01` теперь называет четыре слоя как **зоны → связи → узлы → оверлей**.
Слой оверлея держит ручки размера контейнеров, которые раньше жили в слое
`resizers`; порядок наложения не изменился.

## 17. Открытые вопросы

### Q-01 — Семантическая вложенность против визуальной

Концептуальный документ разделяет логическую принадлежность и физическое
размещение, и `node.zone` записывается при смене родителя — но его никто не
читает, кроме как подсказку в `R-CONT-01` и экспорт в Draw.io. Либо поле
становится главным, либо главным остаётся геометрическое правило, а поле
становится производным.

### Q-02 — Время жизни свёрнутости

Свёрнутость намеренно не сохраняется (R-EDIT-11), поэтому работа по
сворачиванию/разворачиванию за сессию разбора теряется при перезагрузке.
Правильно это или нет — зависит от того, свёрнутость это подспорье для чтения
или часть смысла диаграммы.

### Q-03 — Режим только для чтения

Всё редактируемо всегда, включая порождённые модели, где ручные правки будут
затёрты следующим прогоном генератора. Режим просмотра может принадлежать сюда,
а может — отдельному потребителю того же холста.

## 18. Добавлено после переноса

Новые возможности, которых в оригинале не было. Записаны здесь по той же схеме
идентификаторов, чтобы дальнейшей работе было с чем сверяться.

### R-EDIT-12 — Изменение размера за любую сторону или угол

У выделенного элемента восемь ручек: четыре угла и середины четырёх сторон.
Перетаскивание северной или западной ручки двигает и начало координат, и
размер, поэтому противоположный край остаётся на месте. Минимумы (160 × 100 для
контейнеров, 100 × 40 для листьев) и привязка к сетке действуют во всех
направлениях.

Ручки рисуются постоянного экранного размера, с делением на текущий масштаб,
поэтому остаются схватываемыми при отдалении и не мешают при приближении.

### R-EDIT-13 — Множественное выделение

`Ctrl`/`Cmd`/`Shift` + щелчок добавляет элемент в выделение или убирает из него.
`Shift` + протяжка по пустому холсту рисует рамку, которая выделяет элементы,
**полностью попавшие** внутрь, — задеть краем недостаточно. Обычный щелчок по
пустому месту снимает выделение и панорамирует, как раньше.

Щелчок по элементу, уже входящему в множественное выделение, сохраняет группу,
чтобы перетаскивание двигало всё, а не схлопывало выделение до одного.

### R-EDIT-14 — Перемещение группы

Перетаскивание любого выделенного элемента двигает всё выделение на одну и ту же
величину, контейнеры по-прежнему несут свои поддеревья. Привязка вычисляется
один раз по элементу под курсором и применяется ко всем, поэтому взаимное
расположение сохраняется точно.

Смена родителя остаётся операцией над одним элементом: бросок группы в контейнер
никого не перевешивает.

### R-EDIT-15 — Изменение размера группы

Когда выделено больше одного элемента, ручки стоят на объединении их
прямоугольников, обведённом пунктиром. Перетаскивание любой из них отображает
каждый элемент из старой рамки в новую, пропорционально масштабируя положения и
размеры, — компоновка растягивается, а не перекладывается. Контейнеры проносят
своё содержимое через масштабирование.

### R-HIST-10 — Набор текста — один шаг истории (закрывает D-02)

Правка текстового поля в инспекторе удерживает состояние до первого нажатия и
фиксирует его, когда поле замолчало на 600 мс — или раньше, если история
понадобилась кому-то ещё: смене выделения, жесту, сохранению, отмене или
загрузке другой модели. Пять нажатий дают один шаг отмены, а не пять и не ноль.

### R-REND-16 — Причаливание связей сменяемо

Поставляются три раскладки, выбираются в тулбаре и никогда не хранятся в модели:

| режим | поведение |
| --- | --- |
| `center` (по умолчанию) | каждый конец в середине обращённой стороны — исходное поведение, и несколько связей между одной парой совпадают точь-в-точь |
| `uniform` | концы на одной стороне разводятся равномерно |
| `discrete` | концы встают на фиксированную сетку вдоль стороны, группа центрируется |

Разводящие режимы упорядочивают оба конца связи одним и тем же ключом —
положение противоположного конца, затем тип, затем id, — поэтому линии остаются
параллельными, а не пересекаются. Раскладка есть чистая функция от модели,
поэтому в JSON нет поля якоря, а переключение режимов ничего не стоит.

### R-REND-17 — Shape-Aware геометрия и отступы углов (`cornerInset`)

Безопасные интервалы причаливания связей и отступы от углов определяются самой фигурой через `ElementRenderer.cornerInset(side, style)`, а не глобальным алгоритмом холста.
- Узлы со скруглением (`BoxRenderer`) отдают свой радиус скругления (`style.radius ?? 8`), зоны (`ContainerRenderer`) — `style.radius ?? 10`, острые фигуры — `0`.
- Роутер связей (`EdgeRouter.sharedRun`) строит строго прямое соединение только в пределах общего перекрытия прямых сегментов обеих фигур, что исключает попадание стрелок на дуги скруглений и предотвращает преждевременный срыв в кривую Безье (см. [`ADR_20260901_diagrams_shape-aware-geometry-and-insets.md`](../../../docs/adr/ADR_20260901_diagrams_shape-aware-geometry-and-insets.md)).

### R-CRUD-08 — Удаление снимает всё выделение

Удаление при нескольких выделенных элементах убирает их все, каждый вместе со
ссылающимися на него связями.

### R-INSP-11 — Показ множественного выделения

При нескольких выделенных элементах бейдж показывает их количество, а панель
поясняет, что операции с геометрией работают на группу, а поля ниже правят
только главный элемент.

### Отклонение — ручки требуют выделения

В оригинале у каждого узла была невидимая ручка размера, работавшая без
предварительного выделения. Теперь ручки рисуются только вокруг текущего
выделения, потому что при нескольких выделенных элементах они принадлежат рамке
выделения, а не какому-то одному элементу. Выделить — это один щелчок, и так
устроен любой другой редактор.

## 19. Вне области

Намеренно отсутствует и должно отсутствовать после миграции:

- автоматическая укладка любого вида, глобальная или локальная;
- ортогональная маршрутизация связей и обход препятствий;
- множественное выделение и групповые операции;
- копирование, вставка, дублирование;
- выравнивание и распределение;
- переключение уровня детализации по масштабу;
- совместная работа, комментарии, присутствие;
- валидация модели и принуждение к схеме;
- порождение моделей — это дело генератора раскладки.
